## 개요 {#overview}

플래그 키 난독화는 사전 계산된 할당 응답에서 사람이 읽을 수 있는 플래그 키를 해시로 대체합니다. 이로 인해 응답을 살펴보는 사람이 플래그 이름을 알아보기 어려워집니다. 이 기능은 클라이언트 측 기능 플래그를 비밀로 유지하거나 응답 변조를 방지하는 것은 아닙니다.

애플리케이션은 원래 키를 사용하여 플래그를 계속 평가합니다. 난독화는 타겟팅, 할당된 값, 기본값 또는 텔레메트리의 플래그 키를 변경하지 않습니다.

## 호환성 및 롤아웃 {#compatibility-and-rollout}

플래그 키 난독화를 사용하려면 JavaScript SDK인 `@datadog/openfeature-browser` 버전 `2.1.0` 이상이 필요합니다. Datadog은 호환되는 SDK로의 롤아웃을 제어합니다. SDK가 인코딩을 자동으로 처리합니다. 공급자 옵션을 설정하거나, 해시를 생성하거나, 평가 호출을 변경할 필요가 없습니다.

롤아웃 중에 Datadog은 인코딩 지원을 보고하는 SDK에만 난독화된 응답을 보냅니다. 다른 SDK 버전은 계속해서 읽을 수 있는 키를 수신합니다. 하나의 애플리케이션을 업데이트해도 이전 SDK 버전을 실행 중인 다른 애플리케이션의 동작은 변경되지 않습니다.

이 기능은 사전 계산된 할당에 적용됩니다. 로컬 평가용으로 다운로드한 타겟팅 규칙은 난독화하지 않습니다.

## 플래그 키 난독화 작동 방식 {#how-flag-key-obfuscation-works}

1. Datadog은 SDK가 제공한 주체와 컨텍스트를 기반으로 플래그를 평가합니다.
2. Datadog은 할당 응답의 각 플래그 키를 솔트가 적용된 SHA-256 해시로 대체합니다.
3. SDK는 해당 솔트를 사용하여 평가 호출의 키를 해싱하고 할당을 찾아 그 값을 반환합니다.

솔트는 응답마다 변경됩니다. 솔트는 보안 키가 아닌 퍼블릭 정보입니다. SDK는 캐시된 할당과 함께 솔트를 유지합니다.

예를 들어, 다음 JavaScript 평가 호출은 응답에 읽을 수 있는 키가 포함되어 있든 해시된 키가 포함되어 있든 동일합니다.

{{< code-block lang="javascript" >}}
const enabled = client.getBooleanValue('new-route-planner', false);
{{< /code-block >}}

원래 키는 Datadog과 애플리케이션 코드에서 변경되지 않습니다. 변형 값, 변형 식별자 및 할당 식별자도 변경되지 않습니다.

## 민감한 기능 정보 보호 {#protect-sensitive-feature-information}

난독화는 할당 응답에서 플래그 이름이 쉽게 발견될 가능성을 줄입니다. 암호화, 권한 부여 또는 서명 검증 기능을 제공하지는 않습니다. 플래그 키로 사용되었을 가능성이 있는 값을 아는 사람은 퍼블릭 솔트를 사용하여 해당 값의 해시를 확인할 수 있습니다.

- 시크릿과 민감한 비즈니스 로직은 서버에 보관합니다. 서버 전용 플래그를 **Server** [배포 채널][1]로 제한합니다.
- 클라이언트에 노출되는 값에 민감한 정보를 포함하지 마세요. 문자열과 JSON 객체는 여전히 읽을 수 있습니다. 불리언 값으로도 동작이 드러날 수 있습니다.
- 애플리케이션 코드의 플래그 이름이 노출되는 것이 우려된다면 의미를 드러내지 않는 플래그 키를 선택합니다. 페이로드 난독화는 브라우저 코드에서 문자열을 제거하지 않습니다.
- 클라이언트에 노출되는 값, 식별자, 텔레메트리 및 애플리케이션 동작은 모두 검사할 수 있다고 가정합니다. 플래그 키를 해싱해도 이러한 다른 정보 소스는 숨겨지지 않습니다.
- 민감한 액세스 제어 결정은 서버에서 적용합니다. 난독화는 수정된 클라이언트가 자신의 동작을 변경하는 것을 방지하지 못합니다.
