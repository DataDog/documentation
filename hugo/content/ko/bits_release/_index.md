Bits Release는 병합된 풀 리퀘스트가 프로덕션에서 의도대로 작동하는지 검증합니다. 변경 사항의 의도를 파악하고 변경 사항이 적용된 후 서비스를 모니터링하며, 풀 리퀘스트와 Slack을 통해 결과를 보고합니다.

표준 릴리스 검사는 변경 사항이 목표로 하는 특정 동작을 거의 다루지 않습니다. 몇 분 동안 모니터링한 대시보드에서는 서비스가 정상으로 표시될 수 있으며 변경한 기능에 대한 경보는 전혀 발생하지 않을 수도 있습니다. 따라서 오류가 있거나 아무런 효과가 없는 상태로 배포된 변경 사항이 며칠 동안 발견되지 않을 수 있습니다. Bits Release는 병합할 때마다 해당 동작을 직접 검사합니다.

Bits Release는 코드를 수정하거나 영구적인 계측을 추가하지 않습니다. 이미 Datadog으로 전송 중인 관측 가능성 데이터를 읽습니다. 일정 기간 동안 검사를 실행해야 할 경우 임시 리소스를 생성하고 검증이 끝나면 이를 제거합니다.

## Bits Release가 작동하는 방식 {#how-bits-release-works}

1. **병합 탐지**: Bits Release는 범위 내 리포지토리의 기본 브랜치에 풀 리퀘스트가 병합되면 이를 탐지합니다.
2. **변경 사항 분석**: 코드 변경 사항과 프로덕션 데이터를 함께 읽어 변경 목적을 파악합니다. 즉, 배포 후 프로덕션에서 나타나야 할 효과(예상 영향)와 영향을 주지 않아야 할 동작(예상 회귀 위험)을 분석합니다.
3. **배포 대기**: Bits Release가 풀 리퀘스트의 변경 사항이 프로덕션에서 실행 중임을 확인할 때까지 검증은 대기합니다.
4. **프로덕션 평가**: Bits Release는 판정에 도달할 때까지 프로덕션의 동작을 예상한 결과와 비교하여 측정합니다. 그런 다음 풀 리퀘스트 댓글, Slack 알림, Datadog의 전체 보고서 형태로 판정을 전달합니다.

검증은 프로덕션 환경을 대상으로 실행됩니다.

### Bits Release용 데이터 소스 {#data-sources-for-bits-release}

Bits Release에는 전용 데이터 소스가 필요하지 않습니다. 서비스가 이미 전송 중인 핵심 Datadog 텔레메트리(백엔드 서비스의 경우 주로 [로그][3] 및 [APM][4] 트레이스, 웹 프런트엔드의 경우 [RUM][5])를 사용하여 변경 사항을 검증하며, 각 서비스에서 활성화된 항목에 맞춰 조정됩니다.

적용 범위는 계측 수준에 따라 달라집니다. APM과 로그가 있는 서비스의 백엔드 변경 사항은 RUM이 없는 애플리케이션의 프런트엔드 변경 사항보다 더 강력한 증거를 확보합니다.

## 판정 {#verdicts}

검증은 4가지 판정 중 하나로 종료됩니다. **Passed**와 **Failed**는 변경 사항에 대한 결론입니다. **Not enough data**와 **Inconclusive**는 Bits Release가 결론을 내릴 수 없어 확인이 필요함을 의미합니다.

| 판정 | 의미 |
| ------- | ------- |
| **Passed** | 배포 후 서비스가 정상 상태입니다. 변경 사항으로 인해 특정 결과가 예상되었던 경우 Bits Release는 해당 결과 중 최소 하나가 발생했음을 확인했습니다. 가시적인 효과를 의도한 변경 사항을 통과시키기에는 서비스가 정상 상태인 것만으로는 충분하지 않습니다. 특별히 확인할 사항이 없는 변경 사항의 경우 서비스가 정상 상태이면 충분합니다. |
| **Failed** | Bits Release가 문제가 있다는 명확한 증거를 확보했습니다. 즉, 변경 사항으로 인해 회귀가 발생했거나 변경된 코드가 실행되었으나 의도한 효과가 나타나지 않았거나 잘못된 방향으로 진행되었습니다. 예를 들어, 수정된 버그가 여전히 발생하거나 개선하려던 지연 시간이나 오류율이 개선되지 않았거나 새로운 기능에서 오류가 발생하는 경우입니다. |
| **Not enough data** | 프로덕션에서 Bits Release가 판단할 수 있는 충분한 데이터를 제공하지 않았습니다. 관련 텔레메트리가 도착하지 않았거나 결론을 내릴 만큼 충분한 요청이 변경된 코드에 도달하지 않았습니다. 이는 예상된 효과가 확인되지 않은 정상적인 서비스에도 적용됩니다. 예를 들어 변경 사항이 한가한 시간에 배포되었거나, 아직 꺼져 있는 기능 플래그 뒤에 있거나, Bits Release가 모니터링하는 동안 트래픽이 없는 경로를 서비스하는 경우 등이 이에 해당합니다. |
| **Inconclusive** | 데이터는 충분하지만 서로 다른 방향을 가리키거나, 동시에 발생한 다른 문제 때문이 아닌 변경 사항 때문이라고 확신할 수 없는 경우입니다. |

검증이 실행되는 동안에는 **In Progress**로 표시됩니다. Bits Release가 잠정적인 답변을 가지고 있지만 모니터링 기간이 짧거나 필요한 신호가 도착하지 않아 결과를 보류 중인 경우 **Pending**으로 표시됩니다. 두 경우 모두 계속 감시하여 더 많은 정보가 확보되면 보고합니다.

Bits Release는 변경 후 프로덕션 환경이 어떻게 작동하는지 보고합니다. 수정해야 할 코드를 식별하지는 않습니다. 검증하는 동안에 수집된 컨텍스트(예상 영향, 판정의 근거, 확인한 텔레메트리)를 수정의 출발점으로 사용하세요. [Bits Code][1]에 판정 결과를 전달해 조사하고 풀 리퀘스트를 생성하도록 하거나, 자체 AI 코딩 도구에서 해당 컨텍스트를 활용하세요.

## 전제 조건 {#prerequisites}

Bits Release는 병합한 코드를 읽고 해당 코드가 프로덕션 환경에 적용된 시점을 탐지합니다. GitHub 리포지토리만 지원합니다. GitLab, Azure DevOps 또는 Bitbucket에서 호스팅되는 리포지토리는 지원되지 않습니다.

### 필수 {#required}

| 요구 사항 | 필요한 이유 |
| ----------- | ---------------- |
| 범위 내 리포지토리에 설치된 Datadog [GitHub App][2]은 `Contents: Read` 및 `Pull Requests: Write` | `Contents: Read`과 함께 Bits Release가 검증 중인 코드 변경 사항을 읽을 수 있도록 합니다. `Pull Requests: Write`를 사용하면 검증 계획과 판정 결과를 풀 리퀘스트에 게시할 수 있으며, 대부분의 개발자는 이곳에서 결과를 확인합니다. |
| 범위 내 서비스에 대한 `version` 태그 | 각 배포를 식별하여 Bits Release가 새로운 배포가 발생한 시점을 알 수 있게 합니다. 서비스는 [APM][4] 또는 [RUM][5] 텔레메트리를 통해 이를 보고합니다. |
| 배포 시마다 배포되는 커밋 SHA | 배포를 병합한 코드와 연결하며 이것이 검증을 시작하는 계기가 됩니다. 서비스의 텔레메트리에 `git.commit.sha` 태그로 보고하거나 `version` 태그에 포함된 SHA로 보고하세요. 이를 설정하려면 [서비스 매핑][8]을 참조하세요. |

### 권장 {#recommended}

| 요구 사항 | 추가하는 항목 |
| ----------- | ------------ |
| [Slack 통합][6] | 풀 리퀘스트 댓글을 확인하도록 의존하는 대신, 판정이 준비되면 풀 리퀘스트 작성자에게 직접 알림을 보냅니다. |
| 애플리케이션 도메인에 대한 기존 [Synthetic 테스트][7] | 실제 사용자 트래픽을 기다리는 대신 애플리케이션을 직접 호출하여 Bits Release가 변경 사항을 검증할 수 있도록 합니다. 기존 테스트가 이미 설정한 진입점과 로그인 방법을 재사용합니다. |

## 결과가 표시되는 위치 {#where-results-appear}

- **풀 리퀘스트 댓글**: Bits Release는 분석 후 검증 계획을 게시하고 평가가 완료되면 판정이 포함된 별도의 댓글을 게시하여 작성자에게 새로운 알림이 생성되도록 합니다.
- **Slack**: 판정이 준비되면 풀 리퀘스트 작성자에게 알림이 전송됩니다.
- **Datadog의 Bits Release**: Bits Release 페이지에는 전체 보고서가 포함됩니다. 여기에는 검증 목록, 각 계획의 수명 주기 타임라인, 판정 및 그 근거, 각각의 근거 자료가 포함된 예상 영향, 배포 마커가 주석으로 달린 메트릭 차트가 포함됩니다. 미리 보기 기간 중에는 풀 리퀘스트 댓글의 링크를 통해 액세스할 수 있습니다. Datadog 사이드 탐색 메뉴에서는 액세스할 수 없습니다.

## 청구 {#billing}

Bits Release는 미리 보기 기간에는 무료로 제공됩니다. [AI 크레딧][9]을 사용하지 않으며 변경 사항을 검증하는 동안 생성되는 임시 리소스에는 요금이 청구되지 않습니다.
