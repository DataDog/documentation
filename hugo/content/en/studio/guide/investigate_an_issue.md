## Overview

This guide walks through one complete Datadog Studio workflow. A background [Loop][1] flags a drop in successful save events, [Bits AI][2] finds the root cause, you stage a fix, and you create a Loop to watch the area going forward.

The example uses save failures caused by a schema mismatch, but the same flow applies to any signal Studio surfaces.

## Start from a signal

Open Studio. The home page shows signals generated by Studio's out-of-the-box Loops, which watch your app's traffic patterns, user activity, and errors.

In this example, a Loop picked up a dip in successful save events and flagged it with a short summary.

1. Select the signal card.
2. Bits opens an investigation and begins pulling in data across logs, error events, and user activity.
3. Leave the investigation running. You can close the panel to free up space; the investigation continues in the background.

## Check the user side of the problem

While Bits works, look at what users experienced.

1. Go to the **User activity** page.
2. Review total users, returning users, new users, and the AI-generated summary of what happened with your users over the last day.
3. Scroll down to see sessions, top actions, top views, and the top paths users take through your app.
4. Select one of your top users to open their details page.

On the user details page, you can see the user's sessions, the views they visited, and the critical issues they faced. If the user encountered the same error you're investigating, it appears here.

Scroll down to the Session Replay to watch what the user was doing leading up to the failure.

For more on these pages, see [Out-of-the-box pages][3].

## Review what Bits found

Return to the investigation.

In this example, Bits traced the save failures to a schema mismatch: a recently added AI suggestions feature also added a new field.

Every claim Bits makes is backed by data. Expand a finding to see the data Bits pulled in to support it, and confirm the conclusion before you act on it.

## Act on the finding

To go deeper, open the investigation in the full workspace view. From there, you have two options:

- **Ask Bits to suggest a code fix and stage a pull request.** Review the code changes, then review and approve the pull request after it opens.
- **Copy the full investigation context as a prompt** and take it into whichever environment you prefer.

## Watch the area going forward

The investigation surfaced that a specific feature triggered the failures, so keep an eye on it instead of checking manually.

Ask Bits, in plain language, to create a Loop:

```text
Watch errors on the AI Suggestions feature weekly, and let me know if the error rate spikes.
```

Bits creates the Loop, sets it to run weekly, and delivers results to the home page when there's something worth your attention. No monitor, threshold, or dashboard setup is required.

Manage this Loop, along with the out-of-the-box Loops, from the **Loops** page. See [Loops][1].
