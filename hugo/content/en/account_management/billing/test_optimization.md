## Overview

This guide describes how Datadog bills [Test Optimization][1]. For prices and plan details, see the [Test Optimization pricing page][2].

Test Optimization is billed based on:

- **Committers**: The number of active committers who send test data to Test Optimization.
- **Test spans**: The number of test runs that Test Optimization indexes. Your plan includes an allotment of test spans for each committer. Test spans above the allotment are billed as additional usage.

## Counting committers

A committer is an active Git contributor, identified by their Git author email address. For billing purposes, a committer is included if they make at least three commits in a given month.

## Counting test spans

Every individual test run counts as a test span, except for the test spans that Test Optimization features generate.

### Test spans generated by Test Optimization features

Some Test Optimization features run or report tests on your behalf. The test spans that these features generate do not count as billable test spans:

- Retries from [Auto Test Retries][3], [Early Flake Detection][4], and the [Attempt to Fix][5] remediation flow. The first execution of the test is billed, but the retries that the feature adds are not.
- Tests skipped by [Test Impact Analysis][6].

These test spans are still ingested and indexed. You can search and analyze them in the [Test Optimization Explorer][7] like any other test span.

The following test spans are still billed:

- Retries configured in your test framework.
- Tests that you skip in your code or test framework configuration.

These exceptions don't change how committers are counted.
