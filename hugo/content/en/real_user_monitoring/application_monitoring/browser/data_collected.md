<div id="cdoc-content" class=""><article><h2 id="overview">Overview</h2><p>The RUM Browser SDK generates events that have associated telemetry and attributes. Every RUM event has all of the <a href="#default-attributes">default attributes</a>, for example, the URL of the page (<code>view.url</code>) and user information such as their device type (<code>device.type</code>) and their country (<code>geo.country</code>).</p><p>There are additional <a href="#event-specific-attributes">attributes specific to a given event type</a>. For example, the <code>view.loading_time</code> telemetry is associated with view events, and the <code>resource.method</code> attribute is associated with resource events.</p><table><thead><tr><th>Event Type</th><th>Retention</th><th>Description</th></tr></thead><tbody><tr><td>Session</td><td>30 days</td><td>A user session begins when a user starts browsing the web application. It contains high-level information about the user (browser, device, geolocation). It aggregates all RUM events collected during the user journey with a unique <code>session.id</code> attribute. <strong>Note:</strong> The session resets after 15 minutes of inactivity.</td></tr><tr><td>View</td><td>30 days</td><td>A view event is generated each time a user visits a page of the web application. While the user remains on the same page, resource, long-task, error, and action events are linked to the related RUM view with the <code>view.id</code> attribute.</td></tr><tr><td>Resource</td><td>15 days</td><td>A resource event is generated for images, XHR, Fetch, CSS, or JS libraries loaded on a web page. It includes detailed loading timing information.</td></tr><tr><td>Long Task</td><td>15 days</td><td>A long task event is generated for any task in the browser that blocks the main thread for more than 50ms.</td></tr><tr><td>Error</td><td>30 days</td><td>RUM collects every frontend error emitted by the browser.</td></tr><tr><td>Action</td><td>30 days</td><td>RUM action events track user interactions during a user journey and can also be manually sent to monitor custom user actions.</td></tr></tbody></table><p>The following diagram illustrates the RUM event hierarchy:</p><a href="http://localhost:1313/images/real_user_monitoring/data_collected/event-hierarchy.86b26bc249a457cd958cad386d03aabd.png?fit=max&amp;auto=format" class="pop" data-bs-toggle="modal" data-bs-target="#popupImageModal"><div class="shortcode-wrapper shortcode-img expand"><figure class="text-center"><picture style="width:50%"><img srcSet="http://localhost:1313/images/real_user_monitoring/data_collected/event-hierarchy.86b26bc249a457cd958cad386d03aabd.png?auto=format" class="img-fluid" style="width:50%" alt="RUM Event hierarchy"/></picture></figure></div></a><h2 id="default-attributes">Default attributes</h2><p>See a complete list of <a href="/standard-attributes/?product=browser">standard attributes</a> for RUM Browser.
