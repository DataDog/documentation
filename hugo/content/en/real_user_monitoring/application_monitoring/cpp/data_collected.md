<div id="cdoc-content" class=""><article><h2 id="overview">Overview</h2><p>The RUM C++ SDK generates events that have associated attributes. Quantifiable attributes can be used for measurements related to the event, while non-quantifiable attributes can be used to slice telemetry in analytics (group by).</p><p>Every RUM event has all of the <a href="#default-attributes">default attributes</a>, for example, the device type (<code>device.type</code>) and user information such as their name (<code>usr.name</code>) and their country (<code>geo.country</code>). There are also <a href="#event-specific-attributes">event-specific attributes</a>. You can further enrich your session data by <a href="/real_user_monitoring/application_monitoring/cpp/advanced_configuration/#custom-attributes">adding custom attributes</a>.</p><h2 id="events">Events</h2><table><thead><tr><th>Event type</th><th>Retention</th><th>Description</th></tr></thead><tbody><tr><td>Session</td><td>30 days</td><td>A session represents a continuous usage period in your application. It begins with the first call to <code>StartView()</code> and remains active as long as the application is in use. All RUM events generated during the session share the same <code>session.id</code>. <strong>Note:</strong> The session resets after 15 minutes of inactivity and expires after 4 hours of continuous activity.</td></tr><tr><td>View</td><td>30 days</td><td>A view corresponds to a logical screen or scene, tracked manually using <code>StartView()</code> and <code>StopView()</code>. All events (errors, resources, and actions) generated while a view is active are attached to it with a unique <code>view.id</code>.</td></tr><tr><td>Resource</td><td>15 days</td><td>A resource represents a network request, tracked manually using <code>StartResource()</code> and <code>StopResource()</code>. Resources are associated with the active view.</td></tr><tr><td>Error</td><td>30 days</td><td>An error represents an exception or problem in the application, reported with <code>AddError()</code> or automatically captured as a crash. Errors are attached to the active view.</td></tr><tr><td>Action</td><td>30 days</td><td>An action represents a significant application or user event, tracked with <code>AddAction()</code> for instantaneous events or <code>StartAction()</code> and <code>StopAction()</code> for continuous ones. Actions are attached to the active view.</td></tr></tbody></table><p>The following diagram illustrates the RUM event hierarchy:</p><a href="http://localhost:1313/images/real_user_monitoring/data_collected/event-hierarchy.86b26bc249a457cd958cad386d03aabd.png?fit=max&amp;auto=format" class="pop" data-bs-toggle="modal" data-bs-target="#popupImageModal"><div class="shortcode-wrapper shortcode-img expand"><figure class="text-center"><picture style="width:50%"><img srcSet="http://localhost:1313/images/real_user_monitoring/data_collected/event-hierarchy.86b26bc249a457cd958cad386d03aabd.png?auto=format" class="img-fluid" style="width:50%" alt="RUM Event hierarchy"/></picture></figure></div></a><h2 id="default-attributes">Default attributes</h2><p>By default, RUM collects common attributes for all events and the event-specific attributes listed below. You can further enrich your session data by <a href="/real_user_monitoring/application_monitoring/cpp/advanced_configuration/#custom-attributes">adding custom attributes</a>.</p><h3 id="common-core-attributes">Common core attributes</h3><table><thead><tr><th>Attribute name</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>application.id</code></td><td>string</td><td>The RUM application ID.</td></tr><tr><td><code>application.name</code></td><td>string</td><td>The RUM application name.</td></tr><tr><td><code>date</code></td><td>integer</td><td>Start of the event in milliseconds from epoch.</td></tr><tr><td><code>service</code></td><td>string</td><td>The <a href="/getting_started/tagging/unified_service_tagging/">unified service name</a> for this application.</td></tr><tr><td><code>env</code></td><td>string</td><td>The environment tag (for example, <code>production</code> or <code>staging</code>).</td></tr><tr><td><code>version</code></td><td>string</td><td>The application version set with <code>SetVersion()</code>.</td></tr><tr><td><code>type</code></td><td>string</td><td>The type of the event (for example, <code>view</code> or <code>error</code>).</td></tr></tbody></table><h3 id="operating-system">Operating system</h3><p>The following OS-related attributes are attached automatically to all events collected by Datadog:</p><table><thead><tr><th>Attribute name</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>os.name</code></td><td>string</td><td>The OS name as reported by the system (for example, <code>Windows</code>, <code>macOS</code>, or <code>Linux</code>).</td></tr><tr><td><code>os.version</code></td><td>string</td><td>The OS version string (for example, <code>10.0.22631</code>, <code>14.2.1</code>).</td></tr><tr><td><code>os.version_major</code></td><td>string</td><td>The major version component (for example, <code>10</code>, <code>14</code>, <code>22</code>).</td></tr><tr><td><code>os.build</code></td><td>string</td><td>The OS build identifier (for example, <code>22631.6491</code>, <code>23C71</code>). Omitted if unavailable.</td></tr></tbody></table><h3 id="device">Device</h3><p>The following device-related attributes are attached automatically to all events collected by Datadog:</p><table><thead><tr><th>Attribute name</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>device.type</code></td><td>string</td><td>The device type (for example, <code>desktop</code>).</td></tr><tr><td><code>device.name</code></td><td>string</td><td>The device name (for example, <code>MacBookPro</code>, <code>Latitude 7420</code>).</td></tr><tr><td><code>device.model</code></td><td>string</td><td>The device model identifier (for example, <code>MacBookPro16,1</code>).</td></tr><tr><td><code>device.brand</code></td><td>string</td><td>The device brand or manufacturer (for example, <code>Apple</code>, <code>Dell Inc.</code>).</td></tr><tr><td><code>device.architecture</code></td><td>string</td><td>The CPU architecture (for example, <code>x86_64</code>, <code>arm64</code>).</td></tr><tr><td><code>device.locale</code></td><td>string</td><td>The system locale as a language tag (for example, <code>en-US</code>, <code>fr-FR</code>).</td></tr><tr><td><code>device.time_zone</code></td><td>string</td><td>The IANA time zone identifier (for example, <code>America/New_York</code>, <code>Europe/Berlin</code>).</td></tr></tbody></table><h3 id="geolocation">Geolocation</h3><p>The following attributes are related to the geolocation of IP addresses. Datadog resolves these attributes server-side from the client IP address on the intake connection. The SDK does not access the device's GPS or OS location.</p><p><strong>Note:</strong> If you want to stop collecting geolocation attributes, change the setting in your <a href="/data_security/real_user_monitoring/#geolocation">application details</a>.</p><table><thead><tr><th>Attribute name</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>geo.country</code></td><td>string</td><td>Name of the country.</td></tr><tr><td><code>geo.country_iso_code</code></td><td>string</td><td>ISO code of the country (for example, <code>US</code> for the United States or <code>FR</code> for France).</td></tr><tr><td><code>geo.country_subdivision</code></td><td>string</td><td>Name of the first subdivision level of the country (for example, <code>California</code> in the United States).</td></tr><tr><td><code>geo.continent_code</code></td><td>string</td><td>ISO code of the continent (<code>EU</code>, <code>AS</code>, <code>NA</code>, <code>AF</code>, <code>AN</code>, <code>SA</code>, <code>OC</code>).</td></tr><tr><td><code>geo.continent</code></td><td>string</td><td>Name of the continent (<code>Europe</code>, <code>Australia</code>, <code>North America</code>, <code>Africa</code>, <code>Antarctica</code>, <code>South America</code>, <code>Oceania</code>).</td></tr><tr><td><code>geo.city</code></td><td>string</td><td>The name of the city (for example, <code>San Francisco</code>, <code>Paris</code>, or <code>New York</code>).</td></tr></tbody></table><h3 id="global-user-attributes">Global user attributes</h3><p>You can enable <a user.</td></tr><tr><td><code>usr.name</code></td><td>string</td><td>Name of the user.</td></tr><tr><td><code>usr.email</code></td><td>string</td><td>Email of the user.</td></tr></tbody></table><h3 id="account-attributes">Account attributes</h3><p>You can enable <a href="/real_user_monitoring/application_monitoring/cpp/advanced_configuration/#track-user-and-account-information">tracking account name</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>acc.id</code></td><td>string</td><td>Identifier of the account.</td></tr><tr><td><code>acc.name</code></td><td>string</td><td>Name of the account.</td></tr></tbody></table><h2 id="event-specific-attributes">Event-specific attributes</h2><h3 id="session">Session</h3><table><thead><tr><th>Attribute</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>session.id</code></td><td>string</td><td>Unique ID of the session.</td></tr><tr><td><code>session.type</code></td><td>string</td><td>Type of the session (<code>user</code>).</td></tr><tr><td><code>session.is_active</code></td><td>Boolean</td><td>Indicates if the session is active. The session ends after 15 minutes of inactivity or 4 hours of continuous activity.</td></tr><tr><td><code>session.ip</code></td><td>string</td><td>IP address of the session extracted from the TCP connection of the intake. If you want to stop collecting this attribute, change the setting in your <a href="/data_security/real_user_monitoring/#ip-address">application all views collected for this session.</td></tr><tr><td><code>session.action.count</code></td><td>number</td><td>Count of all actions collected for this session.</td></tr><tr><td><code>session.error.count</code></td><td>number</td><td>Count of all errors collected for this session.</td></tr><tr><td><code>session.resource.count</code></td><td>number</td><td>Count of all resources collected for this session.</td></tr><tr><td><code>session.initial_view.name</code></td><td>string</td><td>Name of the initial view of the id="resource">Resource</h3><table><thead><tr><th>Attribute name</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>resource.id</code></td><td>string</td><td>A unique identifier for collected with Real User Monitoring (RUM). The error message and stack trace are included when available.</p><table><thead><tr><th>Attribute name</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>error.source</code></td><td>string</td><td>Where the error originated (for example, <code>source</code>, <code>network</code>, or <code>custom</code>).</td></tr><tr><td><code>error.type</code></td><td>string</td><td>The error type or kind string provided to <code>AddError()</code>.</td></tr><tr><td><code>error.message</code></td><td>string</td><td>A concise, human-readable, one-line message explaining the event.</td></tr><tr><td><code>error.stack</code></td><td>string</td><td>The stack trace or complementary information about the error.</td></tr><tr><td><code>error.category</code></td><td>string</td><td>High-level grouping for the type of error. Possible values: <code>Exception</code>, <code>Network</code>.</td></tr><tr><td><code>error.is_crash</code></td><td>Boolean</td><td><code>true</code> if the error caused the application to crash.</td></tr></tbody></table><h4 id="network-errors">Network errors</h4><p>Network errors include information about failing HTTP requests. The following facets are also collected:</p><table><thead><tr><th>Attribute</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>error.resource.status_code</code></td><td>number</td><td>The response status code.</td></tr><tr><td><code>error.resource.method</code></td><td>string</td><td>The HTTP method (for example, <code>POST</code> or <code>GET</code>).</td></tr><tr><td><code>error.resource.url</code></td><td>string</td><td>The resource URL.</td></tr></tbody></table><h3 id="action">Action</h3><table><thead><tr><th>Attribute name</th><th>Type</th><th>Description</th></tr></thead><tbody><tr><td><code>action.id</code></td><td>string</td><td>A unique identifier for the action.</td></tr><tr><td><code>action.type</code></td><td>string</td><td>The type of action (for example, <code>tap</code>, <code>click</code>, <code>scroll</code>, <code>swipe</code>, or <code>custom</code>).</td></tr><tr><td><code>action.target.name</code></td><td>string</td><td>The name provided to <code>AddAction()</code> or <code>StartAction()</code>.</td></tr><tr><td><code>action.loading_time</code></td><td>number (ns)</td><td>Duration of the action.</td></tr><tr><td><code>action.error.count</code></td><td>number</td><td>Count of errors that occurred while this action was active.</td></tr><tr><td><code>action.resource.count</code></td><td>number</td><td>Count of resources tracked while this action was active.</td></tr></tbody></table><h2 id="data-storage">Data storage</h2><p>The SDK stores events on disk before uploading them to Datadog. Events are preserved across application restarts, so data collected before an unexpected shutdown is sent on the next launch. The SDK manages disk usage automatically, pruning the oldest events when limits are reached. You can configure the storage location using <code>SetApplicationStoragePath()</code> in <code>CoreConfig</code>. See <a href="/real_user_monitoring/application_monitoring/cpp/advanced_configuration/#application-storage-path">Event Storage Location</a> for details.</p><h2 id="further-reading">Further
