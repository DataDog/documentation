<div id="cdoc-content" class=""><article><p>Instrument your Electron applications for <a href="/real_user_monitoring/">Real User Monitoring (RUM)</a> with the Electron SDK.</p><ul><li>The Electron SDK monitors the main process. It uses <code>dd-trace-js</code> to collect traces and sends the data from the main process to Datadog.</li><li>The Browser SDK monitors renderer processes. It forwards its events to the main process, which uploads them to Datadog.</li></ul><h2 id="prerequisites">Prerequisites</h2><p>Before you begin, you need:</p><ul><li>A Datadog account with RUM enabled</li><li>Electron 39 or later, on Linux, macOS, or Windows</li></ul><h2 id="create-the-application-in-datadog">Create the application in Datadog</h2><ol><li>In Datadog, navigate to <a href="https://app.datadoghq.com/rum/application/create"><strong>Digital Experience</strong> &gt; <strong>Add an Application</strong></a>.</li><li>Select <strong>Electron</strong> as the application type.</li><li>Copy the client token and application ID. You need them to initialize the SDK.</li></ol><div class="alert alert-info"><p>If you've purchased Error Tracking as a standalone product (without RUM), navigate to <a href="https://app.datadoghq.com/error-tracking/settings/setup/client"><strong>Error Tracking</strong> &gt; <strong>Settings</strong> &gt; <strong>Browser and Mobile</strong> &gt; <strong>Add an Application</strong></a> instead.</p></div><h2 id="install-the-sdk">Install the SDK</h2><p>Add <code>@datadog/electron-sdk</code> to your application:</p><div class='code-tabs'>

These windows send no data, including the interactions that keep the session alive. If end users interact only with such windows, the session expires after 15 minutes of inactivity and no new session starts.</p></div><p>To wait for the end user's consent, don't defer <code>init</code>. Call it at startup with <code>trackingConsent: 'pending'</code> instead. See <a href="/real_user_monitoring/application_monitoring/electron/setup/#set-tracking-consent">Set tracking consent</a>.</p><h2 id="set-up-renderer-processes">Set up renderer processes</h2><p>Renderer processes are monitored by the Browser SDK.</p><ol><li>Follow the <a href="/real_user_monitoring/application_monitoring/browser/setup/">Browser SDK setup</a> in the pages loaded by your renderer processes.</li><li>In the main process <code>init</code> call, list the renderer hosts that report through the main process in <code>allowedRendererHosts</code>. Renderers whose host is not listed do not report through the main process.</li></ol><div class="alert alert-info"><p>Sampling, Session Replay, and profiling options are set in the main process <code>init</code> call, and the main process manages sessions. The values set in the renderer for these options, including <code>sessionPersistence</code>, are ignored.</p></div><p>For details on <code>allowedRendererHosts</code>, see <a href="/real_user_monitoring/application_monitoring/electron/advanced_configuration/#allowed-renderer-hosts">Advanced Configuration</a>.</p><h2 id="configure-your-bundler">Configure your bundler</h2><p>The SDK must load before Electron. Add the Datadog plugin for your bundler to the main-process bundler configuration so that this order is respected.</p><p>By default, the plugins do not copy the SDK or <code>dd-trace-js</code> into the build output. Your application packager must include <code>@datadog/electron-sdk</code> and its runtime dependencies, so keep <code>@datadog/electron-sdk</code> in your application's production <code>dependencies</code>.</p><h3 id="electron-forge">Electron Forge</h3><p>The Forge Vite and Webpack plugins package only the <code>.vite</code> or <code>.webpack</code> directory.
