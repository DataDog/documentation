<div id="cdoc-content" class=""><article><h2 id="overview">Overview</h2><p>The RUM Roku SDK generates events that have associated telemetry and attributes. Telemetry is quantifiable values that can be used for measurements related to the event. Attributes are non-quantifiable values used to slice telemetry values (group by) in analytics.</p><p>Every RUM event has all of the <a href="#default-attributes">default attributes</a>, for example, the device type (<code>device.type</code>) and user information such as their name (<code>usr.name</code>) and their country (<code>geo.country</code>).</p><p>There are additional <a href="#event-specific-attributes">attributes specific to a given event type</a>. For example, the <code>view.loading_time</code> telemetry is associated with view events, and the <code>resource.method</code> attribute is associated with resource events.</p><table><thead><tr><th>Event Type</th><th>Retention</th><th>Description</th></tr></thead><tbody><tr><td>Session</td><td>30 days</td><td>A session represents a real user journey on your Roku channel. It begins when the user launches the channel, and the session remains live as long as the user stays active. During the user journey, all RUM events generated as part of the session will share the same <code>session.id</code> attribute. <strong>Note:</strong> The session resets after 15 minutes of inactivity. If the channel crashes or is killed by the Roku OS, it will reset the session.</td></tr><tr><td>View</td><td>30 days</td><td>A view represents a unique screen (or screen segment) on your Roku channel. A view starts when you call the <code>startView</code> function and stops when a new view is started. Each occurrence is classified as a distinct view. While a user stays on a view, RUM event attributes (Errors, Resources, and Actions) get attached to the view with a unique <code>view.id</code>.</td></tr><tr><td>Resource</td><td>15 days</td><td>A resource represents network requests to first-party hosts, APIs, and third-party providers in your Roku channel. All requests generated during a user session are attached to the view with a unique <code>resource.id</code>.</td></tr><tr><td>Error</td><td>30 days</td><td>An error represents an exception or crash emitted by the Roku channel attached to the view it is generated in.</td></tr><tr><td>Action</td><td>30 days</td><td>An action represents user activity in your Roku channel (such as a remote click). Each action is attached with a unique <code>action.id</code> attached to the view it gets generated in.</td></tr><tr><td>Long Task</td><td>15 days</td><td>A long task event is generated for any task in the application that blocks the main thread for more than the specified duration threshold.</td></tr></tbody></table><p>The following diagram illustrates the RUM event hierarchy:</p><a href="http://localhost:1313/images/real_user_monitoring/data_collected/event-hierarchy.86b26bc249a457cd958cad386d03aabd.png?fit=max&amp;auto=format" class="pop" data-bs-toggle="modal" data-bs-target="#popupImageModal"><div class="shortcode-wrapper shortcode-img expand"><figure class="text-center"><picture style="width:50%"><img srcSet="http://localhost:1313/images/real_user_monitoring/data_collected/event-hierarchy.86b26bc249a457cd958cad386d03aabd.png?auto=format" class="img-fluid" style="width:50%" alt="RUM Event hierarchy"/></picture></figure></div></a><h2 id="default-attributes">Default attributes</h2><p>RUM collects common attributes for all events and attributes specific to each event listed below automatically. You can also choose to enrich your user session data by tracking <a href="/real_user_monitoring/application_monitoring/roku/advanced_configuration/#enrich-user-sessions">additional events</a> or by <a href="/real_user_monitoring/application_monitoring/roku/advanced_configuration/#enrich-user-sessions">adding custom attributes</a> to default events specific to your application monitoring and business analytics needs.</p><h3 id="common-core-attributes">Common core attributes</h3><table><thead><tr><th>Attribute <code>resource</code>).</td></tr><tr><td><code>service</code></td><td>string</td><td>The <a href="/getting_started/tagging/unified_service_tagging/">unified service name</a> for this application used align="left">The name of the city (for example, <code>San Francisco</code>, <code>Paris</code>, or <code>New York</code>).</td></tr></tbody></table><h3 id="global-user-attributes">Global user (ns)</td><td>Time spent on a session.</td></tr><tr><td><code>session.type</code></td><td>string</td><td>Type of the session
