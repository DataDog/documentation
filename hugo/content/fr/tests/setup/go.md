## Installation d'Orchestrion {#installing-orchestrion}

Orchestrion est un outil permettant de traiter le code source Go au moment de la compilation et d'insérer automatiquement une instrumentation à l'aide de `dd-trace-go`.

Installez `orchestrion` depuis [https://github.com/datadog/orchestrion][1] en utilisant la commande :

```bash
$ go install github.com/DataDog/orchestrion@latest
```

{{% collapse-content title="Optionnel : enregistrement du go.mod du projet" level="h3" expanded=false %}}

Vous pouvez ajouter automatiquement `orchestrion` aux dépendances de votre projet en exécutant :

```bash
$ orchestrion pin
```

Cette commande a les effets suivants :
1. Créer un nouveau fichier `orchestrion.tool.go` contenant un contenu similaire à :
    
    ```go
    // Code generated by `orchestrion pin`; DO NOT EDIT.

    // This file is generated by `orchestrion pin`, and is used to include a blank import of the
    // orchestrion package(s) so that `go mod tidy` does not remove the requirements rom go.mod.
    // This file should be checked into source control.

    //go:build tools

    package tools

    import _ "github.com/DataDog/orchestrion"
    ```

2. Exécutez `go get github.com/DataDog/orchstrion@<current-release>` pour vous assurer que la version du projet correspond à la
    version actuellement utilisée
3. Exécutez `go mod tidy` pour vous assurer que vos fichiers `go.mod` et `go.sum` sont à jour

Si vous n'exécutez pas cette commande, elle est effectuée automatiquement si nécessaire. Une fois terminé, la version de `orchestrion`
utilisée par ce projet peut être contrôlée directement à l'aide du fichier `go.mod`, comme vous contrôleriez toute autre dépendance.

{{% /collapse-content %}}


Orchestrion prend en charge les deux dernières versions de Go, conformément à la [politique de publication officielle][go-releases] de Go. Il peut
fonctionner correctement avec les anciennes versions de Go, mais Datadog ne peut pas prendre en charge les anciennes versions qui ne fonctionnent pas.

En plus de cela, Orchestrion ne prend en charge que les projets utilisant des [modules Go][go-modules].

[go-releases]: https://go.dev/doc/devel/release#policy
[go-modules]: https://pkg.go.dev/cmd/go#hdr-Modules__module_versions__and_more

## Instrumentation des tests {#instrumenting-tests}

Pour configurer la bibliothèque, définissez les variables d'environnement suivantes avant de démarrer le processus de test. Pour les exécuteurs de tests parallèles, définissez-les sur le processus parent afin que chaque worker en hérite.

`DD_CIVISIBILITY_ENABLED=true` (Requis)
: Active Test Optimization.<br/>
**Par défaut**: `false`

`DD_SERVICE` (Optionnel)
: Nom du service ou de la bibliothèque à tester.<br/>
**Par défaut**: Le nom du dépôt

`DD_ENV` (Optionnel)
: Nom de l'environnement où les tests sont exécutés.<br/>
**Par défaut**: `(empty)`<br/>
**Exemples**: `local`, `ci`

`DD_CIVISIBILITY_AGENTLESS_ENABLED=true` (Requis pour le mode Agentless)
: Activez le mode Agentless pour envoyer les résultats des tests directement à Datadog.<br/>
**Par défaut** : `false`

`DD_API_KEY` (Requis pour le mode Agentless)
: La clé d'API Datadog utilisée pour authentifier les téléchargements des résultats de test. Cette variable n'active pas le mode Agentless.<br/>
**Par défaut** : `(empty)`

`DD_SITE` (Optionnel pour le mode Agentless)
: Le [site Datadog][2] vers lequel télécharger les résultats de test. Définissez cette configuration lorsque vous utilisez un site autre que US1.<br/>
**Par défaut** : `datadoghq.com`

`DD_TRACE_AGENT_URL` (Uniquement lors de l'utilisation du Datadog Agent)
: L'URL du Datadog Agent pour la collecte des traces, sous la forme `http://hostname:port`.<br/>
**Par défaut** : `http://localhost:8126`

`DD_TEST_SESSION_NAME` (Optionnel)
: Identifie un groupe de tests, tel que `unit-tests`, `integration-tests` ou `smoke-tests`.<br/>
**Par défaut**: Le nom du job CI et la commande de test, ou la commande de test si le nom du job CI n'est pas disponible.<br/>
**Exemple**: `unit-tests`, `integration-tests`, `smoke-tests`

Faites précéder votre commande go test de `orchestrion` :

```bash
$ orchestrion go test -race ./...
```

Si vous n'avez pas exécuté `orchestrion pin`, vous pourriez voir apparaître un message similaire au suivant, car `orchestrion pin` est exécuté automatiquement :

```
  ╭──────────────────────────────────────────────────────────────────────────────╮
  │                                                                              │
  │  Warning: github.com/DataDog/orchestrion is not present in your go.mod       │
```

### Alternative {#alternative}

_Orchestrion_ est essentiellement un proxy `-toolexec` de la chaîne d'outils Go standard. Au lieu d'utiliser `orchestrion go`, vous pouvez
également fournir manuellement l'argument `-toolexec` aux commandes `go` qui l'acceptent :

```console
$ go build -toolexec 'orchestrion toolexec' .
$ go test -toolexec 'orchestrion toolexec' -race .
```
