[Signals Explorer][1]でWorkload Protectionシグナルを選択すると、サイドパネルに、攻撃のストーリーを再構築し、影響を理解し、生のシグナルデータにアクセスするための調査ツールが表示されます。

## 何が起こったか{#what-happened}

{{< ui >}}What Happened{{< /ui >}}セクションでは、現在のシグナルの概要を確認できます。

- {{< ui >}}Attack chain{{< /ui >}}: 検出されたアクティビティと、それがより広範な脅威ストーリーにどのように適合するかについての人間が読める形式の説明。
- {{< ui >}}Where{{< /ui >}}: クラウドプロバイダー、アカウント、リージョン、ホスト、Kubernetesクラスター、ネームスペース、ポッド、コンテナ、イメージなど、シグナルが発生したインフラストラクチャーのコンテキスト。
- {{< ui >}}Detection rule{{< /ui >}}: 名前、重大度、ルール式など、シグナルを生成したバックエンド検出ルール。
- {{< ui >}}Agent rule{{< /ui >}}: ルール名、イベント名、デプロイメントポリシーなど、基盤となるランタイムアクティビティと一致した Agent ルール。

## 調査グラフ{#investigation-graph}

{{< ui >}}Investigation{{< /ui >}}タブには、シグナルに関与するプロセス、リソース、およびランタイムイベントをマッピングするインタラクティブなグラフが表示されます。調査グラフは、攻撃がどのように段階的に展開されたかを把握するのに役立ちます。

{{< img src="security/workload_protection/investigate_and_triage/security_signals/signal_investigation_graph.png" alt="攻撃者から侵害されたコンテナまでの攻撃チェーンを示す調査グラフ。相関するプロセスと不審なアクションが含まれています。" width="100%">}}

グラフから、Code SecurityやInfrastructure Monitoringなどの他のテレメトリソースにピボットして、コードの脆弱性を検証したり、特定のリソースに関する詳細情報を取得したりできます。

### 相関イベント{#correlated-events}

調査グラフで{{< ui >}}Correlated events{{< /ui >}}を使用して、最初のシグナルを超えてビューを拡張します。これは[変数][2]を使用して、同じプロセス系統またはエクスプロイトチェーンに属するランタイムアクティビティをグループ化します。相関キーは、同じ実行チェーン内の他のイベントと関連付けます。

Workload Protectionによって検出された各イベントには、同じ実行チェーン内の他のイベントと関連付ける相関キーがタグ付けされます。このグループ化により、個別の警告に対応するのではなく、より広範な侵害の試みに集中できるようになります。

Workload Protectionは、以下を含む一般的なランタイムシナリオ向けの組み込みの実行コンテキストレイヤーをサポートしています。

- **汎用cgroupコンテキスト**: 関連のないイベントのフォールバックコンテキストです。
- **汎用auidコンテキスト**: ユーザーセッションごとにイベントをグループ化します。
- **サービスコンテキスト**: サービス境界内のランタイムアクティビティを分離します。
- **インタラクティブシェルコンテキスト**: 同じシェルセッションからのコマンドを関連付けます。
- **Kubernetesユーザーセッションコンテキスト**: きめ細かな相関付けにより、Kubernetesユーザーのアクションを追跡します。
- **マルウェアIOC**: ファイルハッシュやドメインなど、[脅威インテリジェンス][5]から同じマルウェアインジケーターに一致するイベントをグループ化します。

### 影響範囲{#blast-radius}

調査グラフで{{< ui >}}Blast radius{{< /ui >}}を使用して、検出された脅威の潜在的な影響を評価します。影響範囲ビューは、侵害が最初の検出ポイントを超えて広がった場合に影響を受ける可能性のあるリソース、サービス、および依存関係を強調表示します。

これにより、対応の優先順位を判断し、どの隣接するワークロード、ホスト、またはコンテナに追加の監視や強化が必要かを理解するのに役立ちます。

### イベントタイムライン{#events-timeline}

{{< ui >}}Events timeline{{< /ui >}}は、相関付けられた脅威ストーリー内のすべてのイベントの時系列の物語を提示します。相関イベント、トリアージステータス、対応、推奨アクションを単一のビューに統合します。これを使用して、ビューを切り替えることなく、最初の悪用からその後のアクションまで、攻撃者の動きをたどることができます。

タイムライン内の各イベントには、コンテキストの詳細と、相関付けられたメトリクス、ログ、トレースへのリンクが含まれています。

## コンテキスト{#context}

{{< ui >}}Context{{< /ui >}}タブは、シグナルがトリガーされたホストの主要な属性を要約し、影響を受けたリソースを評価するのに役立つ関連メトリクス、プロセス、その他の情報へのリンクを提供します。

## シグナルJSON{#signal-json}

{{< ui >}}Signal JSON{{< /ui >}}タブには、シグナルの未加工の内容が表示されます。シグナルJSONは、Signalsエクスプローラー、ダッシュボード、およびプログラムによるクエリを支える基盤となるデータ構造です。

次のような場合にSignal JSONを使用します：

- [Signals Explorer][1]または[dashboards][3]で、シグナルをグループ化、カウント、または関連付けるための複雑なクエリを作成します。
- [Datadog API][4]を通じてシグナルデータを利用する自動化や統合を構築します。
- 調査中に、シグナルの全ペイロードを同僚や外部ツールと共有します。

<div class="alert alert-info">Signal JSONは、シグナルをプログラムでクエリする上級ユーザーに最も役立ちます。ほとんどの調査では、調査グラフ、タイムライン、およびコンテキストタブが必要な情報を提供します。</div>
