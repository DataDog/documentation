[API 検出結果][1]エクスプローラーは、定義、ゲートウェイ、およびライブトラフィック全体で検出された API リスクの一元的なトリアージビューを提供します。デフォルトのルールは、一般的な脆弱性や誤構成を検出します。特定のユースケースに合わせて[カスタムルール][2]を追加することもできます。

**API 検出結果**の列:

- **Severity (重大度):** 各問題がリスクに基づいてランク付けされます。
- **Endpoints (エンドポイント):** 影響を受けるエンドポイントの数とそのサービスを表示します。
- **Status and Ticketing (ステータスとチケット発行):** `Open` または `In Progress` により、修復の進捗状況とワークフローのインテグレーションが追跡されます。

**サービス**ファセットを使用して各サービスのエンドポイントを確認し、所有権を特定してビジネスへの影響度に基づいて優先順位を付けます。

## 一般的な操作 {#common-operations}

検出結果をクリックして詳細を表示し、検証 > 調査 > 修正 > 追跡といったワークフローを実行します。

1. 検証:
   - [{{< ui >}}What Happened{{< /ui >}}] (発生した事象) および [{{< ui >}}Detected In{{< /ui >}}] (検出場所) を確認し、検出が正確であること (サービス、エンドポイント、メソッド) を確認します。
   - [{{< ui >}}Next Steps{{< /ui >}}] (次のステップ) で、所有権と影響度に応じて [{{< ui >}}Mute{{< /ui >}}] (ミュート)、[{{< ui >}}Create Ticket{{< /ui >}}] (チケットを作成)、[{{< ui >}}Run Workflow{{< /ui >}}] (ワークフローを実行) のいずれかを選択します。
2. 調査:
   - [{{< ui >}}Context{{< /ui >}}] (コンテキスト) タブを使用して、エンドポイントのスナップショットと属性 (メソッド、パス、認証フラグ、タグ) を調べます。
   - [{{< ui >}}Detected In{{< /ui >}}] は、ルーティングの所有権と修復に関する情報を提供します。
   - [{{< ui >}}Detection Rule Query{{< /ui >}}] (検出ルールクエリ) では、[{{< ui >}}See Detection Rule{{< /ui >}}] (検出ルールを表示) をクリックして API 検出結果ルールを編集できます。
3. 修正:
   - [{{< ui >}}Remediation{{< /ui >}}] (修復) のガイダンスに従ってください。
4. 追跡:
   - [{{< ui >}}Create Ticket{{< /ui >}}] を使用して、問題を追跡システムにリンクします。
   - [{{< ui >}}Reference Links{{< /ui >}}] (参照リンク) を使用して、開発者の教育やコードレビューを行います。

## 修復 {#remediation}

Datadog API Posture は [Bits Code][3] を使用して、脆弱性に対するコード修正を生成します。

1. Datadog で [[{{< ui >}}Security{{< /ui >}}] (セキュリティ) > [{{< ui >}}App & API Protection{{< /ui >}}] > [{{< ui >}}Findings{{< /ui >}}] (検出結果)][1] の順に移動します。
2. 検出結果を選択すると、その検出結果と影響を受けるエンドポイントに関する詳細が表示されたサイドパネルが開きます。
3. [**Next Steps**] (次のステップ) > [**Remediation**] セクションで、[**Fix with Bits**] (Bits で修正) をクリックします。

これにより、この単一の API 検出結果を修正するための Bits Code セッションが開きます。提案された差分を確認し、フォローアップの質問を行い、パッチを編集し、プルリクエストを作成してソースコードリポジトリに修復を適用できます。
すべての Bits Code セッションは、[**Bits AI**] > [**Bits Code**] > [[**Sessions**] (セッション)][4] で表示できます。

### 修復セッションの詳細 {#remediation-session-details}

各 Bits Code セッションには、AI が生成した修正のライフサイクルが表示されるため、マージ前に変更を確認および検証できます。たとえば以下のものが含まれます。

- 元のセキュリティ検出結果と提案されたコード変更
- Bits Code がその修正を生成した方法と理由の説明
- パッチが安全にデプロイできることを検証するための CI 結果 (有効な場合)
- 修正を調整するためのオプションや、ソースコードリポジトリに変更を適用するための [**Create PR**] (PR を作成)

修復セッションを開くには、[**[Findings] (検出結果)**][1] ページで API 検出結果を選択してサイドパネルを開き、[**Remediation**] セクションまでスクロールして、[**Expand & Chat**] (展開してチャット) を選択します。

[[**Sessions**]][4] ですべての修復セッションを表示することもできます。
