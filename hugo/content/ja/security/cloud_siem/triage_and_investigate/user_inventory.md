## 概要 {#overview}

[Cloud SIEM のユーザーインベントリ][6]は、Cloud SIEM 内にあるユーザーディレクトリの同期され正規化されたコピーです。Cloud SIEM が IdP から同期したすべてのユーザーアイデンティティが一覧表示されます。これには、そのユーザーに関連するアクティビティ、シグナル、またはリスクの有無は関係ありません。ユーザーが誰であるか、アカウントがどのような状態か、どのように変更されたかを確認する必要がある場合、IdP に切り替えることなく Cloud SIEM 内で確認できます。

ユーザーインベントリを使用すると、次のことが可能です。

- 同期されたすべてのユーザーアイデンティティとサービスアカウントを 1 つのリストで表示します。
- アカウントステータス、職責、オフィス所在地、プリンシパル ID、プロバイダー、およびユーザータイプでユーザーをフィルターします。
- 名前またはプリンシパル ID でインベントリを検索します。
- 職責、部署、オフィス所在地、多要素認証 (MFA) ステータスなど、ユーザーの現在の構成を確認します。
- ユーザーアイデンティティに関連付けられた各アカウントのリスクスコアと、そのスコアの推移を確認します。
- ユーザーのシグナル、ログイン、MFA の変更、パスワードの変更、構成の変更、およびログを時系列で追跡します。

ユーザーインベントリと[エンティティリスク][1]は、異なる目的に対応します。ユーザーインベントリは完全なディレクトリであり、アクティビティに関係なく同期されたすべてのユーザーが含まれます。エンティティリスクは優先順位付きのビューであり、リスクに基づいてスコアリングおよびランク付けされたユーザーアイデンティティやその他のエンティティを表示します。調査対象のユーザーが決まっている場合は、ユーザーインベントリから開始します。最初に確認すべきユーザーを Datadog に提示させたい場合は、エンティティリスクから開始します。

## 前提条件{#prerequisites}

### 権限 {#permissions}

以下の Cloud SIEM 権限がユーザーインベントリに適用されます。

| 権限 | 付与される権限 |
| ---------- | -------------- |
| **SIEM Entities Notification** | この権限を持つユーザーは、エンティティリスクの通知を変更できます。|
| **SIEM Entities Read** | ユーザーインベントリエクスプローラーを表示および検索し、ユーザーサイドパネルを開き、Signals サイドパネルで相関ユーザーピルを確認します。また、コンテンツパックエクスプローラー内のエンティティパックサイドパネルへの読み取りアクセス権も付与されます。|
| **SIEM Entities Admin** | SIEM Entities Read で付与されるすべての権限に加え、エンティティパックやその他のエンティティリスク設定を構成する機能が付与されます。以下のエンティティパックの前提条件を完了するために必要です。|

<div class="alert alert-info">フィルターが適用されていない空のユーザーインベントリには、エンティティパックが有効になっていないか、<strong>SIEM Entities Read</strong> 権限がないという 2 つの原因が考えられます。まずエンティティパックの構成を確認し、次に権限を確認します。</div>

### エンティティパック {#entity-packs}

ユーザーインベントリは、IdP からユーザーおよびアイデンティティコンテキストを同期するエンティティパックによって挿入されます。ユーザーインベントリで結果を返すには、少なくとも 1 つのエンティティパックを有効にする必要があります。

エンティティパックは、以下のプロバイダーで利用可能です。

- [Microsoft Entra ID][2]
- [Okta][3]
- [Google Workspace][4]

エンティティパックを構成するには、`SIEM Entities Admin` 権限が必要です。エンティティパックは、コンテンツパックエクスプローラーから構成します。セットアップ手順については、[エンティティパック][5]を参照してください。

### 推奨: OCSF パイプライン {#recommended-ocsf-pipelines}

アクティブな Open Cybersecurity Schema Framework (OCSF) パイプラインはオプションです。Cloud SIEM は、標準属性のみを使用して一部のアクティビティをユーザーアイデンティティに関連付けることができます。ただし、アクティブな OCSF パイプラインを持つソースから、最も完全な相関関係を得ることができます。Cloud SIEM でのユーザーのアクティビティが予想よりも少ない場合は、関連するソースに OCSF パイプラインが構成されているかどうかを確認します。

## ユーザーインベントリの探索 {#explore-the-user-inventory}

ユーザーインベントリを開くには、[**Cloud SIEM**] > [**Investigate**] > [[**User Inventory**][6]] に移動します。

{{< img src="security/cloud_siem/user_inventory_explorer.png" alt="同期されたユーザーアイデンティティとプリンシパル ID、ユーザータイプ、アカウントステータス、プロバイダーを一覧表示するユーザーインベントリエクスプローラー。" style="width:100%;" >}}

### ユーザーの検索とフィルター {#search-and-filter-users}

表示名またはプリンシパル ID でユーザーを検索するには、検索ボックスにクエリを入力して <kbd>Enter</kbd> キーを押します。

属性でリストを絞り込むには、フィルターのドロップダウンを使用します。各フィルターのデフォルトは **All** です。

| フィルター | 一致するもの |
| ------ | --------------- |
| Account Status | アイデンティティプロバイダーにおけるアカウントのステータス (`ACTIVE`、`SUSPENDED`、`DELETED` など)。|
| Job Title | アイデンティティプロバイダーから報告されるユーザーの職責。|
| Office Location | アイデンティティプロバイダーから報告されるユーザーのオフィス所在地。|
| Principal ID | アイデンティティプロバイダーから報告されるユーザーのプリンシパル ID。|
| Provider | ユーザーの同期元であるアイデンティティプロバイダー。|
| User Type | アカウントのタイプ: `human`、`service_account`、または `guest`。|

職責、オフィス所在地、およびプリンシパル ID は、アイデンティティプロバイダーから渡されます。Cloud SIEM の値が正しくないか欠落している場合は、アイデンティティプロバイダーの対応するフィールドを確認します。

### SIEM 内でのユーザーの表示 {#browse-users-in-siem}

- スクロールすると、リストにユーザーがさらに読み込まれます。リスト上部のエンティティ数は、読み込まれたユーザーの数と、現在の検索およびフィルターに一致するユーザーの数を示します。
- **Changes Detected** 列は、過去 14 日間に 1 つ以上の属性変更を含んでいたユーザーアイデンティティへの更新回数をカウントします。個々の属性ではなく更新回数をカウントするため、3 つの属性を変更した 1 回の更新は 1 回としてカウントされます。最近構成が変更されたユーザーを特定し、ユーザーを開いて **Entity changes** タブで変更内容を確認します。
- リストを CSV ファイルとしてエクスポートするには、テーブルの上にあるエクスポートアイコンをクリックします。CSV ファイルには、Cloud SIEM に同期されたすべてのユーザーではなく、現在ビューに読み込まれているユーザーのみが含まれます。エクスポートにより多くのユーザーを含めるには、まずスクロールして読み込みます。
- 表示する列を変更するには、列設定アイコンをクリックします。

## ユーザーアイデンティティの調査 {#investigate-a-user-identity}

ユーザーリストの任意の行をクリックすると、ユーザーサイドパネルが開きます。同じ情報を全画面表示で開くには、[**Open Fullscreen**] をクリックします。

パネルのヘッダーには、ユーザーのアカウントステータス、表示名、パネルのスコープ対象となる時間範囲、および以下のメタデータが表示されます。

| フィールド | 説明 |
| ----- | ----------- |
| Principal ID | ユーザーのプリンシパル ID。コピーアイコンをクリックしてコピーします。|
| Type | アカウントのタイプ: `human`、`service_account`、または `guest`。|
| Created | アカウントが作成された日時 (相対時間で表示)。|
| Last updated | Cloud SIEM がこのユーザーアイデンティティへの変更を最後に同期した日時 (相対時間で表示)。|

相対時間はパネル全体に表示されます。相対時間の正確なタイムスタンプを確認するには、その上にホバーします。

{{< img src="security/cloud_siem/user_inventory_side_panel.png" alt="現在の状態と関連するリスクを表示する単一ユーザーアイデンティティのユーザーサイドパネル" style="width:100%;" >}}

### 現在の状態の確認 {#review-current-state}

「**Current state**」セクションには、最新の同期時点でのユーザーの構成が表示されます。

| フィールド | 説明 |
| ----- | ----------- |
| Identity Source(s) | このユーザーアイデンティティの同期元となったアイデンティティプロバイダー。|
| Email | ユーザーのメールアドレス。|
| Name | ユーザーの表示名。|
| Job | ユーザーの職責、部署、およびオフィス所在地。|
| MFA status | ユーザーが MFA を登録しているかどうか、およびポリシーで MFA が必須かどうかという 2 つの独立した状態。|

MFA ステータスは、値が不一致となる可能性があるため、2 つの独立した値として報告されます。`ENABLED` は、ユーザーが MFA を登録済みであることを意味します。`NOT ENFORCED` は、アイデンティティプロバイダーのポリシーにより、すべての状況でユーザーに MFA の使用が義務付けられているわけではないことを意味します。ポリシーを見直し、ギャップが存在するかどうかを把握します。

### リスクの確認 {#review-risks}

「**Risks**」セクションには、このユーザーアイデンティティに関連付けられた各アカウントのリスクスコアが一覧表示されます。これらはアカウントごとのスコアであり、ユーザーの集計スコアではありません。

| 列 | 説明 |
| ------ | ----------- |
| Risk Score | アカウントのリスクスコアと、それに対応する重大度。|
| Name | スコアが適用されるアカウント。|
| Type | スコア付けされたエンティティのタイプ (`Email Address` など)。|
| Source | アカウントのアクティビティの相関元となったログソース。オーバーフローインジケーターをクリックして、追加のソースを表示します。|
| Last Seen | アカウントが最後にシグナルを生成した日時 (相対時間で表示)。これは、アカウントでアクティビティが発生した最後の日時ではありません。|
| Risk Change | 過去 14 日間におけるアカウントのリスクスコアの変化。|
| Signals | アカウントのスコアに寄与しているシグナルの数。|

<div class="alert alert-info">Last Seen はシグナルアクティビティのみを反映します。Last Seen の値が古いアカウントでも、引き続きログが生成されている可能性があります。最新のアクティビティを確認するには、<strong>Activity History</strong> の <strong>All logs</strong> タブを確認します。</div>

Risk Change は常に固定の 14 日間の遡及期間を反映し、パネルの時間範囲セレクターには連動しません。

リスクスコアの計算方法およびカスタマイズ方法については、[エンティティリスク][1]を参照してください。

## アクティビティ履歴の探索 {#explore-activity-history}

「**Activity History**」セクションでは、ユーザーが実行した操作とアカウントの変更履歴を追跡します。以下の 2 つのコントロールでセクション全体をスコープします。

- **Activity from**: 単一のアカウントを選択してアクティビティをそのアカウントにスコープするか、**All** を選択してこのユーザーアイデンティティに関連付けられたすべてのアカウントのアクティビティを表示します。
- **Time range**: アクティビティ表示の期間を設定します。

各タブには結果の件数と、対象データをそれぞれのエクスプローラーで開く **See all** リンクが表示され、そこでさらにクエリを実行できます。

Activity History のデータは Datadog 標準属性または OCSF フィールドのいずれかにマッピングされているため、Cloud SIEM の他の場所で使用しているのと同じ属性名を使用してエクスプローラーでクエリを実行できます。

### Signals {#signals}

このユーザーアイデンティティに関連付けられたセキュリティシグナルを表示します。グラフビューはシグナルを重大度別に時系列で分類し、リストビューは個々のシグナルを表示します。このタブを使用して、ユーザーに対して検出が発生したかどうか、およびその直近の状況を確認します。

### Login and MFA changes {#login-and-mfa-changes}

ログインおよび MFA の変更アクティビティを棒グラフで時系列で表示します。このタブを使用して、ユーザーのログインパターンの変化や MFA 設定の変更など、認証動作の変化を特定します。

### Password changes {#password-changes}

ユーザーのパスワードが変更された日時を記録したタイムスタンプのシーケンスを表示します。このセクションを使用して、異常または疑わしいアカウントアクティビティの発生時期の近くでパスワードの変更が行われているかどうかを確認します。

### Entity changes {#entity-changes}

ユーザーの構成が時間の経過とともにどのように変化したかを表示します。Cloud SIEM はユーザーアイデンティティの各バージョンを保存するため、任意の 2 つのバージョンを比較して、どの属性が変更されたかを正確に確認できます。

タブヘッダーには、選択した期間中に行われた変更の数が表示されます。以下の 2 つのビューを利用できます。

- **JSON**: 2 つのバージョンの並列差分。削除された値は赤色で、追加された値は緑色で表示されます。
- **Timeline**: 変更の時系列ビュー。

{{< img src="security/cloud_siem/user_inventory_entity_changes.png" alt="ユーザーアイデンティティの 2 つのバージョンを比較する並列 JSON 差分。MFA 強制の変更を強調表示。" style="width:100%;" >}}

JSON ビューでは、各ペインの上にあるバージョン選択ドロップダウンを使用して、比較するバージョンを選択します。選択した 2 つのバージョン間の変更数が、2 番目のペインの横に表示されます。ノイズを減らすため、変更のない属性は折りたたまれています。非表示行インジケーターをクリックして展開します。

差分で追跡される属性には、ユーザーのメールアドレス、名、姓、職責、オフィス所在地、プリンシパル ID、プロバイダー、ユーザータイプのほか、`mfaEnrolled`、`mfaEnforced`、`lastPasswordChange` などの認証状態が含まれます。

<div class="alert alert-info">選択した時間範囲に関係なく、過去 14 日以内に行われたエンティティの変更のみがこのタブに表示されます。</div>

### All logs {#all-logs}

Cloud SIEM がこのユーザーアイデンティティに関連付けたすべてのログを表示します。以下の 3 つのビューを利用できます。

- **Graph**: ログソース別に分類された、時系列でのログボリュームの棒グラフ。その横にあるドーナツチャートは、ユーザーアイデンティティに関連付けられた各アカウントによるアクティビティの割合を示します。
- **Map**: アクティビティが検出された国が色分け表示された世界地図。
- **List**: 個別のログ。

このタブを使用して、ユーザーがどのシステムにアクセスしたか、またどのアカウントが最も多くのアクティビティを生成しているかを確認します。

### Time range {#time-range}

Activity History はデフォルトで 14 日間の遡及期間を使用します。期間は 30 日間以上に延長できます。

以下の 2 つのビューは時間範囲セレクターに連動しません。

- **Entity changes** は過去 14 日間に限定されます。
Risks セクションの [- **Risk Change**] は、常に固定の 14 日間の遡及期間を反映します。
