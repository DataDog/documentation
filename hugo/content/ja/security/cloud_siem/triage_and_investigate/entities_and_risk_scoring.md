## 概要{#overview}

[Cloud SIEM のエンティティリスク][4]は、SIEM の脅威や Cloud Security のインサイトなど、複数のデータソースを統合し、IAM ユーザーなどの単一のセキュリティエンティティを表すプロファイルを作成します。

<div class="alert alert-info">エンティティリスクは、以前はリスクインサイトと呼ばれていました。</div>

エンティティリスクを使用すると、次のことができます。

- エンティティを調べ、エンティティプロバイダー、エンティティタイプ、エンティティ名、[リスクスコアの重大度](#risk-scoring)、リスクスコア、構成リスクなどの属性でフィルタリングします。
- シグナル、誤構成、アイデンティティリスクなど、エンティティに関連するすべてのデータを表示します。
- ユーザーアイデンティティ別にリスクをグループ化して、1 人の人物につき 1 行を表示します。そのユーザーが使用するすべてのアカウントの合計リスクが示されます。
- リスクの高いエンティティやリスクの高いユーザーが発生したときに対応できるように通知を構成します。
- 関連する項目をまとめてトリアージします。
- グローバル抑制の作成やエンティティのケースの作成などの緩和措置を講じます。

## 前提条件{#prerequisites}

- エンティティリスクを使用するには、アクティブな OCSF (Open Cybersecurity Schema Framework) パイプラインを使用して、Cloud SIEM にログを送信するように以下のサポートされているログソースの少なくとも 1 つを構成します。
  - **アイデンティティおよびリソースエンティティを提供するソース** (ユーザー、サービスアイデンティティ、引き受けたロール、コンピューティングインスタンス、ストレージコンテナなど): AWS、Azure、GCP、GitHub、Microsoft 365、Okta。
  - **メールアドレスで識別されるユーザーエンティティを提供するソース**: 1Password、Cisco Duo、Cloudflare、CrowdStrike、Google Workspace、JumpCloud、LastPass、Salesforce、Slack、ZIA (Zscaler Internet Access)。
- サポートされているソースの多くは、追加の構成を必要としない[すぐに使える OCSF パイプライン][8]を使用しています。サポートされているソースがエンティティを生成していない場合は、すぐに使える OCSF パイプラインがアクティブであることを確認してください。OCSF サポート以前のパイプラインやカスタマイズされたパイプラインには、必要な OCSF 処理が含まれていない場合があります。
- Datadog では、[[Content Packs] (コンテンツパック)][10] ページでアイデンティティプロバイダー (Okta、Google Workspace、または Microsoft Entra ID) の[エンティティパック][9]を構成することを推奨しています。ユーザーアイデンティティが同期されると、エンティティリスクは各人物のアカウントを単一のユーザーアイデンティティに解決し、そのリスクを集計します。ユーザーアイデンティティの通知も利用可能になります。エンティティパックがない場合、エンティティでは個別のスコアリングとアラート生成のみが行われます。「[ユーザーアイデンティティ別にグループ化されたリスク](#risk-grouped-by-user-identity)」を参照してください。
-  (オプション) エンティティパネルで関連する Cloud Security インサイトを表示するには、[Cloud Security を構成する必要があります][2]。


## エンティティリスクを調べる {#explore-entity-risks}

### エンティティのクエリとフィルタリング {#query-and-filter-entities}

[[Entity Risks] (エンティティリスク)][4] ページでは、ゼロ以外のリスクスコアが関連付けられているすべてのエンティティを表示できます。

{{< img src="security/entities/entities-explorer4.png" alt="リスクとそのスコアが一覧表示されている [Entity Risks] ページ。1 つのユーザーアイデンティティ行が展開され、その下にエンティティが表示されています" style="width:100%;" >}}

### ユーザーアイデンティティ別にグループ化されたリスク {#risk-grouped-by-user-identity}

フェデレーション環境では、1 人の人物が通常、複数のメールエイリアス、IAM ユーザー、引き受けたロール、コードリポジトリアカウントなど、多くの個別のエンティティを通じて行動します。これらのエンティティを個別に表示した場合は、その人物の合計リスクは表示されません。

ご使用のアイデンティティプロバイダー用に[エンティティパック][9]を設定すると、Cloud SIEM はそのプロバイダーからユーザーアイデンティティを同期します。その後、各アイデンティティに属するエンティティを解決します。1 人の人物に解決されるエンティティは、その人物の名前が付けられた単一のユーザーアイデンティティ行の下にグループ化されます。その行のリスクスコアは、その下にあるエンティティのリスクスコアの合計です。グループ化は、アイデンティティプロバイダーが接続されるたびに自動的に適用されます。

ユーザーアイデンティティを調査するには、次のようにします。

1. [エンティティリスク][4]で、展開されている矢印と関連エンティティの数が表示されている行を見つけます。
1. 矢印をクリックして行を展開し、そのユーザーアイデンティティに解決された各エンティティを、独自のリスクスコア、タイプ、ソース、およびシグナル数とともに確認します。
1. エンティティをクリックしてサイドパネルを開き、「[エンティティに関するコンテキストを迅速に作成する](#quickly-build-context-on-an-entity)」の説明に従って調査を続けます。

<div class="alert alert-info">エンティティリスクは、ユーザーアイデンティティに明確に解決されるエンティティのみをグループ化します。単一のアイデンティティに解決できないエンティティは引き続き個別の行として表示されるため、同一人物が複数回表示されることがあります。</div>

### エンティティに関するコンテキストを迅速に構築する {#quickly-build-context-on-an-entity}

[エンティティリスク][4]のエンティティをクリックして、エンティティサイドパネルを開きます。

{{< img src="security/entities/entity-side-panel4.png" alt="[What Happened] (発生した事象) の概要と [Risk Contributors] (リスク要因) のリストが表示されているエンティティのサイドパネル" style="width:90%;" >}}

パネルの [{{< ui >}}What Happened{{< /ui >}}] (発生した事象) セクションには、シグナル、誤構成、アイデンティティリスクの数と、それらがどのようにリスクスコアに寄与しているか、および潜在的な構成リスクの概要が示されます。

[{{< ui >}}Risk Contributors{{< /ui >}}] (リスク要因) セクションには、送信されたシグナル、関連する誤構成、およびアイデンティティリスクのリストが表示されます。

[{{< ui >}}What Happened{{< /ui >}}] および [{{< ui >}}Risk Contributors{{< /ui >}}] セクションには、エンティティのリスクスコアにポイントを加算するシグナル、誤構成、およびアイデンティティリスクのみが含まれます。スコアに影響を与えないものを含め、エンティティに関連付けられたすべてのシグナルを表示するには [{{< ui >}}View All Related Signals{{< /ui >}}] (関連するシグナルをすべて表示) をクリックします。誤構成ミスとアイデンティティリスクを表示するには、[{{< ui >}}View in Vulnerability Explorer{{< /ui >}}] (Vulnerability Explorer で表示) をクリックします。

### 脅威をまとめてトリアージおよび緩和する {#triage-and-mitigate-threats-in-bulk}

エンティティサイドパネルの [{{< ui >}}Risk Contributors{{< /ui >}}] セクションには、利用可能な緩和手順が示されています。対処する項目を選択し、インラインアクションを使用して、トリアージ状態の設定、項目の割り当て、セキュリティケースの作成、インシデントの宣言、または抑制の作成を行います。

## エンティティリスクの通知を構成する {#configure-notifications-for-entity-risks}

{{< site-region region="gov,gov2" >}}<div class="alert alert-danger">通知ルールは、 {{< region-param key="dd_site_name" >}} サイトでは利用できません。</div>
{{< /site-region >}}

条件に一致する新しい脅威が検出されたらすぐに通知を送信するように Datadog を構成することができます。

1. [{{< ui >}}Create a new Entity Risk notification{{< /ui >}}] (新規エンティティリスク通知の作成) ページに移動します。これを行う方法は 2 つあります。
   - Datadog で [エンティティリスク][4] ページに移動し、[{{< ui >}}Create Notification Rule{{< /ui >}}] (通知ルールの作成) をクリックしてください。
   - Datadog で [{{< ui >}}Cloud SIEM{{< /ui >}}] > [{{< ui >}}Settings{{< /ui >}}] (設定) に移動します。[{{< ui >}}Products{{< /ui >}}] (製品) の [{{< ui >}}Cloud SIEM{{< /ui >}}] セクションで [[{{< ui >}}Entity Risks{{< /ui >}}][7] をクリックし、[{{< ui >}}Notification rules{{< /ui >}}] (通知ルール) の下にある [{{< ui >}}New notification rule{{< /ui >}}] (新規通知ルール) をクリックしてください。
1. [{{< ui >}}Group risk by{{< /ui >}}] (リスクのグループ化基準) で、ルールの測定対象を選択します。
   - [{{< ui >}}Individual entity{{< /ui >}}] (個別のエンティティ): ルールは各エンティティの独自のリスクスコアを評価します。
   - [{{< ui >}}User identity{{< /ui >}}] (ユーザーアイデンティティ): このルールは、ユーザーアイデンティティの集計されたリスクスコアを評価します。これは、その人物に解決されたすべてのエンティティのスコアを合計したものです。このオプションは、エンティティパックが構成され、ユーザーアイデンティティが同期されている場合に使用できます。「[集計されたユーザーアイデンティティリスクについて通知する](#notify-on-rolled-up-user-identity-risk)」を参照してください。
   <div class="alert alert-warning">ルールを作成した後で、ルールのグループ化を変更することはできません。別のグループ化を使用するには、別のルールを作成してください。</div>
1. [{{< ui >}}Define entity attributes{{< /ui >}}] (エンティティ属性の定義) で、Datadog によってエンティティ上で検出されたときに通知をトリガーする属性を指定します。[{{< ui >}}Entities matching{{< /ui >}}] (エンティティの一致) の横で、エンティティの属性と値の入力を開始します。入力中に、プレビューテーブルに条件に一致するエンティティが動的に表示されます。
   <div class="alert alert-info">このステップはオプションです。ただし、属性を入力しない場合、通知ではデフォルトで、すべてのエンティティに関するアラートを送信します。</div>
1. [{{< ui >}}Set notification conditions{{< /ui >}}] (通知条件の設定) で、エンティティの重大度またはリスクスコア値に基づいてトリガー条件を設定します。
   - [{{< ui >}}Entity severity{{< /ui >}}] (エンティティの重大度): エンティティが特定の重大度レベルに達したときに通知をトリガーします。演算子を選択し、重大度レベルを選択します。各重大度レベルに対応するリスクスコアについては、「[エンティティの重大度しきい値](#entity-severity-thresholds)」を参照してください。
   - [{{< ui >}}Risk score value{{< /ui >}}] (リスクスコア値): エンティティのリスクスコアが指定されたしきい値を超えたときに通知をトリガーします。通知のしきい値を指定します。
1. [{{< ui >}}Configure notification{{< /ui >}}] (通知の構成) で、通知の名前を入力し、カスタムメッセージ本文を追加して、送信先の受信者を指定します。
   - オプションで、再通知を有効にすることもできます。また、エンティティが指定した条件をまだ満たしている場合に、Datadog が受信者に再通知するまでの期間を指定します。
1. 設定を確認するには、[{{< ui >}}Test Notification{{< /ui >}}] (通知のテスト) をクリックして、構成された受信者にテスト通知を送信します。
1. [{{< ui >}}Save Notification{{< /ui >}}] (通知の保存) をクリックします。

### 集計されたユーザーアイデンティティリスクについて通知する {#notify-on-rolled-up-user-identity-risk}

[{{< ui >}}User identity{{< /ui >}}] (ユーザーアイデンティティ) でグループ化されたルールは、ある人物のすべてのエンティティにわたる合計リスクがしきい値を超えたときにユーザーに通知します。これを利用すると、個々のエンティティしきい値を超えているエンティティがない場合に、複数のエンティティに分散されているリスクを特定できます。

ユーザーアイデンティティでグループ化されたルールは、個々のエンティティルールとは以下の点で異なります。

- **一致する属性はユーザー属性です。**エンティティ属性の代わりに、ユーザーインベントリに表示される内容と一致する、解決されたユーザーアイデンティティの属性をクエリします。たとえば、アイデンティティプロバイダー、ユーザータイプ、部署、役職、事業所の場所でクエリできます。プレビューテーブルには、一致するユーザーアイデンティティと集計されたリスクスコアが表示されます。
- **条件は集計されたスコアを評価します。**個々のエンティティルールと同様に、エンティティの重大度レベルまたはリスクスコア値のいずれかでトリガーすることができ、同じ[エンティティ重大度しきい値](#entity-severity-thresholds)が適用されます。どちらの場合も、条件は単一のエンティティのスコアではなく、ユーザーアイデンティティの集計されたリスクスコアに対して評価されます。
- **しきい値を超えると通知が送信されます。**Datadog は、ユーザーアイデンティティがしきい値を超えた状態になったときに通知を送信します。しきい値を超えた状態が続いている間に、評価が行われるたびに通知を送信することはありません。ルール作成時にユーザーアイデンティティがすでにしきい値を超えている場合、Datadog は通知を 1 件送信します。ユーザーアイデンティティがしきい値を超えた状態である間は、再通知を使用して再度注意を促すことができます。
- **メッセージの内容は人物中心です。**テンプレート変数には、ユーザーアイデンティティの表示名、アイデンティティプロバイダー、集計されたリスクスコア、寄与しているエンティティの数、スコアへの影響度が高いエンティティが含まれます。
- **通知にはユーザーインベントリへのリンクがあります。**通知の主要なリンクから、ユーザーインベントリのユーザーアイデンティティのサイドパネルが開きます。

ユーザーアイデンティティでグループ化されたルールと個々のエンティティでグループ化されたルールはともに使用され、ルールリストでは各ルールにそのグループのラベルが付けられます。どちらの種類のルールも、組織につき 100 個という同じ通知ルール数の上限を計測する際の対象となります。

## リスクスコアリング {#risk-scoring}

エンティティのリスクスコアは、過去 14 日間のアクティビティにおけるエンティティのリスクレベルを概算したものです。Datadog は、シグナルの重大度レベルやシグナルが送信された回数など、エンティティに関連するシグナルの特徴からリスクスコアを算出します。

### シグナルのスコア影響度を表示およびカスタマイズする {#view-and-customize-signal-score-impacts}

各シグナルには、その重大度に基づいてスコア影響度が設定されています。Datadog によって、各シグナルの重大度にデフォルトのポイント数が割り当てられます。組織のデフォルトのスコア影響度、および誤構成アイデンティティリスクの影響を表示または上書きするには、[エンティティリスクの設定ページ][7]に移動します。

スコア影響度を変更すると、Datadog ではそれを既存のすべてのエンティティリスクスコアに即時かつ遡及的に適用します。更新されたスコアを使用して、今後のエンティティリスク通知に対する変更の影響を評価できるため、ノイズを減らし、通知から提供されるシグナルを増やすことができます。

<div class="alert alert-info">シグナルのスコア影響度は 14 日間存続し、14 日が経過すると <code>0</code>に低下します。</div>

| シグナルの重大度 | ポイント数 |
|-----------------|------------------|
| `Critical`      | `100`            |
| `High`          | `50`             |
| `Medium`        | `5`              |
| `Low` と `Info`| `0`              |

### エンティティの重大度しきい値 {#entity-severity-thresholds}

エンティティの重大度しきい値は、そのエンティティに関連付けられているすべてのシグナルのスコア影響を合計して算出されます。ユーザーアイデンティティにも同じしきい値が適用されます。その重大度は、集計されたリスクスコアから算出されます。これは、ユーザーアイデンティティに解決されたすべてのエンティティのリスクスコアの合計です。

| 重大度しきい値          | リスクスコア                                         |
|-----------------------------|----------------------------------------------------|
| `Critical`                  | `100` 以上。                   |
| `High`                      | `50` 以上、`100` 未満。|
| `Medium`                    | `25` 以上、`50` 未満。 |
| `Low`                       | `10` 以上、`25` 未満。 |
| `Info`                      | `10` 未満。                                   |
