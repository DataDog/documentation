## チーム詳細 {#team-detail}

各チームには、チーム、そのメンバー、および関連するリソースに関する情報が表示される詳細ページがあります。[Teams ディレクトリ][1]でチームをクリックして、チーム詳細ページに移動します。

チーム詳細ページは、次の 3 つのタブで構成されています。

- **[Info] (情報)**: チームの基本詳細とメンバーシップ。
- **[Resources] (リソース)**: チームに関連付けられている Datadog リソース。
- **[On-Call]**: チームの [Datadog On-Call][6] 構成。

チームヘッダーには、チームのアバター、バナー、名前、および説明が表示されます。絵文字アバターとバナーを選択して、チームの外観をカスタマイズします。絵文字アバターは、Datadog 全体でリストのチーム名の横に表示されます。

### [Info] タブ {#info-tab}

チームの基本詳細: 通知チャネル、リンク、接続、階層 (親チームとサブチーム)、およびメンバー。

### [Resources] タブ {#resources-tab}

生産性、ソフトウェア、パフォーマンス、クラウドコストなどの領域ごとにグループ化された、チームが所有する Datadog リソース。チームにサブチームがある場合は、[**Include Subteams**] (サブチームを含める) トグルを使用して、サブチームのリソースをチーム自体のリソースと合わせて表示します。

### [On-Call] タブ {#on-call-tab}

チームの [Datadog On-Call][6] 設定: メンバー、スケジュール、エスカレーションポリシー、ルーティング、および引き継ぎの自動化。

### 設定をカスタマイズする {#customize-settings}

チームの詳細を変更するには、`user_access_manage` または `teams_manage` 権限が必要です。あるいは、メンバーやマネージャーがチームの詳細を編集できるように設定されているチームのメンバーまたはマネージャーも編集を行えます。

チームの詳細ページから直接、チームの詳細を編集します。

- **アバター、名前、説明**: チーム名にマウスを合わせ、編集 (鉛筆) アイコンをクリックします。
- **バナー**: バナーにマウスを合わせ、編集 (鉛筆) アイコンをクリックします。
- **[Info] タブのセクション**: [Links] (リンク)、[Members] (メンバー)、[Notification Channels] (通知チャネル) などのセクションにマウスを合わせ、編集アイコンをクリックしてその場で更新します。

チームヘッダーの [Settings] (設定) (歯車) メニューを使用して、次の操作を行います。

- **[Configure Notifications] (通知の設定)**: チームの通知チャネルを追加または更新します。サポートされているターゲットには、Slack、Microsoft Teams、PagerDuty、メール、ServiceNow があります。
- **[Edit Roles and Permissions] (ロールと権限の編集)**: チームに関連付けられているロールと権限を管理します。
- **[Edit Team Handle] (チームハンドルの編集)**: チームのハンドルを変更します。
- **[Edit Connections] (接続の編集)**: チームを外部システムに接続します。**GitHub チーム**を接続して Datadog チームを GitHub チームに関連付けるか、**ServiceNow アサインメントグループ**を接続してインシデントや変更リクエストを自動的にルーティングします。
- **[Join Team] (チームに参加)** または **[Leave Team] (チームを脱退)**: 自分をチームに追加するか、チームから削除します。

## チームのメンバーシップ {#team-membership}

### チームマネージャー {#team-manager}

チームのメンバーを区別するために、一部のメンバーをチームマネージャーに指定します。メンバーリストでは、チームマネージャーの名前の横に「TEAM MANAGER」バッジが表示されます。

### チーム変更権限 {#team-modification-permissions}

チームのロールと権限の設定で、チームのメンバーシップを変更できるユーザーを指定します。利用可能なオプションは次のとおりです。
- Only users with the `user_access_manage` permission (user_access_manage 権限を持つユーザーのみ)
- Team managers (チームマネージャー)
- Team managers and members (チームマネージャーとメンバー)
- Anyone in the organization (組織内の全員)

リストは、許可範囲が広い順に並べられています。リスト内の各オプションには、その上にあるエントリに含まれるグループが含まれます。たとえば、[Team managers] を選択した場合、チームマネージャーと `user_access_manage` を持つユーザーの両方がメンバーシップを変更できます。

メンバーを追加および削除できるユーザーを決定するために選択したオプションによって、アクセス制御リストをチームに追加できるかどうかが決まります。チームには、招待制チームとオープンチームの 2 種類があります。

招待制チーム
: メンバーシップが制限されているチーム。アクセス制御の受信者として設定できます。最初の 3 つのオプションのいずれかにチームメンバーシップの変更を制限した場合に作成されます。

オープンチーム
: メンバーシップが制限されていないチーム。アクセス制御の受信者として設定できません。[{{< ui >}}Anyone in the organization{{< /ui >}}] がチームメンバーシップを変更できるようにした場合に作成されます。

`user_access_manage` 権限を持つユーザーは、メンバーの追加や削除、またはチーム詳細の編集が可能なユーザーに関するデフォルトルールを設定できます。チームディレクトリページの [{{< ui >}}Default Settings{{< /ui >}}] (デフォルト設定) ボタンを使用して、デフォルトルールを設定します。チーム詳細パネルで、個々のチームに対してこれらのポリシーを上書きします。

### Datadog 外で管理されているチーム {#teams-managed-outside-datadog}

場合によっては、`user_access_manage` を持つユーザーを含め、誰であっても Datadog 内でチームのメンバーシップを直接変更できないことがあります。
- 組織が SAML を唯一のチームプロビジョニングソースとして選択している場合、SAML チームマッピングによってチームのメンバーシップが制御されます。Datadog を通じてチームのメンバーシップを変更することはできません。
- チームがアイデンティティプロバイダーを通じて管理されている場合は、そのアイデンティティプロバイダーがチームのメンバーシップを制御します。Datadog を通じてチームのメンバーシップを変更することはできません。

アイデンティティプロバイダーによって外部で管理されているチームには、ヘッダーに [**Managed**] (管理対象) バッジが表示されます。

#### 複数のソースを持つチーム {#teams-with-multiple-sources}

1 つのチームが複数のソースに接続できますが、ソースの種類によって制御の範囲が決まります。

**チームを管理するソース**
- **ソース:** SCIM、および SAML 専用モードの SAML
- SCIM がチームをプロビジョニングする場合、または組織で SAML のみのプロビジョニングを使用している場合にチームが管理されます。ソースは、チームの名前、ハンドル、およびメンバーシップを制御します。Datadog やその他のソースを通じてそれらを変更することはできません。他のソースは接続したままにすることができます。たとえば、[ServiceNow][12] からインシデントをルーティングできます。

**チームを同期するソース**
- **ソース:** [GitHub][9]、[ServiceNow][12]、および SAML (SAML が唯一のプロビジョニングソースではない場合)
- これらのソースは、排他的な制御を行わずにチームを同期します。これらはチームの名前、ハンドル、およびメンバーシップを設定します。他のソースをチームに接続することや、Datadog UI、[Teams API][10]、または [Terraform プロバイダー][11]からそれらを変更することは可能です。複数のソースが同じチームにメンバーを同期する場合、Datadog は各ソースのメンバーを結合します。

<div class="alert alert-info">SCIM は、GitHub または ServiceNow からすでに同期されているチームの管理を開始できます。チームはそのソースとの接続を維持しますが、SCIM がその名前、ハンドル、およびメンバーシップを制御します。</div>

<div class="alert alert-info">GitHub および ServiceNow は、管理ソースがチームを制御していない場合にのみ、チーム名を更新します。ソースは [{{< ui >}}Import, create, and link teams{{< /ui >}}] を使用してチームを作成している必要もあります。チームの作成後、これらのソースがチームハンドルを変更することはありません。</div>


## チーム階層 {#team-hierarchies}

Teams マップを作成してチーム階層を可視化し、チームを互いに入れ子にしてサブチームを作成することで、会社の実際の構造を反映されます。そうすると、階層がなく、チーム間の関連がないリストよりも包括的な所有権モデルが作成されます。チームの関連チーム、親チーム、姉妹チーム、サブチームは、そのチームのページの [**Info**] タブにある [**Hierarchy**] (階層) セクションに表示されます。組織に含まれるすべてのチームのマップ全体を確認するには、Datadog Internal Developer Portal の [Teams マップ][7]をご覧ください。

{{< img src="/account_management/teams/github/manage/teams-map.png" alt="親チームと子チームの階層が示されている Teams マップ。選択したチームの詳細パネルに、メンバーとサブチームが表示されています。" style="width:100%;" >}}

階層を定義すると、次のことが可能になります。

- **問題のエスカレーション**: 担当チームだけでは問題に対処できない場合、階層に沿って親チームに問題が引き継がれるため、次に誰が対応すべきかを個別に探すことなく、より広い範囲で問題を把握し、迅速に解決できます。
- **ロールアップフィルタリング**: 親チームを選択すると、各サブチームを個別に選択しなくても、そのサブチームに関連付けられているすべてのデータを表示できます。これは、特定のチームではなく組織全体のフットプリントに関心があるディレクターや VP レベルのビューで役立ちます。
- **アクセス制御の簡素化**: 親チームレベルで一度アクセス権を付与すると、すべてのサブチームに一貫した権限が自動的に適用されます。

{{< img src="account_management/teams/teams_filter_hierarchies2.png" alt="親チームが展開され、チェックボックスとして選択するサブチームが表示されているチームフィルタードロップダウン" style="width:35%;" >}}

### チーム階層を設定する {#set-up-team-hierarchies}

チーム間の階層関係は、次の 5 つの方法で定義できます。

- **GitHub Teams**: [GitHub][9] を使用して Datadog Teams を設定し、GitHub のチーム階層を構成した場合、それらのチーム間のリンクはプロビジョニング中に Datadog に自動的に同期され、Teams マップに表示されます。
- **ServiceNow アサインメントグループ**: [ServiceNow][12] を使用して Datadog Teams を設定し、アサインメントグループに親グループがある場合、それらのリンクはプロビジョニング中に Datadog に自動的に同期され、Teams マップに表示されます。
- **Teams API**: 「[チーム階層リンクの作成][5]」を参照してください。
- **Terraform**: [`datadog_team_hierarchy_links`][8] リソースを使用します。
- **Datadog UI**: チームのページで直接関係を定義します。
   1. [チームディレクトリページ][1]で、サブチームまたは親チームの関係を追加するチームをクリックします。
   1. チームページの [{{< ui >}}Info{{< /ui >}}] タブで、[{{< ui >}}Hierarchy{{< /ui >}}] セクションの [{{< ui >}}Edit{{< /ui >}}] (編集) をクリックします。
   1. チームに関連付ける親チームまたは子チームを選択し、[{{< ui >}}Save{{< /ui >}}] (保存) をクリックします。

## 制限事項 {#limits}

- 組織には最大 5,000 個のチームを含めることができます。
- チーム階層の最大深度は 10 レベルです。

## アイデンティティプロバイダーによるチーム管理 {#manage-teams-through-an-identity-provider}

管理対象チームをセットアップする際、ID プロバイダーとのインテグレーションを通じてチームのプロパティを外部から設定します。
 - チーム名
 - チームハンドル
 - チームのメンバーシップ (対応するアイデンティティプロバイダーのグループから同期される)

管理対象チームとアイデンティティプロバイダーにおけるチームの設定との一貫性を維持するには、Datadog サイトや API 経由ではなく、アイデンティティプロバイダーで管理対象プロパティを変更してください。

Datadog は、管理対象チーム向けに Okta やその他 SCIM 準拠の ID プロバイダーをサポートしています。

管理対象チームの機能や設定方法の詳細については、「[SCIM][3]」を参照してください。

## SAML 属性マッピング {#saml-attribute-mapping}

SAML 属性を使用してチームおよびチームメンバーシップを管理するには、「[SAML 属性のチームへのマッピング][2]」を参照してください。

## チーム管理を委任する {#delegate-team-management}

オープンメンバーシップモデルの場合は、[{{< ui >}}Anyone in the organization{{< /ui >}}] がメンバーを追加または削除できるようにデフォルトのチーム設定を構成します。全員がチームを作成したり、チームの詳細を編集したりできるようにするには、適切なロールに `teams_manage` 権限を割り当てます。

チーム主導のメンバーシップモデルを使用する場合は、[{{< ui >}}Team Managers{{< /ui >}}] または [{{< ui >}}Team Managers and Members{{< /ui >}}] がメンバーを追加または削除できるように、デフォルトのチーム設定を構成します。すべてのチームマネージャーを含むロールに、`teams_manage` 権限を割り当てます。

厳格なメンバーシップモデルを適用するには、[{{< ui >}}Only users with user_access_manage{{< /ui >}}] がメンバーを追加または削除できるように、デフォルトのチーム設定を構成します。`teams_manage` 権限は、組織の管理者のみに割り当てます。
