アクセスのリクエストはプレビュー版であり、順次提供される予定です。貴組織ではまだ利用できない場合があります。
{{< /callout >}}

## 概要 {#overview}

Datadog の機能へのアクセスを取得する場合、誰に依頼すべきかを把握し、チケットを発行し、回答を待つという手順を経ることになります。多数のロールやユーザーを管理している組織では、これによりユーザーの作業が遅延し、管理者の手動作業が増加します。

アクセスのリクエストを使用すると、ユーザーはブロックされているページから直接、リクエストの正当な理由を添えて必要な権限を要求することができます。管理者は、中央キューからこれらのリクエストを確認および承認することや、特定のロールが自動的に付与されるように設定することができます。すべてのリクエスト、決定、および正当な理由は [Audit Trail][2] に表示されるため、サポートチケットなしでアクセス権の変更を追跡できます。

## アクセスのリクエストを有効または無効にする {#enable-or-disable-request-access}

**注**: `user_access_manage` 権限が必要です。

組織で手動または自動承認リクエストを有効にするには、[[Organization Settings] (組織設定)][1]に移動して [{{< ui >}}Access Controls{{< /ui >}}] (アクセス制御) を選択し、対応する設定を作成します。設定の詳細については、「[管理者としてアクセスリクエストを設定する](#configuring-access-requests-as-an-administrator)」を参照してください。

手動または自動の承認リクエストを無効にするには、対応するすべての設定を削除します。別の内部アクセス昇格プロセスを通じてアクセスを管理している場合は、無効化が特に重要です。

## エンドユーザーとしてアクセスをリクエストする {#requesting-access-as-an-end-user}

### アクセス拒否ページから {#from-a-permission-denied-page}

必要な権限が付与されていないページにアクセスすると、Datadog により 403 アクセス拒否ページが表示されます。組織で、その権限を含むロールに対する手動承認または自動承認設定を有効にしている場合は、ページに [{{< ui >}}Request Access{{< /ui >}}] (アクセスのリクエスト) ボタンが表示されます。

1. [{{< ui >}}Request Access{{< /ui >}}] をクリックします。
2. リクエストの正当な理由を入力します。
3. リクエストを送信します。

一致する自動承認設定が存在する場合、Datadog により 1 分以内にアクセスが許可され、通知されます。そうでない場合、Datadog によって組織の承認者にリクエストが送信され、そこで手動のレビューが行われます。

### [Roles] (ロール) ページから {#from-the-roles-page}

アクセス拒否ページが表示される前に、直接ロールをリクエストすることもできます。

1. [[Organization Settings]][1] に移動し、[{{< ui >}}Roles{{< /ui >}}] を選択します。
2. 目的のロールを見つけて、その詳細パネルを開きます。
3. [{{< ui >}}Request Access{{< /ui >}}] をクリックします。
4. 正当な理由を入力して送信します。

直接のロールリクエストは、アクセス拒否ページから行われるリクエストと同じ承認および自動承認ルールに従います。

### アセットの場合 {#for-an-asset}

管理者が自動承認ルールを設定している場合は、モニターやダッシュボードなどのアセットへのアクセスをリクエストすることもできます。

個々のアセットへのアクセスをリクエストするには、そのアセットに移動し、[{{< ui >}}Request Access{{< /ui >}}] をクリックします。すでに閲覧者アクセス権を持っており、より高い権限レベルをリクエストする場合は、代わりにそのアセットの既存の共有設定を開きます。

## 管理者としてアクセスリクエストを設定する {#configuring-access-requests-as-an-administrator}

[[Organization Settings]][1] に移動し、[{{< ui >}}Access Controls{{< /ui >}}] を選択して、すべてのアクセスリクエスト設定を構成および管理します。このページにアクセスするには、`user_access_manage` 権限が必要です。

### 手動承認 {#manual-approval}

手動承認では、リクエストを承認または拒否できる一連の承認者にリクエストがエスカレーションされます。組織では 1 つの手動承認設定がサポートされており、これを有効にすると組織内のすべてのロールに対して手動リクエストが有効になります。

1. [[Organization Settings]][1] に移動し、[{{< ui >}}Access Controls{{< /ui >}}] を選択します。
2. 手動承認設定を作成します。
3. リクエストを承認できるユーザーを選択します。`user_access_manage` 権限を持つユーザーのみを選択できます。

承認者を指定しない場合でも、`user_access_manage` を持つすべてのユーザーがリクエストを承認または拒否することはできますが、メール通知は送信されません。

承認者は、[Access Controls] ページの [{{< ui >}}Pending Requests{{< /ui >}}] (保留中のリクエスト) タブから保留中のリクエストを確認します。ここには、各リクエストのリクエスター、ロール、およびリクエスターの正当な理由が表示されます。承認者がアクションを実行すると、Datadog からリクエスターにメールが送信されます。

### ロールと権限の自動承認 {#auto-approval-for-roles-and-permissions}

自動承認を使用すると、対象ユーザーは手動レビューを実行せずに、即座に自分のブロックを解除できます。

1. [[Organization Settings]][1] に移動し、[{{< ui >}}Access Controls{{< /ui >}}] を選択します。
2. 自動承認設定を作成します。組織では最大 10 個の設定を作成できます。
3. この設定で自動承認するロールを選択します。
4. 必要に応じて、この設定をトリガーできるユーザー、チーム、またはロールを制限します。このフィールドを空のままにすると、すべてのユーザーに設定が適用されます。

### 一時的なアクセス (プレビュー) {#temporary-access-preview}

自動承認設定では、ロールを永続的ではなく期間限定で付与できます。設定を作成する際に、割り当て期間を 1 時間、1 日、1 週間、30 日、または永続的に設定します。

一時的なロールの割り当てが期限切れになると、Datadog は 5 分以内にそのロールを無効にします。ユーザーのプロファイルページ、または [[Organization Settings]][1] の [{{< ui >}}Users{{< /ui >}}] (ユーザー) から、ユーザーのアクティブなロール割り当てと期限切れになるロール割り当てを確認できます。

### アセットの自動承認 {#auto-approval-for-assets}

アセットの自動承認は、個々のリソースに対して同じセルフサービスモデルを拡張します。組織では、以下のリソースタイプに対して閲覧者または編集者アクセスの自動承認を設定できます。

- Case Management プロジェクト
- ダッシュボード
- モニター
- Notebooks
- リファレンステーブル
- Synthetic テスト
- Synthetic グローバル変数
- Synthetic プライベートロケーション

リソースタイプを有効にすると、そのタイプのリソースすべてに設定が適用されます。ロールや権限の自動承認と同様に、アセットの自動承認設定でも、特定のユーザー、チーム、またはロールを対象にすることができます。アクセスレベルごとに、個別に対象となるリクエスターを設定します。たとえば、すべてのユーザーにダッシュボードへの閲覧者アクセスのリクエストを許可しながら、編集者アクセスのリクエストは特定のチームのみが行えるように制限することができます。

## Audit Trail {#audit-trail}

Datadog は、リクエスター、リクエストされたロールまたはリソース、正当な理由、結果など、すべてのアクセスリクエストを [Audit Trail][2] に記録します。Audit Trail を使用すると、チケットやチャット履歴を利用しなくても、アクセス履歴を確認できます。

## ロール選択の仕組み {#how-role-selection-works}

ユーザーが権限不足のためにアクセスをリクエストした場合、Datadog は必要な権限を満たすロールのうち、合計権限数が最も少ないロールを選択します。権限数が同じロールが複数ある場合、Datadog はアルファベット順で最初のロールを選択します。この選択方法により、管理者が考えられるすべてのアクセスシナリオに対してすべてのロールをあらかじめマッピングしなくても、過剰なプロビジョニングを防ぐことができます。

## 制限事項 {#limitations}

- 組織では、1 つの手動承認設定と最大 10 個の自動承認設定を作成できます。
- 組織内のどのロールにも必要な権限が含まれていない場合、ユーザーはその権限へのアクセスをリクエストすることはできません。
- リクエストによって付与されるのは単一の権限ではなく、ロール全体です。よりきめ細かな制御が必要な場合は、必要な権限のみにスコープを絞ったロールを作成し、それを自動承認または手動承認のオプションとして設定してください。
