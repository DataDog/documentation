## 概要 {#overview}

一元化された使用量メトリクスにより、パートナー管理組織 (Admin Org) は、接続されているすべての顧客組織の使用量および推定使用量メトリクスを監視できます。メトリクスは顧客ごとにタグ付けされて Admin Org にロールアップされるため、パートナーは単一のダッシュボード、モニター、およびアラートのセットから、ビジネス全体の使用量をフィルタリングして紐付けることができます。

Datadog は 2 種類の使用量メトリクスを生成します。

- **推定使用量メトリクス** (`datadog.estimated_usage.*` 名前空間)。これらのメトリクスは数分以内に更新され、使用量をほぼリアルタイムで表示します。推定使用量メトリクスは、請求対象の使用量と平均で約 10〜20% 異なる場合があり、使用量の少ない組織では分散が大きくなることがあります。メトリクスの詳細なリファレンスについては、[推定使用量メトリクス][1]を参照します。
- **使用量メトリクス** ({{< ui >}}Usage{{< /ui >}} クエリソース)。これらのメトリクスは、請求書を生成するものと同じメータリングおよび請求パイプラインから取得されるため、プランと使用量を密接に追跡します。使用量メトリクスは推定使用量メトリクスほど即時的ではありませんが、請求に関する話し合いには十分な精度を備えています。

推定使用量メトリクスを使用して使用量の急増を早期に検出し、使用量メトリクスを使用して請求書と照合する数値をレポートします。

## アトリビューションタグ {#attribution-tags}

ロールアップされたメトリクスには、次の 2 つのタグが付与されます。

- `account_name`: 親組織名 (Admin Org)。
- `child_org_name`: 子組織名 (顧客組織、親組織に対する相対名称)。

## クエリ使用量メトリクス {#query-usage-metrics}

ダッシュボードウィジェットまたはモニターを作成する場合:

- 推定使用量メトリクスの場合は、{{< ui >}}Metrics{{< /ui >}} をソースとして選択し、`datadog.estimated_usage.*` メトリクスを使用します。
- 使用量メトリクスの場合は、{{< ui >}}Usage{{< /ui >}} をソースとして選択し、使用タイプ (例: {{< ui >}}Infra Hosts{{< /ui >}}) を選択します。

推定使用量メトリクスの場合は、`child_org_name` タグを使用してクエリをフィルタリングまたはグループ化します。例として、すべての顧客の推定インフラストラクチャーホスト使用量をクエリします。

```
sum:datadog.estimated_usage.hosts{*} by {child_org_name}
```

{{< img src="partners/multi_tenant_billing/usage_metrics_rollup.png" alt="推定使用量メトリクスと child_org_name タグを表示するメトリクスソース。" style="width:100%;" >}}

使用量メトリクスの場合は、`child_org_name` でフィルタリングしてクエリの対象を 1 つの顧客に絞り込むか、`child_org_name` でグループ化して顧客同士を比較します。

{{< img src="partners/multi_tenant_billing/usage_source_infra_hosts.png" alt="[Infra Hosts] が選択された使用量クエリソース。" style="width:100%;" >}}

Plan & Usage の合計値と一致させるには、ホストスタイルの製品には 1 時間ごとのロールアップを使用し、Plan & Usage のレポートは UTC で行われるため、UTC でグラフ化します。
