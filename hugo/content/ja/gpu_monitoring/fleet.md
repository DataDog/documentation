## 概要 {#overview}

[GPU Fleet Explorer][0] は、指定された期間における AI インフラストラクチャー (GPU デバイス、ホスト、Ray クラスターなど) および AI ワークロード (ポッド、Kube Containers、トレーニング実行など) の詳細な内訳を提供します。このページでは、GPU 使用率、ホストレベルのメトリクス、コストなどのリソーステレメトリを通じて、プロビジョニングの非効率性やワークロードのパフォーマンス最適化の機会を発見できます。また、Datadog によるフリートやワークロードに影響を与える問題のリアルタイム検知機能と、その修正方法に関するガイダンスも表示されます。

## すぐに使えるモニターで問題を検知 {#detect-issues-with-out-of-the-box-monitors}

Datadog には、以下のような一般的な GPU の問題をリアルタイムで検知する、すぐに使える (OOTB) モニターテンプレートがいくつか用意されています。

- 温度の急上昇
- 電力制限スロットリング
- 対応できていない GPU リクエスト
- XID エラー
- ECC エラー
- 突発的なワークロード
- アイドル状態のデバイス

組織のニーズに合わせて、各モニターのしきい値をカスタマイズできます。

これらのテンプレートにアクセスするには、ページ右上の {{< ui >}}Monitors{{< /ui >}} ドロップダウンをクリックします。

{{< img src="gpu_monitoring/fleet-ootb-monitors.jpg" alt="[GPU Fleet] (GPU フリート) ページの右上にあるモニタードロップダウン。温度、電力制限スロットリング、対応できていない GPU リクエスト、重大な XID エラー、一般的な XID エラー、ECC エラー、突発的なワークロード、アイドル状態のデバイスのためのすぐに使える (OOTB) モニターテンプレートが表示されています。" style="width:40%;" >}}

## 任意のタグでフリートの内訳を表示する{#break-down-your-fleet-by-any-tag}

GPU Fleet Explorer を使用すると、AI ワークロードから基盤となる AI インフラストラクチャーまでを可視化できます。ポッドやトレーニング実行などのワークロードエンティティと、デバイス、ホスト、クラスターなどのインフラストラクチャーエンティティを切り替えることができます。

{{< img src="gpu_monitoring/gpu-fleet-sidenav.jpg" alt="AI インフラストラクチャーエンティティ (デバイス、ホスト、Kube クラスター、Ray クラスター) と、AI ワークロードエンティティ (ポッド、Kube Containers、トレーニング実行) を示すサイドナビゲーションバー" style="width:30%;" >}}

**注**: サイドナビゲーションの [Kube Clusters] (Kube クラスター)、[Pods] (ポッド)、[Kube Containers] オプションは、Kubernetes を使用している場合にのみ利用可能です。

ページ上部のフィルタードロップダウンを使用すると、特定の {{< ui >}}Provider{{< /ui >}}、{{< ui >}}Device Type{{< /ui >}}、{{< ui >}}Cluster{{< /ui >}}、{{< ui >}}Region{{< /ui >}}、{{< ui >}}Service{{< /ui >}}、{{< ui >}}Data Center{{< /ui >}}、{{< ui >}}Environment{{< /ui >}}、または {{< ui >}}Team{{< /ui >}} でフィルタリングできます。

検索フィールドとグループ化フィールドを使用して、他のタグで {{< ui >}}Search{{< /ui >}} または {{< ui >}}Group{{< /ui >}} することもできます。たとえば、{{< ui >}}Service{{< /ui >}} でグループ化すると、一意のサービスごとにテーブルの行を表示できます。各エントリの横にある {{< ui >}}\>{{< /ui >}} ボタンをクリックすると、そのサービスのデバイスを確認できます。

{{< img src="gpu_monitoring/host_row_expansion-2.png" alt="サービスとそのデバイスタイプを表示する GPU フリートテーブル。行展開ボタンが強調表示されています" style="width:90%;" >}}

## ユースケース駆動型のビューと推奨事項 {#use-case-driven-views-and-recommendations}
GPU Monitoring の [Fleet Explorer] ページには、2 つの専用のユースケース駆動型のビューが用意されています。

- **プロビジョニング**: キャパシティの割り当てとクォータの管理を行います。
- **パフォーマンス**: ワークロードの効率とスループットを最適化します。

### プロビジョニング {#provisioning}
{{< ui >}}Provisioning{{< /ui >}} タブは、デバイスのワークロードへの割り当てに影響を与えるハードウェアの健全性の問題を検出し、その修正方法に関するガイダンスを提供します。

{{< img src="gpu_monitoring/provisioning-tab-3.jpg" alt="プロビジョニングのユースケース駆動型のビュー" style="width:90%;" >}}

検出された各問題に対して、Datadog は解決に役立つステップバイステップの修正アクションを推奨します。

{{< img src="gpu_monitoring/critical-xid-recommendation.jpg" alt="重大な XID エラーに対する推奨される修正アクション" style="width:60%;" >}}

#### プロビジョニングサマリーグラフ {#provisioning-summary-graph}

サマリーグラフは、選択したユースケース駆動型のビューに関連する主要なテレメトリのすぐに使える (OOTB) 可視化を提供します。プロビジョニングユースケースでは、プロビジョニング済み、割り当て済み、およびアクティブなデバイスの内訳が表示されるため、無駄になっているアイドルコストを削減し、ワークロードに割り当て可能なデバイスを再発見できます。

### パフォーマンス {#performance}
{{< ui >}}Performance{{< /ui >}} タブでは、GPU デバイスで実行されているワークロードの進行を妨げるハードウェアの健全性やワークロードの問題が検出されます。これは、プラットフォームエンジニアや AI/ML チームにとって、それらの問題を修復する方法に関する信頼できる情報とガイダンスの唯一のソースになります。

{{< img src="gpu_monitoring/performance-tab-3.jpg" alt="パフォーマンスのユースケース駆動型のビュー" style="width:90%;" >}}

## 詳細サイドパネル {#details-side-panel}

フリートテーブルの任意の行をクリックすると、選択したクラスター、ホスト、またはデバイスの詳細が表示されるサイドパネルが開きます。

### 接続されているエンティティ {#connected-entities}

Datadog の GPU Monitoring は、NVIDIA の DCGM Exporter を必要としません。Datadog Agent を使用して GPU を直接観察し、ポッドやプロセスの GPU 使用量とコストに関するインサイトを提供します。任意の詳細ビューの {{< ui >}}Connected Entities{{< /ui >}} セクションでは、SM アクティビティ、GPU コア利用率 (システムプローブが有効な場合のみ)、およびポッド、プロセス、Slurm ジョブのメモリ使用量を確認できます。これにより、合計使用量を減らすために削減または最適化すべきワークロードを特定できます。

**注意**: {{< ui >}}Pods{{< /ui >}} タブは、Kubernetes を使用している場合にのみ利用可能です。

## インストール推奨事項 {#installation-recommendations}

Datadog はインフラストラクチャーを積極的に監視し、GPU Monitoring の価値を十分に引き出せない原因となり得るインストールの不備を検出します。このモーダルでは、GPU Monitoring の最適な価値を得るためのインストール更新推奨事項を見つけることができます。たとえば、ホストに Datadog Agent の [最新バージョン][1] がインストールされていることを確認し、NVIDIA ドライバーの最新バージョンをインストールし、ホストの設定ミスをチェックします。

<div class="alert alert-danger">予期しないカーネルパニックを引き起こす可能性があるため、Datadog Agent v7.82.0 は使用しないでください。</div>

関連するプロセスや SLURM ジョブによる GPU リソースの帰属などの高度な GPU Monitoring の機能を表示するには、それぞれ [Live Processes][3] と [Slurm][4] のインテグレーションを有効にする必要があります。
