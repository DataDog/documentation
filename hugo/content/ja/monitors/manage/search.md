モニターを検索するには、左側のファセットパネルや上部の検索バー、またはその両方を使用してクエリを作成します。属性を選択すると、それに合わせて検索バーのクエリが更新されます。同様に、検索バーのクエリを変更 (あるいは新規入力) すると、属性のチェックボックスが更新され、変更が反映されます。いずれの場合も、クエリを編集すると、クエリ結果がリアルタイムで更新されます。**注**: クリックする*検索*ボタンはありません。

## 検索バー {#search-bar}

単純な文言を使用して、すべてのモニターのタイトルと通知メッセージを検索します。たとえば、`*postgresql*` を検索すると、`postgresql` がタイトルまたは
通知メッセージのどこかに含まれるすべてのモニターが返されます。

フィールド名を指定することで、検索結果の絞り込みが可能です。

| 項目    | 説明                                            | 例        |
|---------|--------------------------------------------------------|----------------|
| タイトル   | モニターのタイトルに含まれる文言を検索します。               | `title:text`   |
| メッセージ | モニターの通知メッセージに含まれる文言を検索します。| `message:text` |

さらに、ID を使用してモニターを検索することもできます (例: `1234567`)。モニターの ID は、[Monitor Status ページ][1] で確認できます。

<div class="alert alert-info">モニターグループのフィルタリング方法については、<a href="/monitors/manage/status/">Monitor Status ページ</a>を参照してください。</div>

### クエリ {#query}

ブール演算子 (`AND`、`OR`、`NOT`) と括弧を使用して、検索クエリを強化できます。検索構文は [Elasticsearch][2] に似ていますが、以下の例外があります。

* 正規表現はサポートされていません。
* 単一文字の Wildcard (`?`) と通常の Wildcard (`*`) の両方がサポートされています。
* 近接検索はサポートされていませんが、[ファジー][3]演算子はサポートされています。
* 範囲検索はサポートされていません。
* ブースティングはサポートされていません。

以下の文字は予約済みです: `-`、`(`、`)`、`"`、`~`、`*`、`:`、`.`、および空白。予約文字を含むモニターフィールドを検索するには、フィールド文字列を引用符で囲んでください。たとえば、`status:Alert AND "chef-client"` は有効なクエリ文字列です。

引用符で囲まれたフィールドには注意事項があります。

* 一部のフィールドでよく使用されますが、引用符の有無にかかわらず `.` は使用できます。たとえば、`metric:system.cpu.idle` は有効です。
* 引用符で囲まれた文字列内では、Wildcard 検索はサポートされていません。たとえば、`"chef-client*"` は `"chef-client failing"` というタイトルのモニターを返しません。これは `*` がリテラルとして扱われるためです。
* コロンを含む値で Wildcard を使用するには、引用符を使用する代わりに、バックスラッシュ (`\`) でコロンをエスケープします。たとえば、`tag:service\:*` は、値にかかわりなく `service` タグを持つすべてのモニターを返します。

## 属性 {#attributes}

高度な検索を使用すると、以下のモニター属性を組み合わせてモニターを絞り込むことができます。

| 属性    | 説明                                                                                     |
|--------------|-------------------------------------------------------------------------------------------------|
| ステータス       | モニターステータス: `Triggered` (`Alert`、`Warn`、`No Data`)、または `OK`                            |
| ミュート        | モニターのミュート状態: `true` または `false`                                               |
| タイプ         | Datadog の[モニタータイプ][4]                                                                   |
| 作成者      | モニターの作成者                                                                      |
| サービス      | `service:<VALUE>` の形式で使用されるサービスタグ。                                        |
| タグ          | モニターに割り当てられた[タグ][5]                                               |
| Env          | `env:<VALUE>` の形式で使用される環境タグ。                                        |
| スコープ        | モニタークエリの `from` フィールドに一覧表示された検索タグ。                                  |
| メトリクス/チェック | 監視対象のメトリクスまたはサービスチェック                                                     |
| 通知 | 通知を受け取る人またはサービス                                                  |
| Muted left   | ダウンタイムがこのモニターの通知のミュートを停止するまでの残り時間。`muted_left:30m` を検索すると、ミュートの残り時間が最大 30 分のモニターがすべて返されます。サポートされている単位は、秒 (`s`)、分 (`m`)、時間 (`h`)、および週 (`w`) です。   |
| Muted elapsed | ダウンタイムがこのモニターの通知のミュートを開始してからの経過時間。`muted_elapsed:30d` を検索すると、少なくとも 30 日間ミュートされているすべてのモニターが返されます。サポートされている単位は、秒 (`s`)、分 (`m`)、時間 (`h`)、および週 (`w`) です。|

任意の数のボックスをチェックして、モニターを検索します。以下のルールが適用されます。

`status:Alert type:Metric` のように、* 複数のフィールドの属性をチェックする際、`AND` 演算子が適用されます。(2 つの検索条件の間に演算子がない場合は、`AND` になります)。
* 多くの場合、同じフィールド内の属性をチェックする際には `status:(Alert OR Warn)` のように `OR` 演算子が適用されます。例外もあり、たとえば複数のスコープやサービスタグをチェックする場合は `AND` 演算子が使用されます。
* 一部の属性では、複数の値を選択できません。たとえば、メトリクスやサービスチェックを選択すると、選択を解除するまでその他のオプションはリストに表示されなくなります。
* {{< ui >}}Status{{< /ui >}} 属性の下にある `Triggered` チェックボックスでは、`status:(Alert OR Warn OR "No Data")` として解決されます。Triggered は有効なモニターステータスではありません。
* {{< ui >}}Metric/Check{{< /ui >}} 属性の名前は、クエリ内では常に `metric` となります。たとえば、`http.can_connect` をチェックするを選択すると、`metric:http.can_connect` として解決されます。

**注**: モニター全体に多数の値が存在する属性については、属性検索バーを使用して正しい値を検索してください。

## Saved View {#saved-view}

Saved Views を活用して、事前に設定されたビューにすばやく移動し、チームのモニターや 60 日以上ミュートされたモニターなどの特定のコンテキストに関連するモニターを見つけます。

### デフォルトビュー {#default-view}

{{< img src="monitors/manage_monitor/default.jpg" alt="デフォルトビュー" style="width:50%;" >}}

既存の Manage Monitor ビューがデフォルトの Saved View となります。この構成にアクセスして表示できるのは本人のみで、構成を更新しても組織には何の影響もありません。

デフォルトの Saved View は、UI でアクションを完了するか、別の構成が埋め込まれた Manage Monitor ページへのリンクを開くことで、**一時的に**上書きすることが可能です。

Views パネルのデフォルトビューエントリからは、以下のアクションが可能です。

* エントリをクリックして、デフォルトビューを {{< ui >}}Reload{{< /ui >}} します。
* {{< ui >}}Update{{< /ui >}}現在のパラメーターでデフォルトビューを更新。
* {{< ui >}}Reset{{< /ui >}}デフォルトビューを Datadog のデフォルトにリセットして再起動。
