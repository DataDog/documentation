## 概要 {#overview}

ドラフトモニターを使用すると、通知をトリガーすることなく、安全にアラートを作成、調整、テストすることができます。

しきい値を試す、複雑なクエリを反復する、あるいはチームメイトと共同作業するなど、どのような場合でも、ドラフトを使用すれば、未完成やテスト中のモニターによるノイズのない、クリーンで分離された作業スペースを確保できます。また、ドラフトモニターは、開発中のアラート疲労の軽減に役立ち、完全に精査されたモニターのみが本番環境に移行されるようにすることができます。

ドラフトモニターは、アラートのワークフローを管理するエンジニアや SRE に最適です。複数のチームで作業する際にも状況を明確に把握することができ、アイデアを基に信頼性の高いアラートを確実に作成することができます。

## ドラフトモニターを作成する {#create-a-draft-monitor}

モニターを作成してドラフト状態で保存するには、次のようにします。

1. [[{{< ui >}}Monitors{{< /ui >}}] (モニター) > [{{< ui >}}New Monitor{{< /ui >}}] (新規モニター)][1] に移動します。 
2. [モニターを構成します][2] (クエリの追加、条件の指定、必要に応じて通知の設定を行います)。ドラフトで設定された通知ハンドルは、モニターが公開された後で初めて使用されます。
3. [{{< ui >}}Save as Draft{{< /ui >}}] (ドラフトとして保存) をクリックします。このドラフトモニターからはアラートは送信されません。

{{< img src="/monitors/draft/save_as_draft.png" alt="モニター作成インターフェイスの [Save as Draft] ボタン" style="width:100%;" >}}

## ドラフトモニターを公開する {#publish-a-draft-monitor}

モニターが完成したら、次のようにします。

1. ドラフトステータスファセットを使用するか、`status:draft` でフィルタリングして、[[{{< ui >}}Monitors List{{< /ui >}}] (モニターリスト)][3] からドラフトモニターを開きます。 
2. 設定を確認します。 
3. [{{< ui >}}Publish Monitor{{< /ui >}}] (モニターの公開) をクリックします。 
4. これによりモニターが公開され、条件に基づいてアラートが開始されます。

ドラフトステータスファセットを使用するか、`draft_status:draft` でフィルタリングして、[[{{< ui >}}Monitors List{{< /ui >}}]][3] からドラフトモニターを見つけます。ドラフトは、モニターのステータスページおよびモニターリストに [{{< ui >}}Draft{{< /ui >}}] (ドラフト) ラベル付きで表示されます。ドラフトは更新がないまま 6 か月経過すると期限切れになりますが、ドラフトモニターはいつでも削除できます。

## 権限{#permissions}

[編集権限][4]を持つユーザーであれば誰でも、ドラフトモニターを更新できます。イベントを使用すると、実際の通知を送信することなく、モニターがトリガーされた頻度をプレビューできます。

[**Draft Monitors Write**] (ドラフトモニターの書き込み) 権限を持つユーザーは、より広範な [**Monitors Write**] (モニターの書き込み) 権限がなくても、ドラフトモニターを管理できます。公開済みのモニターを変更せずに、ドラフトを処理する必要があるユーザーには、この権限を付与してください。

[**Draft Monitors Write**] 権限のみを持つユーザーは、以下の操作を実行できます。

- モニターを作成する (`draft_status` を `draft` に設定してモニターが保存されている場合のみ)。
- 既存のドラフトモニターを編集する (編集によって `draft_status` が `draft` から変更されない場合のみ)。
- 自身が作成したドラフトモニター、または所属するチームが所有するドラフトを削除する。

[**Draft Monitors Write**] 権限のみを持つユーザーは、以下の操作は実行できません。

- ドラフトモニターを公開する。
- 公開済みのモニターを編集または削除する。

これらの権限は、Datadog UI と API の両方に適用されます。

## ベストプラクティス{#best-practices}

* **ピアレビューにドラフトを使用する:** 変更を本番環境に反映させる前に共同で確認します。 
* **本番環境でのノイズを回避する:** まずドラフトでアラート条件を安全にテストします。 
* **作業を追跡する:** 開発中はドラフトに明確な名前とタグを使用します。 
* **古いドラフトを制限する:** 古いドラフトを確認してクリーンアップし、きれいに整理します。
