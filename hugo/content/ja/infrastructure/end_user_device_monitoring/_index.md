End User Device Monitoring は、物理および仮想の従業員が使用するデスクトップやノート PC の健全性とパフォーマンスを IT チームが可視化できるようにします。これは、従業員に影響を与えるパフォーマンスや接続性の問題を特定するのに役立ち、従業員全体のデバイス、ネットワーク、アプリケーションの健全性を統合的に把握して、次のような質問に答えるのに役立ちます。
- なぜこの従業員のノート PC は、特定のアプリケーションを開くたびに速度が低下するのか。
- オフィス内の過負荷な Wi-Fi アクセスポイントの影響を受けている従業員は誰か。
- Zoom、Microsoft Teams、または Google Meet の通話の遅延は、デバイス、ネットワーク、またはアプリケーション自体のどれが原因か。
- SaaS アプリケーションへのパスのどこでレイテンシーが発生しているか。
- どのデバイスでブルースクリーンエラーが発生しており、その頻度はどのくらいか。
- 関連部署全体にどのようなソフトウェア (およびどのバージョン) がインストールされているか (ハードウェアおよびライセンスのインベントリ計画のため)
- どのデバイスの CPU、メモリ、またはディスクのパフォーマンスが低下していて、注意や交換が必要か。
- レポートされた問題が発生する直前に、デバイス上で何が (どのプロセス、ログ、またはイベントが) 発生していたか。

## 仕組み {#how-it-works}

End User Device Monitoring は、Datadog Agent を使用して、従業員のデスクトップ、ノート PC、ワークステーションから直接データを収集します。Agent は各デバイスからシステムメトリクス、ネットワーク情報、およびログを収集し、そのデータを Datadog に送信します。Datadog では、それらを監視および可視化できます。

[End User Devices][5] (エンドユーザーのデバイス) ページでは、組織のデバイス全体の健全性とパフォーマンスを要約した組み込みのダッシュボードとメトリクスを提供します。すべてのデバイスの概要メトリクスや、CPU、メモリ、ネットワーク使用量を含む個々のデバイスの詳細メトリクスを表示することができます。

[Fleet Automation][6] を使用して、それらのデバイスにインストールされている Agent を管理できます。これには、バージョンステータスの確認、構成の一貫性の検証、および必要なインテグレーションが有効になっていることの確認などが含まれます。

## 主な機能 {#key-capabilities}

| 機能                        | 説明                                                                                                                                                                                               |
|-----------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **デバイスのパフォーマンス監視** | CPU、メモリ、ディスク、ネットワーク使用率などのシステム全体の健全性メトリクスを監視することで、パフォーマンスが低下しているデバイスを特定します。                                                                            |
| **バッテリーの健全性** | 最大容量、サイクル数、充電状態などのバッテリーメトリクスを使用して、ハードウェアのライフサイクルを計画します。                                                                             |
| **プロセスの可視性**            | [Live Processes][1] を使用して、個々のプロセスによるリソース使用量を監視し、デバイスのパフォーマンスに影響を与えているアプリケーションを特定します。                                                                        |
| **ログの収集**               | [ログ][7] を使用して、エンドユーザーのデバイスやアプリケーションからログを収集して調査し、クラッシュ、エラー、パフォーマンスの問題をトラブルシューティングします。                                                            |
| **Wi-Fi 監視**              | [WiFi/WLAN 統合][2] を使用して、信号品質、伝送速度、アクセスポイントの切り替えなどの Wi-Fi メトリクスを監視することで、接続の問題や過負荷のアクセスポイントを特定します。|
| **Windows クラッシュ検出**       | [Windows クラッシュ検出統合][3] を使用して、Windows デバイス上の Blue Screen of Death (BSOD) イベントを検出します。この統合により、システムクラッシュが発生したタイミングを示す Datadog イベントが生成されます。                        |
| **ネットワークトラフィック**         | 宛先ごとのトラフィック量と、レイテンシーおよびエラー率を確認します。                                                       |
| **Network Pathのトレース**         | [Network Path][4] を使用して、エンドユーザーのデバイスから宛先までのネットワークトラフィックをトレースし、レイテンシーや接続の問題が発生している場所を特定します。                                                       |
| **アプリケーションインベントリ**         | デバイスで実行されているアプリケーションをキャプチャして、バージョン更新を確認します。                                         |
| **ID マッピング**         | デバイスをユーザーにマッピングして、パターン分析やコホート分析を行います。                                         | 

## 注目のワークフロー {#featured-workflows}

### ユーザーデバイスから SaaS アプリケーションへの Network Path のトレース{#trace-network-paths-from-user-devices-to-saas-applications}

ユーザーからアプリケーションのパフォーマンス低下やビデオ通話の品質低下 (Zoom など) が報告された場合、問題はデバイス、ネットワークパスのどこか、またはアプリケーション自体にある可能性があります。End User Device Monitoring は [Network Path][4] と統合されており、ユーザーのデバイスから宛先の SaaS アプリケーションまでの全ルートをトレースし、これら 3 つのレイヤーすべてを可視化します。

traceroute の結果の可視化では、ローカルルーターや ISP からパブリックインターネットを経由してアプリケーションの CDN やサーバーに至るまで、パス上のすべてのホップが表示されます。各ホップにはレイテンシーデータが含まれているため、合計のラウンドトリップ時間だけでなく、どこで速度低下が発生しているかを特定できます。

Network Path のトレースを使用すると、次のことが可能になります。

- **デバイス間でのパスの比較**: 同じネットワーク上の複数のデバイスからの traceroute の結果を表示し、問題が単一のユーザーに影響しているのか、それともネットワーク全体に影響しているのかを判断します。
- **時間経過に伴うパスの比較**: 問題がレポートされる前後の Network Path の変化を調査し、レイテンシーがいつ、どこで増加したかを特定します。
