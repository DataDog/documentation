## 概要{#overview}

Datadog Notebooks は、ライブグラフ、メトリクス、ログ、モニター、および[分析機能][1]を統合し、データに基づいたリアルタイムのコラボレーション環境を提供します。チームは Notebooks を活用して、問題の切り分けと調査、インシデント詳細の記録、インタラクティブなガイドの作成、さらには特別なレポートの作成を行い、プロアクティブなワークフローを強化できます。

このガイドでは、Datadog Notebooks を紹介し、ノートブックの活用がいかにチームのコラボレーションや調査ワークフローを強化するかを説明します。

### 主なメリット{#key-benefits}

- **データへの直接アクセス**: ドキュメントを離れることなく、Datadog のメトリクス、ログ、トレースのクエリ実行や可視化が可能
- **リアルタイムのコラボレーション**: 複数のチームメンバーによる同時編集、コメントの追加、変更履歴の追跡が可能
- **ワークフローとの統合**: アラート、ダッシュボード、ログ、または Datadog Work Management からノートブックを作成し、問題が発生したその場所ですぐに調査を開始可能

## 適切なノートブックタイプの選択{#choosing-the-right-notebook-type}

適切なノートブックタイプを選択することで、チームはドキュメントの目的や期待される成果を理解しやすくなります。各タイプは特定のワークフローのニーズに対応しています。

{{< ui >}}Investigation{{< /ui >}} Notebooks は、リアルタイムのトラブルシューティング作業を記録します。未知の問題、予期しない動作、またはシステムの異常を調査する際に、このタイプを使用します。発見のプロセス、チームのコラボレーション、および成功した解決策を記録します。

{{< ui >}}Runbook{{< /ui >}}Notebooks は、一般的なタスクの手順をステップバイステップで示します。デプロイプロセス、インシデント対応ワークフロー、またはチームが定期的に実行する定期的に行う反復的なオペレーション作には、このタイプを使用します。

{{< ui >}}Documentation{{< /ui >}}Notebooks は、常に更新されるリファレンス資料として機能します。システムアーキテクチャの概要、チームのオンボーディングガイド、または時間の経過とともに変化する設定基準には、このタイプを使用します。

{{< ui >}}Report{{< /ui >}}Notebooks は、関係者向けに調査結果をまとめます。四半期ごとのインシデントの要約、重要な計画データの提示、技術的な意思決定の経営層への報告などに使用します。

{{< ui >}}Postmortem{{< /ui >}}Notebooks は、完了したインシデントを分析します。サービス停止などのインシデント発生後に作成し、時系列の記録、根本原因の特定、改善策の追跡を行います。

どのタイプのノートブックでも、チームメンバーとのコラボレーションが可能であり、Datadog のデータと連携させることができます。

## 活用事例: Notebooks を使用したログエラーの調査{#example-case-study-investigating-log-errors-with-notebooks}

システムでエラーログが発生した際、ワンクリックでノートブックを作成できます。ここでは、チームがコラボレーション用ノートブックを活用し、最近発生したチェック失敗の根本原因を調査して特定する例を紹介します。このプロセスにより、チームは将来同様の問題を防ぐために必要な対策を講じることが可能になります。

1. **アプリケーションログでエラーの急増に気づく**
   {{< img src="/getting_started/notebooks/log-explorer-errors.png" alt="画像の説明" style="width:100%;" >}}

1. **Log Explorer からノートブックを作成する**<br>
   [{{< ui >}}Open in Notebooks{{< /ui >}}] をクリックし、次の画面で [{{< ui >}}New notebook{{< /ui >}}] を選択します。

   {{< img src="/getting_started/notebooks/notebooks-button.png" alt="画像の説明" style="width:80%;" >}}

1. **ノートブックの左上隅で、[{{< ui >}}Investigation{{< /ui >}}] ノートブックタイプを選択する**

   {{< img src="/getting_started/notebooks/notebook-type.png" alt="画像の説明" style="width:80%;" >}}

   ノートブックは、Log Explorer から関連するログデータ、クエリ、および時間範囲を自動的に保持します。

   {{< img src="/getting_started/notebooks/log-errors-preserved-in-notebooks.png" alt="画像の説明" style="width:100%;" >}}

1. **チームメイトをタグ付けして共同で調査を行う**

   @メンションを使用してチームメイトをタグ付けし、調査に参加させます。チームメイトは同じエラーパターンを確認し、ノートブック上で直接分析結果を追記できます。Notebooks のコラボレーション機能を使用すると、チームメイトとリアルタイムでやり取りしながら共同作業を進めることが可能です。

   この例では、_transform_ 分析 Notebooks 機能を使用して、チームメイトがログエラーメッセージをフィルタリングし、特定のチェックが失敗していることを確認できます。

   {{< img src="/getting_started/notebooks/transform-analysis-feature.png" alt="画像の説明" style="width:100%;" >}}

1. **ノートブックにモニターを追加する**

   `/monitor` を使用してモニターサマリーをノートブックに追加し、ホストモニターのステータスを可視化します。

   {{< img src="/getting_started/notebooks/monitor.png" alt="画像の説明" style="width:100%;" >}}

   チームメイトがノートブックに残したメッセージによると、Minikube Monitor のチェックで OK ステータスが確認されたため、引き続き調査を行う必要があるとのことです。

この調査の過程で、ノートブックはトラブルシューティングの過程を記録する生きた記録となります。クエリ、発見、分析から得られたインサイトが保存され、将来の参考情報として活用できます。この例は、Notebooks の核心的な価値を示しています。それは、デバッグプロセスを文書化されたチームの知識へと変えることです。こうしてチームは、検索や共有が可能な形式ですべての情報を蓄積できるようになり、知識の散逸を防ぐとともに、今後の調査を迅速化できます。

## Notebooks 活用の次のステップ{#next-steps-with-notebooks}

調査は始まりに過ぎません。Notebooks は、事後対応型のドキュメントから事前対応型の資産へと変化することで、時間の経過とともに価値を高めていきます。インシデント発生時に作成された調査ノートブックは、さまざまなアセットの基盤となり得ます。

- 成功したトラブルシューティングのステップを抽出して、調査を {{< ui >}}Runbook{{< /ui >}} に変換します。これにより、将来の対応者は、ゼロから始めるのではなく、実績のある手順を踏襲できます。
- 複雑な調査を、システム動作と既知の問題を説明する {{< ui >}}Documentation{{< /ui >}} に変換しましょう。
- 複数の調査を集約してパターンや体系的な改善点を特定し、四半期ごとの {{< ui >}}Reports{{< /ui >}} を作成します。

この進化により、組織全体にメリットをもたらす一元化されたナレッジリポジトリが構築されます。新しいチームメンバーはオンボーディング中にこれらの Notebooks を参照でき、オンコールエンジニアはインシデント発生時にランブックとして活用でき、リーダーシップ層はキャパシティプランニングのためにレポートを確認できます。
