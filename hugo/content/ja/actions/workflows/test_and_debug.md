## モニターのトリガーをテストする {#test-a-monitor-trigger}

ワークフローの作成中にモニターのトリガーをテストできます。モニターをテストすると、モニターの通知ウィンドウに貼り付けてワークフローをトリガーできるスニペットが生成されます。

モニターのトリガーをテストするには、
1. ワークフローでモニターのトリガーアクションを選択します。
1. {{< ui >}}Test from Monitor{{< /ui >}} をクリックします。
1. モニターがワークフローに入力を渡す場合は、{{< ui >}}Workflow Inputs{{< /ui >}} の下にテスト値を入力します。
1. テストするモニターを選択します。
1. モニターの状態を選択します。
1. {{< ui >}}Run From Monitor{{< /ui >}} をクリックします。


## ステップをテストする {#test-a-step}

ワークフロー全体を実行することなくステップが意図したとおりに機能することを確認するために、ステップを個別にテストできます。

ワークフローのステップをテストするには、
1. ステップ {{< ui >}}Inputs{{< /ui >}} セクションの {{< ui >}}Test{{< /ui >}} をクリックします。
1. 必要に応じて、ステップ構成を調整します。ステップで前のステップの出力変数を使用する場合は、そのステップで使用するハードコードされたテストデータを入力します。
1. {{< ui >}}Test{{< /ui >}} をクリックしてアクションをテストします。
1. ステップのテストが完了したら、{{< ui >}}Use in configuration{{< /ui >}} をクリックして新しい構成をワークフローで使用するか、画面を閉じてテスト構成を保存せずにワークフローに戻ります。

分岐アクションおよびロジックアクションでは、テストは利用できません。前のステップの出力変数を使用する JavaScript 関数または式アクションをテストするには、コード内の変数をコメントアウトし、テストデータに置き換えます。詳細については、[式と関数のテスト][6]を参照してください。


## 失敗したステップをデバッグする {#debug-a-failed-step}

ワークフローの {{< ui >}}Run History{{< /ui >}} を使用して、失敗したステップをデバッグできます。左上の {{< ui >}}Configuration{{< /ui >}} または {{< ui >}}Run History{{< /ui >}} をクリックして、構成ビューと実行履歴ビューを切り替えます。

失敗したステップをクリックすると、そのステップの入力、出力、実行コンテキスト、および関連するエラーメッセージが表示されます。以下の例は、失敗した _GitHub プルリクエストのステータス_ステップを示しています。エラーメッセージは、権限不足が原因でステップが失敗したことを示しています。

{{< img src="actions/workflows/test_and_debug/failed-step4.png" alt="ステップが失敗したワークフロー。" >}}

ワークフローの初期実行履歴には、過去のワークフロー実行のリストと、各実行が成功したか失敗したかを示すパネルが表示されます。失敗した実行には、失敗したワークフローステップへのリンクが含まれています。リスト内のワークフロー実行をクリックして調査します。ワークフローキャンバス上のどこかをクリックすると、いつでも初期実行履歴に戻ることができます。


## AI で失敗したステップを修正する {#fix-a-failed-step-with-ai}

{{< ui >}}Run History{{< /ui >}} で、失敗したステップを選択し、その {{< ui >}}Outputs{{< /ui >}} タブを開きます。エラーメッセージの横にある {{< ui >}}Fix with AI{{< /ui >}} をクリックすると、障害の解決に関するヘルプが表示されます。

{{< img src="actions/workflows/test_and_debug/fix-with-ai.png" alt="Bits Chat が失敗したワークフローステップを診断し、修正案を提示します。" >}}

アシスタントが [Bits Chat][7] で開き、ステップの入力、出力、実行コンテキスト、エラーメッセージを使用して障害を診断します。また、サードパーティ製 API から返されたエラーについて外部ドキュメントを検索することも可能です。問題の内容を説明して修正案を提示し、変更を適用する前に確認を求めます。確認後、アシスタントがステップの設定を更新し、検証を再実行します。

AI による修正は、不適切な入力や古いアクション設定など、ワークフローの設定における問題に適用されます。無効な認証情報、レート制限、サービスの停止など、外部要因によって発生した障害については、アシスタントが根本原因を説明し、認証情報の確認やサービスの所有者への連絡といった次のステップを提案します。

失敗したステップが別のワークフローをトリガーする場合、Bits Chat はそのトリガー先のワークフローまでトレースし、同様に診断と修正案の提示を行うことができます。
