## 概要 {#overview}

[Work Management ページ][1] では、作成日、ステータス、または優先度でワークアイテムを並べ替えることができます。デフォルトでは、ワークアイテムは作成日で並べられます。**リスト**表示と**ボード**表示を切り替える: リスト表示では詳細なテーブルが提供され、ボード表示ではドラッグアンドドロップ機能付きの Kanban ボードが提供されます。

プロジェクト内のワークアイテムを一括編集するには、チェックボックスを使用して 1 つ以上のワークアイテムを選択します。次に、ドロップダウンメニューを使用して、ステータス管理、割り当て、アーカイブなどのアクションを一括で実行します。ワークアイテムを別のプロジェクトに移動すると、新しいワークアイテム ID が割り当てられます。古いワークアイテムの URL は、新しいワークアイテムにリダイレクトされません。

## キーボードショートカット {#keyboard-shortcuts}
以下のキーボードショートカットを使用すると、素早くナビゲーションを行うことができます。

| アクション                   | ショートカット       |
| ------------------       | ----------     |
| 上に移動                  | `↑` または `K`     |
| 下に移動                | `↓` または `J`     |
| ワークアイテムを選択         | `X`            |
| 選択されたワークアイテムを表示  | `Enter` または `O` |
| ワークアイテムを作成       | `C`            |
| ステータスを設定               | `S`            |
| ユーザーに割り当てる           | `A`            |
| 優先度を設定             | `P`            |
| プロジェクトへ移動          | `V`            |
| アーカイブ/アーカイブ解除      | `E`            |

## ワークアイテムを検索 {#search-work-items}

プロジェクト内では、以下でワークアイテムを検索できます。
- **属性のキーと値のペア**: たとえば、イベント相関パターンから作成されたすべてのワークアイテムを検索するには、`creation_source:Event Management` と検索します。個々のイベントから作成されたワークアイテムについては、`creation_source:Event` と検索します。
- **タイトル**: 検索語句を二重引用符で囲みます。たとえば、タイトルに「kubernetes pods」という語句が含まれるすべてのワークアイテムを検索するには、`"kubernetes pods."` と検索します。

より複雑なクエリを作成するには、大文字と小文字を区別する次のブール演算子を使用します。: `AND`、`OR`、および `-` (除外)。たとえば、`priority:(P2 OR P3)` は優先度が `P2` または `P3` のワークアイテムを返します。

さらに、左上の検索バーを使うと、すべてのプロジェクトを横断してワークアイテムを検索できます。

## ビューの作成 {#create-a-view}

**ビュー**とは保存されたクエリフィルターのことで、ワークアイテムを一覧表示する際に自分にとって最も関連性の高いものにスコープを絞り込むことができます。プロジェクトに含まれるステータスごとのデフォルトのビュー: オープン、進行中、クローズ、アーカイブ済み。さらに、自分に割り当てられたワークアイテムや、自分が作成したワークアイテムのデフォルトビューもあります。

カスタムビューを作成するには、以下の手順を実行します。。
1. プロジェクト内から **Add View** を選択します。
1. ビューに名前をつけます。
1. 検索ボックスで、クエリを入力します。プレビューが更新され、現在の検索クエリに一致するワークアイテムが表示されます。
1. (オプション) Slack、Microsoft Teams、PagerDuty、Webhooks などのサードパーティツールを使用して通知を送信します。**+ Add Recipient Type** をクリックし、事前設定されたチャネルまたは受信者から選択します。利用可能なツールとオプションの詳細については、[通知とチケットの作成][2] を参照してください。
1. **Save view** をクリックします。

## ワークアイテムの詳細 {#work-item-details}

ワークアイテムの詳細ページは、調査の進行に関する信頼できる唯一の情報源として機能します。各ワークアイテムには、以下のプロパティがあります。

ステータス
: すべてのワークアイテムは、作成時にデフォルトでオープンになっています。ワークアイテムを進めるにつれて、進行中やクローズに変更することができます。ワークアイテムのステータスを変更するには、`S` と入力してください。

優先度
: デフォルトでは、優先度は定義されていません。ワークアイテムの優先度は、P1 - 重大、P2 - 高、P3 - 中、P4 - 低、P5 - 情報に設定できます。ワークアイテムの優先度を設定するには、`P` と入力します。

担当者
: デフォルトでは未割り当てです。ユーザーに割り当てるには、`A` と入力します。自分自身に割り当てるには、`I` と入力します。

属性
: 属性を追加することで、整理やフィルタリングが可能になります。デフォルトでは、すべてのワークアイテムに、チーム、データセンター、サービス、環境、バージョンという属性があります。

アーカイブ
: ワークアイテムをアーカイブすると、検索から削除されます。ワークアイテムをアーカイブするには、`E` と入力します。

アクティビティタイムライン
: 各ワークアイテムは自動的にアクティビティタイムラインを作成し、ステータス、担当者、優先度、シグナル、および追加されたコメントの更新をリアルタイムでキャプチャします。コメントで自分がタグ付けされると、メールが届きます。コメントを追加するには `M` と入力し、送信するには `Cmd + Enter` と入力してください。

## アクションを実行する {#take-action}

Work Management を使用して、情報、状況、リソースを収集し、適切なアクションを決定します。これには、さらなる調査、インシデントへのエスカレーション、またはワークアイテムのクローズなどが含まれます。

個別のワークアイテムから:
- [調査ノートブックを作成する][3]: 調査情報を収集し、チームメンバーと協力します。
- [インシデントを宣言する][4]: ワークアイテムをインシデントにエスカレーションし、インシデント対応プロセスを開始します。
- 手動で Jira 課題を作成する: Jira 課題を作成するには、`Shift + J` を使用します。Jira 課題の自動作成と双方向同期の構成方法の詳細については、[設定][5] ドキュメントを参照してください。
- 手動で ServiceNow インシデントを作成する: ServiceNow インシデントを作成するには、`Shift + N` を使用します。
- ワークアイテムをクローズする: これ以上のアクションは不要であることをチームに伝えます。ワークアイテムのステータスをクローズに変更します。
- [承認をリクエストする][7]: ワークアイテムに対してアクションを実行する前に、1 人以上のチームメンバーからサインオフをリクエストします。

## Work Management Analytics {#work-management-analytics}

Work Management Analytics は、集計されたワークアイテム統計のクエリ可能なデータソースです。これらの分析は、[ダッシュボード][8] と [Notebooks][3] の両方で、さまざまなグラフウィジェットを使用してこれらの分析をクエリし、チームの生産性を分析したり、問題のパターンを特定したりできます。

次のウィジェットが Work Management Analytics をサポートしています。時系列、トップリスト、クエリ値、テーブル、ツリーマップ、円グラフ、変更、およびリスト。

## エクスポート {#export}

ワークアイテムの詳細ページから直接ワークアイテムをエクスポートできます。
1. 個々のワークアイテムから、ワークアイテム詳細ページの右上にある**その他のオプション** アイコンをクリックします。
1. **PDF にエクスポート**を選択します。
1. 表示される印刷ダイアログで、送信先に **PDF として保存**を選択します。
1. エクスポートを完了するには、**保存**をクリックしてください。
