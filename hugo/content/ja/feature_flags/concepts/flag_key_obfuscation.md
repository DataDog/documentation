## 概要{#overview}

フラグキーを難読化すると、事前計算された割り当てレスポンス内の読み取り可能なフラグキーがハッシュに置き換えられます。その結果、レスポンスを調べる人にとってフラグ名の判読が難しくなります。これは、クライアントサイドの Feature Flags を秘密にしたり、レスポンスの改ざんを防ぐものではありません。

アプリケーションは、元のキーを使用して引き続きフラグを評価します。難読化によって、ターゲティング、割り当てられる値、デフォルト値、またはテレメトリ内のフラグキーが変更されることはありません。

## 互換性とロールアウト {#compatibility-and-rollout}

フラグキーの難読化には、JavaScript SDK、`@datadog/openfeature-browser`、バージョン `2.1.0` 以降が必要です。Datadog によって、互換性のある SDK へのロールアウトが制御されます。SDK は自動的にエンコーディングを処理します。ユーザーがプロバイダーオプションの設定、ハッシュの生成、評価呼び出しの変更を行う必要はありません。

ロールアウトする際、Datadog はエンコーディングのサポートを報告する SDK に対してのみ、難読化されたレスポンスを送信します。その他の SDK バージョンは、引き続き読み取り可能なキーを受け取ります。1 つのアプリケーションを更新しても、古い SDK バージョンを実行している他のアプリケーションの動作は変更されません。

この機能は、事前計算された割り当てに適用されます。ローカル評価用にダウンロードされたターゲティングルールは難読化されません。

## フラグキーの難読化の仕組み {#how-flag-key-obfuscation-works}

1. Datadog は、SDK から提供されたサブジェクトとコンテキストについてフラグを評価します。
2. Datadog は、割り当てレスポンス内の各フラグキーをソルト付き SHA-256 ハッシュに置き換えます。
3. SDK はそのソルトを使用して評価呼び出しからのキーをハッシュ化し、割り当てを見つけてその値を返します。

ソルトはレスポンスごとに変化します。これは公開情報であり、秘密鍵ではありません。SDK は、キャッシュされた割り当てとともにソルトを保持します。

たとえば、以下の JavaScript 評価呼び出しは、レスポンスに読み取り可能なキーが含まれている場合でも、ハッシュ化されたキーが含まれている場合でも同じです。

{{< code-block lang="javascript" >}}
const enabled = client.getBooleanValue('new-route-planner', false);
{{< /code-block >}}

元のキーが、Datadog およびアプリケーションコード内で変更されることはありません。バリアント値、バリアント識別子、および割り当て識別子も変更されません。

## 機密性の高い機能情報を保護する {#protect-sensitive-feature-information}

難読化すると、割り当てレスポンス内のフラグ名が偶然発見される可能性が低減します。暗号化、認可、および署名検証は提供されません。フラグキーを知っている人は、公開されているソルトを使用してそのハッシュを確認できます。

- 秘密情報や機密性の高いビジネスロジックはサーバー上に保管してください。サーバー専用フラグは、**サーバー** [配信チャンネ]][1]に制限してください。
- クライアントに公開される値に機密情報を含めないでください。文字列や JSON オブジェクトは判読可能なままです。ブール値によっても動作が明らかになることがあります。
- アプリケーションコード内のフラグ名に不安がある場合は、その内容がわからないようなフラグキーを選択してください。ペイロードの難読化によって、ブラウザコードから文字列が削除されることはありません。
- クライアントに表示される値、識別子、テレメトリ、およびアプリケーションの動作は、調査可能であるものとして扱ってください。フラグキーをハッシュ化しても、このような他の情報源を隠すことはできません。
- 機密性の高いアクセス権の決定はサーバー上で実施してください。難読化によって、改変されたクライアントの動作の変更を防ぐことはできません。
