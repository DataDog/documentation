Bits Release は、マージされたプルリクエストが本番環境で意図したとおりに動作することを検証します。変更の目的を学習し、変更がライブになった後にサービスを監視し、プルリクエストおよび Slack で判定結果を報告します。

標準的なリリースチェックでは、変更が対象とする特定の動作をカバーすることはほとんどありません。ダッシュボードを数分間見れば、サービスが稼働していることはわかりますが、変更した機能についてはアラートが発火しないこともあります。そのため、壊れた状態やまったく効果がない状態で出荷された変更が、何日間も気づかれないままになることがあります。Bits Release は、マージのたびにその動作を直接チェックします。

Bits Release は、コードを変更したり、永続的なインスツルメンテーションを追加したりすることはありません。Datadog にすでに送信しているオブザーバビリティデータを読み取ります。チェックを一定期間実行する必要がある場合、一時的なリソースを作成し、検証終了時にそれらを削除します。

## Bits Release の仕組み {#how-bits-release-works}

1. **マージの検出**: Bits Release は、スコープ内のリポジトリのデフォルトブランチにプルリクエストがマージされると、それを検知します。
2. **変更の分析**: コードの変更と本番データを読み取り、その変更の目的を特定します。つまり、出荷後に本番環境で生じるべき効果 (期待される影響) と、変更によって影響を受けてはならない動作 (想定される回帰リスク) を分析します。
3. **デプロイ待ち**: Bits Release がプルリクエストの本番環境での実行を確認するまで、検証は待機します。
4. **本番環境の評価**: Bits Release は、判定に至るまで本番環境を期待値と比較して測定します。その後、判定結果をプルリクエストのコメント、Slack 通知、および Datadog の完全なレポートとして配信します。

検証は本番環境に対して実行されます。

### Bits Release のデータソース {#data-sources-for-bits-release}

Bits Release は専用のデータソースを必要としません。サービスがすでに送信している Datadog のコアテレメトリ (主にバックエンドサービス用の [logs][3] と [APM][4] トレース、Web フロントエンド用の [RUM][5]) を使用して変更を検証し、各サービスで有効になっているものに適応します。

カバレッジはインスツルメンテーションの状況に従います。APM とログを備えたサービスのバックエンド変更は、RUM のないアプリケーションのフロントエンド変更よりも強力な根拠を得られます。

## 判定 {#verdicts}

検証は 4 つの判定のいずれかで終了します。**Passed** および **Failed** は、変更に関する結論です。**Not enough data** および **Inconclusive** は、Bits Release が結論に達することができず、確認が必要であることを意味します。

| verdict | 意味 |
| ------- | ------- |
| **Passed** | デプロイ後、サービスは正常です。変更によって何らかの結果が期待されていた場合、Bits Release はその結果が少なくとも 1 つ発生したことも確認しています。目に見える効果をもたらすはずの変更を合格させるには、サービスが正常であるだけでは不十分です。特に確認すべきことがない変更の場合、サービスが正常であれば十分です。|
| **Failed** | Bits Release には、何らかの問題が発生しているという明確な証拠があります。変更がリグレッションを引き起こしたか、変更したコードは実行されたものの、意図した効果が見られない、あるいは逆の結果になっています。たとえば、修正したはずのバグが依然として発生している、改善しようとしたレイテンシーやエラー率が改善していない、あるいは新機能がエラーをスローしているといったケースです。|
| **Not enough data** | 本番環境から、Bits Release が判断を下すのに十分なデータが得られませんでした。関連するテレメトリが届かなかったか、変更されたコードに到達したリクエストが少なすぎて結論を出せませんでした。これは、サービスが正常であっても期待される効果を確認できなかった場合にも当てはまります。たとえば、変更をトラフィックの少ない時間帯にリリースした場合、まだオフになっている feature flag の背後に変更がある場合、または Bits Release の監視中にトラフィックがなかったパスを変更した場合などがこれに該当します。|
| **Inconclusive** | 十分なデータはありますが、相反する結果を示しているか、同時に起きた別の事象ではなく変更が原因であると確信を持って特定できません。|

検証の実行中は、**In Progress** と表示されます。Bits Release が暫定的な判定結果を得ていても、監視期間がまだ短いか、必要なシグナルが届いていないために結果を保留している場合は、**Pending** と表示されます。どちらの場合も監視は継続され、詳細が判明した時点で報告されます。

Bits Release は、変更後の本番環境の動作を報告します。修正すべきコードを特定するものではありません。検証中に収集されたコンテキスト (期待される影響、判定の根拠、読み取ったテレメトリ) を修正の出発点として使用してください。判定結果を [Bits Code][1] に渡して調査しプルリクエストを作成するか、そのコンテキストを独自の AI コーディングツールで使用してください。

## 前提条件 {#prerequisites}

Bits Release はマージされたコードを読み取り、そのコードが本番環境で稼働していることを検出します。GitHub リポジトリのみをサポートしています。GitLab、Azure DevOps、または Bitbucket でホストされているリポジトリはサポートされていません。

### 必須 {#required}

| 要件 | 必要な理由 |
| ----------- | ---------------- |
|  対象のリポジトリにインストールされた Datadog [GitHub App][2] に `Contents: Read` と `Pull Requests: Write` | `Contents: Read` を付与すると、Bits Release は検証対象のコード変更を読み取ることができます。`Pull Requests: Write` を使用すると、検証計画と判定結果をプルリクエストに投稿できます。これは、ほとんどの開発者が結果を確認する場所です。|
| スコープ内のサービスに付与する `version` タグ | 各デプロイメントを識別するため、Bits Release は新しいデプロイメントが発生したタイミングを把握できます。サービスは、[APM][4] または [RUM][5] テレメトリを使用してこれを報告します。|
| すべてのデプロイメントにおけるデプロイされたコミット SHA | デプロイメントをマージしたコードにリンクします。これが検証を開始するトリガーとなります。サービスのテレメトリの `git.commit.sha` タグ、または `version` タグ内に含まれる SHA として報告してください。これを設定するには、[サービスマッピング][8]を参照してください。|

### 推奨 {#recommended}

| 要件 | 追加される機能 |
| ----------- | ------------ |
| [Slack 連携][6] | 判定の準備が整うと、プルリクエストのコメントを確認してもらうのを待つのではなく、プルリクエストの作成者に直接通知します。|
| アプリケーションのドメインに対する既存の [Synthetic テスト][7] | 自然流入のトラフィックを待つのではなく、アプリケーションを能動的に呼び出すことで、Bits Release が変更を検証できるようにします。既存のテストですでに確立されているエントリポイントとサインイン方法を再利用します。|

## 結果の表示場所 {#where-results-appear}

- **プルリクエストのコメント**: Bits Release は分析後に検証計画を投稿し、評価完了後に判定結果を別のコメントとして投稿します。これにより、作成者に判定結果の新しい通知が届きます。
- **Slack**: 判定の準備が整うと、プルリクエストの作成者に通知されます。
- **Datadog の Bits Release**: Bits Release ページには、検証のリスト、各プランのライフサイクルのタイムライン、判定とその理由、予想される影響とそれぞれを裏付ける根拠、デプロイマーカーが付いたメトリクスチャートを含む完全なレポートが掲載されています。プレビュー期間中は、プルリクエストのコメント内のリンクからアクセスしてください。Datadog のサイドナビゲーションからは利用できません。

## 請求 {#billing}

Bits Release はプレビュー期間中は無料です。[AI クレジット][9]は消費されず、変更の検証中に作成される一時的なリソースも課金対象外となります。
