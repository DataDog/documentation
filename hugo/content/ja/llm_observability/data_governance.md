## Data Access Control {#data-access-control}

Agent Observability では、AI アプリケーションに関連付けられた機密性の高い可能性のあるデータへのアクセスを組織内の特定のチームやロールのみに制限できます。これは、AI アプリケーションが個人データ、独自のビジネス情報、機密性の高いユーザーインタラクションなどの機密情報を処理する場合に特に重要です。

Agent Observability におけるアクセス制御は、Datadog の [Data Access Control][11] 機能に基づいて構築されており、機密と見なされるデータへのアクセスを規制できます。`ml_app` タグを使用して、組織内の特定の AI アプリケーションを識別し、アクセスを制限できます。

また、個々の Agent Observability プロジェクト (実験、データセット、データセットレコード、アノテーションキューを含む) へのアクセスを制限することもできます。[Agent Observability における Access Control][14] を参照してください。

## スパンプロセッサーによるデータの編集 {#redacting-data-with-span-processors}

Datadog に送信される前に、アプリケーションレベルで機密データを編集または変更できます。Agent Observability SDK のスパンプロセッサーを使用して、スパン上の入力データと出力データを条件付きで変更したり、スパンが完全に送信されないようにしたりできます。

これは次のような場合に役立ちます。
- プロンプトやレスポンスからの機密情報の削除
- 内部ワークフローやテストデータのフィルタリング
- タグやその他の基準に基づいたデータの条件付き編集

詳細な実装例と使用パターンについては、[SDK リファレンスのスパン処理セクション][12]を参照してください。

## Sensitive Data Scanner 統合 {#sensitive-data-scanner-integration}

Agent Observability は [Sensitive Data Scanner][13] とインテグレーションし、AI アプリケーションのあらゆるステップに存在する可能性がある機密情報 (個人情報、財務情報、または企業秘密など) を識別および編集することで、データ漏洩の防止を支援します。

機密データをプロアクティブにスキャンすることで、Agent Observability は会話の安全性を維持し、データ保護規制への準拠を支援します。この追加のセキュリティ層は、AI アプリケーションとのユーザーインタラクションの機密性と整合性を維持するという Datadog の取り組みを強化するものです。

## データ保持 {#data-retention}

Agent Observability における保持期間は、データの種類とプランによって異なります。インストルメントされたアプリケーションからのトレースはプランのスパン保持期間に従いますが、実験、データセット、プロンプトにはそれぞれ独自の期間が設定されています。

| データ                                         | 保持期間                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------------------- |
| トレースとスパン                             | 15 日間 (保持アドオンを使用する場合は 30、60、または 90 日間)                                       |
| 実験                                  | 無料プランおよびオンデマンドプラン: 15 日間。コミットプラン: 90 日間。保持アドオンを使用する場合: 6、9、または 12 か月間 |
| アノテーション付きのインタラクションとラベル            | アノテーション時点から 90 日間、またはそれより長い場合はスパン保持期間      |
| データセットレコード                              | 現在のバージョン: 3 年間。以前のバージョン: 90 日間 (使用時にリセット)                     |
| プロンプトレジストリのプロンプト               | 3 年間 (プロンプトがプルされるたびに延長)                                          |
| `ml_obs.*` メトリクス                           | 15 か月間                                                                                 |

### トレースとスパン {#traces-and-spans}

インストルメントされたアプリケーションからのトレースとスパンは、すべてのプランでデフォルトで **15 日間**保持されます。これは、コスト、トークン数、レイテンシー、エラーなどのスパンごとの運用データや、スパンに付加された評価スコアなど、スパンに保存されているすべてのデータに適用されます。

保持アドオンにより、これを **30、60、または 90 日間**に延長できます。アドオンは無料プランでは利用できません。[保持期間の変更](#changing-your-retention-period)を参照してください。

保持期間は、Trace Explorer でクエリを実行する生のスパンに適用されます。それらのスパンから派生したメトリクスは個別に、より長く保持されます。[メトリクス](#metrics)を参照してください。

### 実験 {#experiments}

コミットされたプランでは、[実験][3]は本番環境のトレースよりも長く保持されます。

| プラン                                | 実験の保持期間 |
| ----------------------------------- | -------------------- |
| 無料プラン                           | 15 日間              |
| オンデマンド                           | 15 日間              |
| コミット (月間または年間)       | 90 日間              |
| 30 日間保持アドオン             | 6 か月間             |
| 60 日間保持アドオン             | 9 か月間             |
| 90 日間保持アドオン             | 12 か月間            |

組織がカスタム契約を結んでいる場合、保持期間がこのテーブルと一致しないことがあります。保持期間を確認するには、Datadog アカウント担当者にお問い合わせください。

### 保持期間の変更 {#changing-your-retention-period}

保持期間は請求額に影響します。期間が長くなると、Datadog が保存するデータ量が増えるためです。料金については、[Agent Observability の料金ページ][10]を参照してください。

保持期間アドオンは Datadog UI から有効にするのではなく、アカウントチームを通じて手配します。保持期間の延長をリクエストするには、Datadog アカウント担当者または [Datadog サポート][1]までお問い合わせください。

保持アドオンを追加または延長すると、その長い期間が**まだ期限切れになっていないすべてのスパンに遡及的に**適用されます。以前の期間中に期限切れになったスパンは復元できません。

たとえば、デフォルトの 15 日間の保持期間で、今日 60 日間のアドオンを追加した場合、過去 15 日間のスパンには 60 日間の期間が適用されますが、それより古いものはすでに削除されています。

より短い保持期間に変更すると、新しい期間よりも古いスパンは利用できなくなります。

### アノテーション付きインタラクション {#annotated-interactions}

インタラクションにアノテーションを付与すると、その保持期間が延長されます。トレース、スパン、またはセッションにアノテーションラベルやメモを適用すると (直接または[アノテーションキュー][2]経由のいずれであっても)、スパンの保持期間がそれより短い場合でも、Datadog はアノテーションが付与されたインタラクションをアノテーションの時点から **90 日間**保持します。スパンにアノテーションを付与するとその親トレース全体が保持され、セッションに属するトレースにアノテーションを付与するとセッション全体が保持されます。

アノテーションラベルは、それらがアノテーションを付与するインタラクションと同じ期間保持されます。

インタラクションにアノテーションを付与して保持期間を延長しても、追加料金は発生しません。

### データセットレコード {#dataset-records}

[データセット][4]の現在のバージョンにあるレコードは、スパンの保持期間に関係なく、**3 年間**保持されます。

データセットの以前のバージョンにあるレコードは、**90 日間**保持されます。この期間は、以前のバージョンが使用されるたびにリセットされます (例: 実験でそのバージョンを読み取った場合など)。90 日間連続して使用されなかった場合、以前のバージョンは完全な削除の対象となります。詳細については、[データセットのバージョン管理][5]を参照してください。

### プロンプト {#prompts}

[プロンプトレジストリ][9]内のプロンプトは、**3 年間**保持されます。この期間は、アプリケーションによってプロンプトがプルされるたびに延長されるため、アクティブに使用されているプロンプトは引き続き利用可能です。3 年間プルされていないプロンプトは、完全な削除の対象となります。

### メトリクス {#metrics}

スパンから生成された `ml_obs.*` メトリクスは標準の [Datadog メトリクス][6] であり、[Datadog メトリクスの標準保持期間][7] (詳細な粒度で 15 か月) に従います。これらはスパンの保持期間に関係なくこのスケジュールで保持されるため、基盤となるスパンが期限切れになった後でも、スパン数、トークン使用量、コスト、レイテンシー、エラー率に関する長期的なダッシュボードやモニターを構築できます。

利用可能なメトリクスの全リストについては、[Agent Observability メトリクス][8]を参照してください。
