## 概要 {#overview}

このガイドでは、オペレーションを定義するための適切な方法を選択し、各[オペレーション][1]を定義する際のベストプラクティスを適用する方法を説明します。

適切に定義されたオペレーションは、RUM アプリケーションのすべてのセッショントラフィックから信頼性の高い[可用性とレイテンシーのメトリクス][2]を生成します。オペレーションをジャーニーにリンクすると、これらのメトリクスを使用して、重要なジャーニーステップを評価し、ユーザーのジャーニー完了を阻害しているパフォーマンスの問題を特定できます。

## インスツルメンテーション方法の選択 {#choose-an-instrumentation-method}

フロントエンドコードを変更できるかどうか、およびオペレーションのライフサイクルをどの程度制御する必要があるかに応じて、インスツルメンテーション方法を選択します。オペレーションは、次の 2 つの方法のいずれかで定義できます。

1. [RUM SDK APIs][3] を使用して、フロントエンドアプリケーションコードに直接インスツルメンテーションを追加します。
2. Datadog UI または API を使用して、既存の RUM イベントからオペレーションを作成します。

RUM SDK APIs を使用すると、オペレーションをより詳細に制御できます。Datadog UI および API を使用すると、フロントエンドコードを変更してデプロイすることなく、オペレーションを定義できます。

### RUM SDK APIs を使用する {#use-rum-sdk-apis}

フロントエンドのコードベースにアクセスでき、変更をデプロイできる場合は、RUM SDK APIs を使用します。この方法では、オペレーションの開始と終了のタイミングを定義し、成功か失敗かを指定し、エラーや離脱による失敗を特定できます。カスタム属性を追加して、各オペレーションに関するコンテキストを提供することもできます。

### Datadog UI または API を使用する {#use-the-datadog-ui-or-api}

フロントエンドのコードベースにアクセスできない場合や、フロントエンドコードを変更せずにオペレーションイベントとメトリクスを生成したい場合は、Datadog UI を使用します。この方法では、ビュー、リソース、エラーなどの RUM イベントを、オペレーションの開始、成功、失敗の条件にマッピングすることでオペレーションを定義します。このオペレーションは RUM によってすでに収集されたイベントに依存しているため、その境界はそれらのイベントに限定されます。

どの既存の RUM イベントが各オペレーションを定義するかを判断した後、Datadog API を使用してオペレーションを一括作成します。

<div class="alert alert-warning">1 つの RUM アプリケーションで、Datadog UI または API を使用して作成できるオペレーションは最大 1,000 件です。RUM SDK APIs では、定義できるオペレーションの数に制限はありません。</div>

## オペレーションを定義する際のベストプラクティス {#apply-best-practices-when-defining-operations}

### アプリケーションが制御する作業の測定 {#measure-application-controlled-work}

アプリケーションが実行し、ユーザーが確実に完了することを期待する技術的なステップに基づいてオペレーションを定義します。たとえば、オペレーションは検索結果の読み込みやフォームの送信にかかる時間を測定する場合があります。オペレーションが遅延または失敗すると、ユーザーにフラストレーションを与え、ジャーニーの完了を妨げる可能性があります。

コンテンツの閲覧や選択内容の決定など、ユーザーの入力を待機している時間は除外します。ユーザーが制御する時間は、アプリケーションが期待通りに動作している場合でも測定されるレイテンシーを増加させ、アプリケーションのパフォーマンス問題を特定することを困難にします。

### タイムアウト率を 1% 以下に維持する {#keep-the-timeout-rate-at-or-below-1}

各オペレーションには、記録された開始と終了が必要です。終了は、オペレーションが成功したか失敗したかを示します。RUM が開始を記録したものの対応する終了を記録しない場合、[オペレーションはタイムアウト][4] (**並列化** の注記を参照) となり、Datadog はその結果を判断できません。

タイムアウトしたオペレーションは、意味のある結果データを持つオペレーションのサンプルを減らし、エラーやユーザーの離脱を隠蔽する可能性があります。タイムアウト率を 1% 以下に維持することで、Datadog は開始されたオペレーションの少なくとも 99% を成功または失敗として分類できます。タイムアウト率が高いと、オペレーションのパフォーマンスメトリクスの代表性が損なわれ、インスツルメンテーションの不備を示している可能性があります。

### オペレーションをジャーニーにリンクする {#link-operations-to-journeys}

オペレーションを作成する際にジャーニーにリンクすることで、そのオペレーションがジャーニーのステータスに寄与するようにします。リンクはオペレーション作成時に任意で行えます。また、後からオペレーションを追加のジャーニーにリンクしたり、既存のリンクを削除したりすることも可能です。

### ジャーニーの SLO を作成する{#create-slos-for-your-journey}

詳細については、[RUM オペレーションの SLO を作成するためのベストプラクティス][7]を参照してください。

### ジャーニーの最終オペレーションを優先する{#prioritize-the-final-operation-in-a-journey}

ジャーニーの最終ステップを表すオペレーションを優先します。多くの場合、その結果によってユーザーがジャーニーを完了したかどうかが決まるためです。その最終ステップを中心に、オペレーションの開始と成功の条件を定義します。例:

- **チェックアウトジャーニー**: ユーザーが **Pay now** をクリックしたときに最終オペレーションを開始し、支払いが完了したときに成功としてマークします。
- **ログインジャーニー**: ユーザーが有効な認証情報を使用して **Sign in** をクリックしたときに最終オペレーションを開始し、アプリケーションがユーザーを認証したときに成功にします。
- **検索ジャーニー**: ユーザーが有効な検索クエリを送信したときに最終オペレーションを開始し、結果ページに一致するアイテムが表示されたときに成功にします。

## オペレーションインスツルメンテーションのトラブルシューティング {#troubleshoot-operation-instrumentation}

予期しないオペレーションの結果を調査したり、オペレーションが正しくインスツルメンテーションされていることを確認したりするには、次のツールを使用してください。

- オペレーション詳細ページの推奨カードから [Bits Investigation][5] を開始し、エラー、離脱、タイムアウト、クラッシュ、処理速度の低下を分析します。
- 調査する結果について、オペレーション詳細ページのセッション例を確認します。
- [RUM Explorer][6] でオペレーションイベントをクエリし、その属性と周囲のセッションコンテキストを検査します。
