## 概要 {#overview}

テンプレート変数により、ダッシュボード内の 1 つ以上のウィジェットを動的にフィルタリングできます。テンプレート変数の選択から保存ビューを構築し、ドロップダウン選択によって視覚化を整理して操作することができます。

テンプレート変数は、次の項目によって定義されます。

* {{< ui >}}Tag or Attribute{{< /ui >}}:
    * Tag: 推奨される [タグ付けフォーマット][1] (`<KEY>:<VALUE>`) に従う場合、*Tag* は `<KEY>` となります。
    * Attribute: [ファセットまたはメジャーをテンプレート変数として](#logs-apm-and-rum-queries)使用します。
* {{< ui >}}Name{{< /ui >}}: ダッシュボード上のクエリに表示されるテンプレート変数の一意の名前です。テンプレート変数は、選択された Tag または Attribute に基づいて自動的に名前が付けられます。
* {{< ui >}}Default Value{{< /ui >}}: ダッシュボードが読み込まれたときに自動的に表示される Tag または Attribute の値です。デフォルトは `*` です。
* {{< ui >}}Available Values{{< /ui >}}: ドロップダウンメニューで選択可能な Tag または Attribute の値です。デフォルトは `(all)` です。利用可能な値のリストには、常に `*` が含まれており、Tag または Attribute のすべての値をクエリすることができます。

### テンプレート変数の値 {#template-variable-values}
テンプレート変数の値 (テンプレート変数のドロップダウンメニューで利用可能な値) は、ダッシュボード内のウィジェットが使用しているソースに基づいて入力されます。たとえば、ログをクエリするウィジェットがダッシュボードにある場合は、ログからの値のみが表示されます。ログ、メトリクス、RUM をクエリするウィジェットがダッシュボードにある場合は、ログ、メトリクス、RUM からの値が表示されます。

ほとんどのソースにおいて、テンプレート変数の値はダッシュボードのグローバルな時間枠に関連しています。たとえば、次のようになります。
- ダッシュボードの時間枠が過去 15 分に設定されている場合、過去 15 分のテンプレート変数の値のみが表示されます。
- ダッシュボードの時間枠が 8 月 15 日午前 0 時から午後 11 時 59 分に設定されている場合、その時間枠の値のみが表示されます。

| データソース                                     | データクエリ期間   |
|--------------------------------------           |---------------------|
| Metrics                                         | 現在～ 48 時間      |
| Cloud cost                                      | 現在～ 48 時間      |
| その他すべてのソース                               | ダッシュボードの時間枠 |

**注**: お探しのタグや属性が表示されない場合、そのデータが最近 Datadog に報告されていない可能性があります。さらに、テンプレート変数のためにクエリされたすべてのデータは保持ポリシーの対象となります。詳細については、「[履歴データ][4]」を参照してください。

### ダッシュボードレイアウト {#dashboard-layout}
変数がヘッダーを圧迫しないように、ダッシュボードは小さなサブセットを表示します。**+ N** ボタンをクリックすると、ダッシュボードに存在する追加の N 個の変数を見ることができます。


スクロールしながらすべての変数を一度に表示する必要がある場合は、[****] (テンプレート変数を展開) をクリックします。

## テンプレート変数の追加 {#add-a-template-variable}
ダッシュボードにテンプレート変数を追加するには、次のようにします。
1. [{{< ui >}}Add Variable{{< /ui >}} (変数を追加) (または、既存のテンプレート変数がある場合は {{< ui >}}\+{{< /ui >}}) をクリックします。
2. 推奨されるテンプレート変数のリストから選択するか、特定のタグを検索します。
4. このテンプレート変数を適用するウィジェットを選択します。
6. [{{< ui >}}Save{{< /ui >}}] (保存) をクリックします。


### テンプレート変数の構成 {#configure-template-variable}
テンプレート変数のサイドパネルが開いている状態で次の操作を行えます。
* 選択したウィジェットにこの変数を適用 (または削除) する ([{{< ui >}}Select All{{< /ui >}}] (すべて選択) または [{{< ui >}}Deselect All{{< /ui >}}] (すべて選択解除) のオプションがあります)
* フィルタリングとグループ化を切り替える
* 変数の表示名を変更する (ヘッダーとウィジェットクエリに表示)
* デフォルトのドロップダウン値を選択する
* ドロップダウン値をプレビューし、検索クエリでさらに構成する

## チームフィルター {#team-filter}

タグキーが `team` であるテンプレート変数は、単純なタグ値セレクターとしてではなく、[チームフィルター][5] としてレンダリングされます。これは、ダッシュボードとノートブックの両方に適用されます。

チームフィルターには、次の機能があります。

- 組織内の Datadog Teams と、一致するチームがない `team` タグ値の両方を含む 1 つのリスト。
- 階層を考慮した選択。チームを選択すると、その下位のチームも選択されます。Shift キーを押しながらチームをクリックすると、サブチームを含めずにそのチームを選択したり、チームを含めずにサブチームを選択したりできます。
- チームハンドルとチーム表示名の両方を検索します。

{{< img src="/dashboards/template_variables/team-template-variable.png" alt="クラスター、環境、およびリージョンの変数が通常の値セレクターとして表示され、team 変数がチームフィルターとして開かれているダッシュボードヘッダー。" style="width:100%;" >}}

階層を考慮した選択は、変数のタグキーが `team` の場合にのみ表示されます。他のタグキーに基づいて作成された変数は、チーム階層の概念がない通常のタグ値セレクターとしてレンダリングされます。あるダッシュボードの team 変数では階層が表示され、別のダッシュボードでは表示されない場合、各変数で設定されているタグキーを比較してください。

`team` 変数の場合、フィルターは組織内のすべてのチームをリストに表示します。[{{< ui >}}Available Values{{< /ui >}}] (利用可能な値) で設定された値は、リストを制限するのではなく、そのリストに追加されます。

### 別のタグキーでチームフィルターを使用する {#use-the-team-filter-with-a-different-tag-key}

一部のデータは、`team` 以外のタグキー (`team_attribution`、`attributes.team`、`usr.team` など) でチームの所有権を記録します。それらのキーのいずれかに基づいて定義されたテンプレート変数は、タグ文字列のフラットなリストを提供し、階層は表示しません。

そのデータに対して階層を考慮したチーム選択を行うには、`team` タグキーでテンプレート変数を定義し、各ウィジェットのクエリで選択した値を `$team.value` として参照します。変数のタグキーによって取得するセレクターが決まります。ウィジェットのクエリがフィルタリングするタグキーとは別のものであり、両方を一致させる必要はありません。

1. タグキー `team` でテンプレート変数を追加します。これはチームフィルターとしてレンダリングされます。
1. 各ウィジェットクエリで、データが使用するタグキーでフィルタリングし、値が入る場所に `$team.value` を記述します。

同じ置換を、どのタグキーに対しても使用できます。通常どおりクエリを作成し、チームハンドルを `$team.value` に置き換えます。

| ウィジェット |  チームハンドルを使用したクエリ| `$team.value` | を使用したクエリ
|---|---|---|
| Case Management (`attributes.team`) | `attributes.team:payments-platform` | `attributes.team:$team.value` |
| Cloud Cost (`team_attribution`) | `sum:all.cost{team_attribution:payments-platform}` | `sum:all.cost{team_attribution:$team.value}` |

#### 選択が解決される仕組み {#how-selections-resolve}

`$team.value` は、選択済みのすべてのチームハンドルを `OR` で結合し、クエリに記述したタグキーを使用して展開されます。`payments-platform` および `payments-fraud` のチームを選択すると、上記の 2 つの例は次のように解決されます。

```text
attributes.team:(payments-platform OR payments-fraud)
```

```text
sum:all.cost{team_attribution:payments-platform OR team_attribution:payments-fraud}
```

親チームを選択すると、親チームとその配下のすべてのチームがそれぞれ独自のハンドルとして展開されます。そのため、階層を指定して選択した場合、`team` タグが付けられたウィジェットと同じハンドルのセットでデータがフィルタリングされます。サブチームを含めずにチームを選択した場合や、チームを含めずにサブチームを選択した場合も、同様に展開されます。その選択に含まれるハンドルのみが対象となります。

展開結果はチームハンドルのリストです。ウィジェットで結果を返すには、データにそれらのハンドルがタグ付けされている必要があります。

## テンプレート変数の編集 {#edit-a-template-variable}
1. ダッシュボードヘッダー上のテンプレート変数にカーソルを合わせ、[**Edit**] (編集) をクリックします。テンプレート変数のサイドパネルが表示されます。
2. パネルのオプションを使用して、変数をカスタマイズしたり、変数を適用するウィジェットを追加したりします。


## 保存済みビュー {#saved-views}

### 作成 {#create}

1. ダッシュボードのテンプレート変数の左にある [{{< ui >}}Saved Views{{< /ui >}}] (保存済みビュー) ドロップダウンメニューをクリックします。テンプレート変数の値を更新しても、その値は自動的にビューに保存されません。
1. 現在のテンプレート変数の値をビューに保存するには、[{{< ui >}}Saved Views{{< /ui >}}] (保存済みビュー) ドロップダウンメニューから [{{< ui >}}Save selections as view{{< /ui >}}] (選択内容をビューとして保存) を選択します。
1. ビューの一意の名前を入力し、任意で説明を追加します。
1. [{{< ui >}}Save{{< /ui >}}] (保存) をクリックします。

{{< img src="/dashboards/template_variables/saved_view_create.png" alt="選択内容をビューとして保存を選択して、保存済みビューを作成する" style="width:100%;" >}}

保存済みビューがドロップダウンメニューに表示されます。ビューをクリックすると、以前に保存したテンプレート変数の値が表示されます。

### 削除 {#delete}

1. 保存済みビューのドロップダウンメニューをクリックし、希望の保存済みビューにカーソルを合わせます。
1. [{{< ui >}}Delete View{{< /ui >}}] (ビューを削除) をクリックします。

### 変更 {#modify}

[{{< ui >}}Default view{{< /ui >}}] (デフォルトビュー) は、テンプレート変数のデフォルト値を変更することでのみ編集できます。デフォルトビューを編集するには
1. テンプレートにカーソルを合わせます。
1. ボタンが表示されたら、[{{< ui >}}Edit{{< /ui >}}] (編集) をクリックします。
1. [{{< ui >}}Done{{< /ui >}}] (完了) をクリックして保存します。

他の保存済みビューのテンプレート変数の値を変更するには
1. ドロップダウンメニューから希望の保存済みビューを選択します。
1. テンプレート変数を編集して、新しいモデルを構成します。
1. ドロップダウンメニューを再度開きます。
1. [{{< ui >}}Save Changes{{< /ui >}}] (変更を保存) をクリックします。

{{< img src="/dashboards/template_variables/saved_views_update_template_variable.png" alt="保存済みビューのテンプレート変数を変更します。" style="width:100%;" >}}

タイトルと説明を編集するには
1. ドロップダウンメニューから希望の保存済みビューにカーソルを合わせます。
1. [{{< ui >}}Edit{{< /ui >}}] (編集) をクリックします。
1. タイトルまたは説明を変更します。
1. [{{< ui >}}Save{{< /ui >}}] (保存) をクリックします。

## 使用方法 {#usage}

テンプレート変数は、ウィジェットとイベントオーバーレイに使用されます。

### ログ、APM、および RUM クエリ {#logs-apm-and-rum-queries}

テンプレート変数は、ログ、APM、および RUM ウィジェットで動作します。これらは同じタグを共有しているためです。ファセットに基づいて、ログ、APM、RUM のテンプレート変数を定義することができます。これらの変数は `@` で始まり、たとえば `@http.status_code` のようになります。

ログ、APM、および RUM のウィジェットでは、値の途中にワイルドカードを使用できます (例: `eng*@example.com`)。また、1 つの値に複数のワイルドカードを使用することもできます (例: `*prod*`)。

**注**: このタイプのテンプレート変数に [{{< ui >}}Add to all{{< /ui >}}] (すべてに追加) を使用すると、すべてのログ、APM、RUM のウィジェットに変数が追加されます。

### ウィジェット {#widgets}

ウィジェットを作成または編集する場合、既存のフィルターテンプレート変数が [`from`] フィールドにオプションとして表示され、既存のグループ化用テンプレート変数が [`by`] フィールドの後にオプションとして表示されます。たとえば、`environment` テンプレート変数を構成する場合、ウィジェットで動的変数として `$environment` オプションを利用できます。

{{< img src="dashboards/template_variables/dynamic_template_variable.png" alt="テンプレート変数はウィジェット内で動的に設定可能" style="width:100%;">}}

`environment` の値として **production** を選択すると、`$environment` 変数を持つウィジェットが本番環境に動的にスコープされます。

テンプレート変数の値を変更する場合、ダッシュボード URL はそのテンプレート変数の値を反映するよう、`&tpl_var_<TEMPLATE_VARIABLE_NAME>=<TEMPLATE_VARIABLE_VALUE>` というフォーマットで更新されます。たとえば、テンプレート変数が `$env` のダッシュボードで値が `prod` に変更された場合、URL のパラメーターは `&tpl_var_env=prod` となります。

値をクエリに含めるには、`$<TEMPLATE_VARIABLE_NAME>.value` という構文で値を追加します。たとえば、`service` という名前のテンプレート変数では、`env:staging-$service.value` を使用します。

テンプレート変数のフィールドにカーソルを合わせると、その変数を使用するウィジェットがダッシュボード上でハイライト表示され、一目でわかります。

#### 関連するテンプレート変数 {#associated-template-variables}

テンプレート変数の値を選択すると、セレクターの上部に関連値が表示されます。関連値は、ページ上で選択されている他のテンプレート変数の値から計算され、追加の構成を行わなくてもシームレスに関連値を識別することができます。

#### テキスト {#text}

テキストベースのウィジェットでは、`$<TEMPLATE_VARIABLE_NAME>` を使用してテンプレート変数のタグ/属性と値を、`$<TEMPLATE_VARIABLE_NAME>.key` でキーを、または `$<TEMPLATE_VARIABLE_NAME>.value` で値を表示できます。これらは、英数字でない任意の文字の後に記述でき、空白や次の文字のいずれかを続けることができます。`#`、`$`、`%`、`=`、`;`、`"`、`(`、`)`、`[`、`]`、`{`、`}`、`^`、`*`、`+`、`|`、`?`。

**注**: テンプレート変数の後にワイルドカード構文を使用することはできません。

たとえば、テンプレート変数が `env` で、タグまたは属性が `environment` で、選択値が `dev` である場合:
* `$env` は `environment:dev` を表示します
* `$env.key` は `environment` を表示します
* `$env.value` は `dev` を表示します
* `$env*` は、`dev{dynamic-wildcard-value}` ではなく `dev*` という正確な値を探します。

### イベントオーバーレイ {#events-overlay}

ダッシュボードのメトリクスと特定のタグを共有するイベントを検索するには、テンプレート変数を使ったイベントオーバーレイ検索を使用します。イベントオーバーレイ検索は個々のグラフから適用します。

イベント検索フィールドで `$<TEMPLATE_VARIABLE_KEY>.value` 構文を使用すると、ダッシュボードテンプレート変数の値を直接キャプチャできます。

**注**: ダッシュボードのテンプレート変数は、イベントタグではなく、メトリクスタグである必要があります。

#### ダッシュボード {#dashboard}

ダッシュボードから、次のフォーマットを使用してテンプレート変数を持つイベントを検索します。

```text
<TAG_KEY>:$<TEMPLATE_VARIABLE_NAME>.value
```

たとえば、`region` テンプレート変数の値が `us-east1` の場合に `region:$region.value` を検索すると、`region:us-east1` でタグ付けされたイベントが表示されます。さらに、イベントのタイミングがグラフ上にピンクのバーで示されます。

複数のテンプレート変数で検索するには、コンマを入れます (例: `role:$role.value,env:$env.value`)

**注**: 検索を実行する際に *enter* を押すと、`$region.value` がテンプレート変数ドロップダウンメニューの値に更新されます。

#### ウィジェット {#widgets-1}

ウィジェットからテンプレート変数を使用してイベントのタイミングをオーバーレイするには、次の形式を使用します。

```text
$<TEMPLATE_VARIABLE_NAME>
```

たとえば、イベントオーバーレイ検索ボックスに `$region` と入力します。これにより、`region` テンプレート変数ドロップダウンメニューにある値を持つイベントを検索します。
