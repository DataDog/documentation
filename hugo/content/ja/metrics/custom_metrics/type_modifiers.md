[メトリクスタイプ][1]は、メトリクスとその送信ソースを使用して何を表そうとしているかを示すものです。`COUNT` と `RATE` のメトリクスタイプは、時間の経過に伴うメトリクス値の変化という同じ概念を表しているため、非常によく似ています。ただし、これらは異なるロジックを使用します。

* `RATE`: 時間の経過に伴う正規化された値の変化 (_1 秒あたり_)。
* `COUNT`: 指定された時間間隔における絶対的な値の変化量。

ユースケースや送信方法によっては、一方のメトリクスタイプが他方よりも送信に適している場合があります。例:

| 送信されるメトリクスタイプ | ユースケース                                                                                                                                                                               |
|-----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `RATE`                | 複数のホストにおいて、時間の経過に伴う受信リクエスト数を監視する場合。                                                                                                   |
| `RATE`                | ソース間での時間的なカウント送信の一貫性を制御できないため、アップストリームで比較できるように個別の間隔ごとに正規化します。|
| `COUNT`               | 関数が呼び出された回数をカウントする場合。                                                                                                                           |
| `COUNT`               | 一定期間内に得られた収益額を集計する場合。                                                                                                       |

`RATE` と `COUNT` は同じメトリクスタイプではないため、Datadog のグラフやモニター内での動作や形状は異なります。`RATE` と `COUNT` の表現をその場で切り替えるには、グラフやモニター内で Datadog のアプリ内修飾子関数を使用します。

## アプリ内修飾子 {#in-application-modifiers}

主な 2 つのアプリ内修飾子は `as_count()` と `as_rate()` です。

| 修飾子    | 説明                                                                                                                                                                                                                                                                   |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `as_count()` | 指定されたメトリクスを `COUNT` 形式で表示するために必要な操作を設定し、[ロールアップ間隔][2]ごとのメトリクス値の絶対的な変化量を提供します。**注:** ロールアップ間隔に依存するため、[より長い時間間隔でグラフ化するとグラフの形状が変化します][3]。|
| `as_rate()`  | 指定されたメトリクスを `RATE` 形式で表示するために必要な操作を設定し、メトリクス値の 1 秒あたりの絶対変化量を提供します。                                                                                                                                    |

適用したメトリクスのタイプによって、動作は異なります。

{{< tabs >}}
{{% tab "カウント (COUNT)" %}}

* `as_count()` の効果:
  * [補間][1]を無効にします。
  * 時間アグリゲーターを `SUM` に設定します。
* `as_rate()` の効果:
  * [補間][1]を無効にします。
  * 時間アグリゲーターを `SUM` に設定します。
  * 正規化するため、集計後の結果をサンプリング間隔で除算します。たとえば、1 秒ごとに送信された以下のポイント `[1,1,1,1].as_rate()` を 20 秒のロールアップ間隔で処理すると、`[0.05, 0.05, 0.05, 0.05]` が生成されます。

**注**: 微小な間隔 (時間集計が行われない場合) では正規化は行われないため、生のメトリクス値のカウントが返されます。

{{% tab "レート (RATE)" %}}

* `as_count()` の効果:
  * [補間][1]を無効にします。
  * 時間アグリゲーターを SUM に設定します。
  * 集計後の結果にサンプリング間隔を乗算します。たとえば、1 秒ごとに送信された以下のポイント `[0.05, 0.05, 0.05, 0.05].as_count()` を 20 秒のロールアップ間隔で処理すると、`[1,1,1,1]` が生成されます。
* `as_rate()` の効果:
  * [補間][1]を無効にします。
  * 時間アグリゲーターを `SUM` に設定します。
  * クエリのロールアップ間隔を、メトリクスのメタデータ間隔まで切り下げます。メトリクスの送信間隔よりも小さいロールアップ間隔で要求されたクエリは、メタデータ間隔に合わせて自動的に引き上げられます。
  * 集計後の各完全なバケットを `min(metadata_interval, rollup_interval) / rollup_interval` で再スケーリングします。ロールアップ間隔がメタデータ間隔と等しい場合、これはノーオペレーションとなり、バケット値は集計後の `SUM` と等しくなります。ロールアップ間隔がメタデータ間隔よりも大きい場合、値はそのバケット内の `per-second` レートサンプルの時間平均になります。たとえば、`60 seconds` ごとに送信されるメトリクスを `1800 second` のロールアップ間隔でクエリする場合、`as_rate()` は各完全なバケットに対して `post_aggregation / 30` を返します。
  * 最も右側の部分バケット (クエリ終了時刻がロールアップ境界に揃っていない場合) を、不自然に低い値ではなく、その部分ウィンドウで実際に観測されたサンプルの平均を表すように再スケーリングします。

  **注**: `RATE` メトリクスにメタデータ間隔が設定されていない場合、上記の再スケーリング手順は適用されず、時間アグリゲーターは `SUM` ではなく `AVG` にフォールバックします。

  **注**: たとえば、これを検証する際は、[高度なグラフ作成][2]の数式 `(post_aggregation / rollup_interval) * min(metadata_interval, rollup_interval)` を使用してください。この式は現在適用されているロールアップ間隔の数値に依存するため、基本的な時系列クエリウィジェットで直接プロットすることはできません。

[2]: /ja/dashboards/querying/#advanced-graphing

{{% tab "ゲージ (GAUGE)" %}}

`GAUGE` メトリクスタイプはメトリクスの絶対値と最終値を表し、`as_count()` および `as_rate()` 修飾子は、ゲージが Metrics Explorer でどのように保存または表示されるかに影響しません。

**注**: モニターにおいて、ゲージメトリクスに `as_count()` を適用すると、`pct_change()` のようなロールアップ依存関数の評価パスが変わります。
- `as_count()`なし: 関数はバケットごとに適用され、それらの値が評価ウィンドウ全体で合計されるため、スパースなゲージでは大きな負の値が生成される可能性があります。
- `as_count()`あり: 時系列はバケット化および集計されてから関数が適用されるため、意図したウィンドウレベルの計算と一致します。

### `weighted()`修飾子 {#the-weighted-modifier}

`pod name` や `container_name` などのタグは、特にコンテナ化されたアプリケーションのコスト管理、キャパシティプランニング、またはオートスケーリングのためのクエリを作成する際に、タグの入れ替わりを激しくします。タグの入れ替わりに関係なくゲージに対するクエリの数学的精度を確保するために、`.weighted()` アプリ内修飾子を使用できます。`.weighted()` 修飾子を使用すると、Datadog は頻繁に入れ替わるこれらのタグの存続期間に基づいてメトリクス値を適切に重み付けできます。

`.weighted()` 修飾子は、以下の両方の条件を満たす場合にのみ、ゲージに関するクエリに自動的に付加されます。

- ゲージメトリクスが定期的に送信されており、ギャップに対する補間が行われないこと。
- 送信間隔が正しく定義され、設定されていること。

Datadog Agent またはインテグレーションのいずれかが、取り込み時にメトリクスの送信間隔を設定します。[Metrics Catalog ページ][4]で送信間隔を変更します。

## Datadog 内でのメトリクスタイプの変更 {#modify-a-metrics-type-within-datadog}

通常は必要ありませんが、[Metrics Catalog ページ][4]でメトリクスのタイプを変更できます。

{{< img src="metrics/custom_metrics/type_modifiers/metric_type.png" alt="メトリクスタイプ" style="width:70%;">}}

使用例:

1. 処理されたリクエスト数をカウントするメトリクス `app.requests.served` があるものの、誤って StatsD から `GAUGE` として送信されてしまいました。そのため、そのメトリクスの Datadog タイプは `GAUGE` になります。

2. 時間集計のために、`app.requests.served` を StatsD の `COUNT` メトリクスとして送信したかったとします。これは、_「過去 1 日間に処理されたリクエストの合計数はいくつですか?」_といった質問に答えるのに役立ちます。`sum:app.requests.served{*}` をクエリすることで回答が得られます (これは `GAUGE` メトリクスタイプでは意味がありません)。

3. `app.requests.served` という名前が気に入っているため、より適切な `COUNT` タイプの新しいメトリクス名を送信するのではなく、以下を更新することで `app.requests.served` のタイプを変更できます。
  * N 件のリクエストが処理された後に `dogstatsd.increment('app.requests.served', N)` を呼び出す送信コード。および、
  * Metrics Catalog ページでの Datadog アプリ内タイプ (`RATE` への変更)。

これにより、`app.requests.served` のタイプ変更前に送信されたデータが正しく動作しなくなります。これは、アプリ内の `GAUGE` (`RATE` ではなく) として解釈される形式で保存されていたためです。ステップ 3 の後に送信されたデータは適切に解釈されます。

`GAUGE` として送信された履歴データを失いたくない場合は、新しいタイプで新しいメトリクス名を作成し、`app.requests.served` のタイプは変更しないでください。

**注**: AgentCheck の場合、`self.increment` は単調増加カウンターのデルタを計算せず、代わりにチェック実行時に渡された値を報告します。単調増加カウンターでデルタ値を送信するには、`self.monotonic_count` を使用します。
