## 概要{#overview}

実験を実行しているチームは、時間の経過とともにメトリクスがどれだけ累積的に動いたかを理解する必要があります。成功した実験から得られた上昇を単純に合計することは、これを行う自然な方法のように思えるかもしれませんが、それは真の影響を体系的に過大評価してしまいます。膨らんだ推定値は実験に対する信頼を損ない、進捗を正確に評価することを困難にします。

累積影響は、チームが単一のメトリクスに対して実行したすべての実験の効果を集計し、全体の変化をノイズ調整済みの推定値で算出する、メトリクスレベルの表示です。これは、既存のメトリクスのトレンドと並んでメトリクス概要ページで利用でき、累積影響チャートと効果分布という 2 つの新しいコンポーネントが含まれています。

## 累積影響の使用 {#using-cumulative-impact}

### 単純な集計が影響を過大評価する理由 {#why-naive-aggregation-overstates-impact}

実験結果を集計する際の課題は*勝者の呪い*として知られています。これは、統計的に有意な結果が真の効果を過大評価する体系的な傾向のことです。大きな測定上昇を伴う実験は、有意性に達してリリースされる可能性が高いため、"勝ち" の実験のリストは、真の値よりも高く測定された結果に偏ります。それらの測定値を合計すると、バイアスがさらに増大します。

これまで、勝者の呪いを補正するには、データチームが独自の統計モデルを構築するか、経験則に頼る必要がありました。Datadog Experiments は、メトリクスに対するチームのすべての実験全体に統計モデルを適合させ、累積影響の補正された推定値を生成することで、この補正を自動的に実行します。

### 累積影響チャートの見方 {#reading-the-cumulative-impact-chart}

累積影響チャートは、選択した期間にわたってメトリクスがどのように変化したかを示します。[**Time frame**] ピッカーを評価したい期間 (例: 過去四半期) に設定すると、その期間中に終了した実験がチャートに表示されます。

チャートには、以下の 2 つの数値が目立つように表示されます。

1. 期間中に実行された実験の数と、トリートメントバリアントをリリースした実験の数。
2. メトリクスに対する累積影響。相対的または絶対的な改善として表されます。

{{< img src="/product_analytics/experiment/cumulative_impact/cumulative_impact_overview.png" alt="過去 6 か月に設定された期間ピッカー、勝ちの実験の数でラベル付けされた +5.58% の累積影響値、および時間の経過とともにプロットされた累積影響チャートを含む累積影響セクションが表示されているメトリクス概要ページ。" style="width:90%;" >}}

[**Including X winning experiments**] をクリックすると、累積影響の計算に使用された実験を確認できます。リストから実験を選択すると、結果ページが開き、元の測定上昇、リリース判断、および累積計算に使用された補正後の推定値を確認できます。これにより、単一の貢献をそのソースまでトレースできるため、リーダに影響を伝えたり、プログラムレベルの主張を監査する際に役立ちます。

### 効果分布の読み取り{#reading-the-effect-distribution}

累積影響チャートの右側には、効果分布が表示されています。これは、そのメトリクスに対するチームの真の効果を可視化したものです。分布の中心はチームが平均的な実験で生み出す効果の大きさを表し、広がりはその効果がどの程度変動しやすいかを示しています。

{{< img src="/product_analytics/experiment/cumulative_impact/effect_distribution.png" alt="[Experiment Effect Distribution] パネルには、10 件の完了した実験で平均効果サイズが +0.55%、標準偏差が 0.15% であり、-1% から +1% の間でゼロを中心にベル型の曲線が描かれています。" style="width:80%;" >}}

この分布はノイズ調整されています。ノイズの多い結果によって、データが裏付ける以上に分布が広がることはありません。

効果分布は、次の 2 つの決定に役立ちます。

- **どこに投資するか**特定のメトリクスにおいて分布がゼロを大きく上回っているチームは、信頼性の高い上昇を生み出しており、この分野への投資を継続することを検討するとよいでしょう。分布がゼロをまたいでいるチームは、取り組みを他の分野へ転換することを検討するとよいでしょう。
- **将来の実験の規模をどのように設定するか**チームが通常 5% の[最小検出可能効果][1]で実験の検出力を設定しているにもかかわらず、真の効果が通常プラスマイナス 3% 以内であることが分布から示唆される場合、その実験は検出力不足である可能性が高いです。サンプルサイズの拡大、ターゲティングの拡大、より高い影響が期待できる機会への注力を検討してください。

### どの実験が含まれるか{#which-experiments-are-included}

累積影響は、選択された期間内にそのメトリクスをターゲットとし、結果が出ているすべての実験を考慮します。各実験がどのように寄与するかは、いくつかのルールによって決定されます。

- **モデルの適合度:** 診断で失敗していないすべての実験が、統計モデルの適合に寄与します。
- **集計:** 非コントロールバリアントをリリースした実験のみが累積合計に寄与します。コントロールバリアントをリリースした実験や、リリースの決定に至らずに終了した実験は合計されません。
- **診断:** 診断で失敗した実験は、適合から完全に除外されます。診断がない実験、または診断で合格または警告が出た実験は含まれます。

### ローカルビューとグローバルビュー {#local-and-global-views}

一部のメトリクスでは、累積影響の*ローカル*ビューと*グローバル*ビューを切り替えることができます。

ローカルビューは、「各実験の対象となったユーザーに対して、このメトリクスはどれくらい変動したか」という問いに答えるものです。これは、対象のサイズによって希釈されないため、チーム間やサーフェス間で効果の大きさを比較する場合に適したビューです。

グローバルビューは、「ユーザーベース全体で、このメトリクスはどれくらい変動したか」という問いに答えるものです。各実験の補正済み推定値に、その実験の対象となったユーザーの割合を重み付けし、プログラムレベルの合計変動の推定値を算出します。組織全体への影響を伝える場合は、グローバルビューが適しています。これは、小規模な対象者に対する大きな上昇が、はるかに大規模な対象者に対する小さな上昇と比較して適切に割り引かれるためです。

どちらのビューも同じ補正済み推定値を使用しており、それらの推定値をどのように組み合わせるかという点のみが異なります。

### 時間枠の選択 {#choosing-a-time-frame}

時間枠ピッカーで、どの実験を含めるかを制御します。期間を長くするとより多くの実験が含まれるため、モデルの適合度が向上し、効果の分布が滑らかになりますが、チームの方向性が変更されている場合は、異なる戦略が混在する可能性もあります。

妥当な開始点として、チームの実験戦略がおおむね一貫していた期間 (多くの場合、四半期または半年) が適しています。期間を比較することも有益です。効果の分布が時間の経過とともに上方にシフトしているチームは、単にリリースの決定が増えているだけでなく、より大きな真の効果を生み出しています。

## 統計の詳細 {#statistical-details}

このセクションでは、補正済み推定値と効果分布を算出するモデルについて説明します。これは、結果を把握、監査、または再現したいデータサイエンティストや統計学者を対象としています。

### 階層モデル{#the-hierarchical-model}

Datadog は、経験ベイズメタ分析の標準的な定式化である階層正規 - 正規モデルを使用しています。θ_i をターゲットメトリクスに対する実験 i の潜在的な真の効果とし、y_i をその実験から推定された上昇とし、既知の標準誤差を σ_i とします。モデルは以下のとおりです。

```
y_i | θ_i  ~ Normal(θ_i, σ_i²)     (sampling distribution)
θ_i        ~ Normal(μ, τ²)         (population distribution of true effects)
```

最初の行は、各実験で独自の真の効果のノイズの多い測定値に、実験の標準誤差によって決定されるノイズレベルを設定することを示しています。2 行目は、チームの真の効果自体が、平均 μ、分散 τ² の共有分布から得られることを示しています。この共有分布は、UI 上で*効果分布*として表示されるものです。

潜在的な θ_i について周辺化すると、観測された上昇の周辺尤度は以下のようになります。

```
y_i ~ Normal(μ, τ² + σ_i²)
```

これがオプティマイザーが適合させるものです。

### 事前分布{#priors}

Datadog は、母集団パラメーターに対して弱情報事前分布を使用します。再スケーリングされたデータ (下記参照) におけるデフォルト値は以下のとおりです。

```
μ ~ Normal(0, 1)
τ ~ HalfCauchy(0, 0.25)
```

μ に対する正規事前分布は、再スケーリング後、ほとんどのメトリクススケールにおいて情報を持たないほど十分に広くなっています。τ に対するハーフコーシー事前分布は、階層スケールパラメーターとして一般的な選択肢です。これは非負の実数上にサポートを持ち、ゼロ付近に質量を集中させるため、データが曖昧な場合にはモデルが均質性を優先することを意味します。その厚いテールは、データがそれを裏付ける場合に大きな不均質性を許容します。

### 数値安定性のための再スケーリング{#rescaling-for-numerical-stability}

適合の前に、観測された上昇と標準誤差は、平均ゼロ、分散 1 に再スケーリングされます。ȳ を上昇の標本平均、s_y をその標本標準偏差とします。オプティマイザーは、再スケーリングされた量に対して機能します。

```
ỹ_i = (y_i − ȳ) / s_y
σ̃_i = σ_i      / s_y
```

これは、自然なスケールが何桁も異なるメトリクス全体で、単一の事前ハイパーパラメーターセットが機能することを意味します。適合の後、μ と τ の推定値は元のスケールに変換されます。

```
μ̂ = μ̃ · s_y + ȳ
τ̂ = τ̃ · s_y
```

### モデルの適合{#fitting-the-model}

モデルパラメーター (μ, τ) は、最大事後確率 (MAP) 推定によって推定されます。最適化中に τ を正に保つため、モデルは τ = exp(η) として再パラメーター化され、オプティマイザーは (μ, η) を探索します。

目的関数は、観測された上昇が生じた場合の (μ, η) の負の対数事後確率です。

```
−log p(μ, η | data) = −[Σ_i log Normal(y_i | μ, τ² + σ_i²)]
                     − log Normal(μ | μ_prior_mean, μ_prior_sd²)
                     − log HalfCauchy(τ | τ_prior_scale)
                     − η                          (Jacobian of τ = exp(η))
```

最適化には、勾配を使用しないシンプレックス法であるネルダー - ミード法を使用します。これは 2 次元問題に対する堅牢な選択であり、τ = 0 付近での有限差分勾配に伴う問題を回避します。

### 補正済み推定値 (事後平均) {#corrected-estimates-posterior-means}

(μ̂, τ̂) の適合の後、各実験には、適合された事前分布の下での真の効果の事後平均に等しい補正済み推定値が与えられます。正規 - 正規共役更新は、観測された上昇と母集団平均の精度加重平均です。

```
θ̂_i = (y_i / σ_i² + μ̂ / τ̂²) / (1 / σ_i² + 1 / τ̂²)
```

同様に、θ̂_i = (1 − w_i) · μ̂ + w_i · y_i となり、ここで w_i = τ̂² / (τ̂² + σ_i²) は観測された上昇に置かれる重みです。区間が短い (σ_i が小さい) 実験は観測された上昇の大部分を維持し、区間が広い実験は母集団平均 μ̂ の方へ引き寄せられます。これが、勝者の呪いを補正する縮小ステップです。

### 累積影響への集計{#aggregating-to-cumulative-impact}

縮小された推定値は、メトリクスが本質的に加法的か乗法的かに応じて組み合わされます。

相対上昇メトリクスの場合、累積影響は乗法的に計算されます。

```
Cumulative relative impact = ∏ (1 + θ̂_i) − 1
```

絶対差メトリクスの場合、累積影響は縮小された推定値の合計となります。

```
Cumulative absolute impact = Σ θ̂_i
```

非コントロールバリアントをリリースした実験のみが、合計または積に含まれます。UI のチャートには、この合計または積の実行バージョンが実験終了日で並べ替えられてプロットされるため、時間の経過とともに影響がどのように蓄積されたかを確認できます。

### カバレッジ加重 (グローバルビュー) {#coverage-weighting-global-view}

グローバルビューでは同じ縮小推定値を使用しますが、それぞれを実験の*カバレッジ* (対象となった適格ユーザーの割合) で加重します。実験 i のカバレッジを c_i とします。

```
Global relative impact = ∏ (1 + c_i · θ̂_i) − 1
Global absolute impact = Σ c_i · θ̂_i
```

カバレッジ加重は、対象となったユーザーごとの推定値をプログラムレベルの推定値に変換するものです。カバレッジ値が記録されていない実験はグローバルビューからは省かれますが、ローカルビューおよびモデルの適合には引き続き寄与します。

### 診断の適格性{#diagnostic-eligibility}

モデルを適合させる前に、各実験が診断基準を満たしているか確認されます。診断では、深刻な割り当ての不均衡、バリアント間での割り当ての混在、メトリクスデータの欠落など、実験の品質に関する問題にフラグを立てます。実験の集約された診断ステータスが FAIL 以外であれば、その実験は*適格*となります。診断行がない実験は、適格として扱われます。

不合格となった実験は、モデルの適合および累積集計から完全に除外されます。それらは母集団平均に引き寄せられてから合計されるのではなく、除外されます。これにより、信頼性の低い測定値が累積合計や効果分布を汚染することを防ぎます。

### 最小サンプルサイズ{#minimum-sample-size}

モデルには、少なくとも 5 つの適格実験が必要です。実験数がこれより少ない場合、τ の MAP 推定値は不安定になり、結果として得られる縮小推定は信頼できません。このしきい値を満たさない場合、累積影響値や効果分布は表示されません。

## トラブルシューティング {#troubleshooting}

### チャートが表示されない場合 {#charts-not-showing}

累積影響には、モデルを適合させるために、診断で不合格となっていない実験が少なくとも 5 つ必要です。適格実験が 5 つ未満の場合、Datadog は累積影響値を表示しません。時間枠を延長するか、メトリクスに対してさらに実験を実施して、この問題を解決してください。
