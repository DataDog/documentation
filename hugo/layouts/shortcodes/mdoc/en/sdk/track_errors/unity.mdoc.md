## Automated error reporting

Native crash reporting is always on after RUM is enabled, with no configuration required.

To also forward uncaught exceptions from Unity's logs, select {% ui %}Forward Unity Logs{% /ui %} when configuring the SDK. Datadog then reports exceptions logged with `Debug.LogException` as RUM errors.

## Manual error reporting

To report a caught exception manually, use `AddError`:

```csharp
try
{
  // Error prone code
}
catch(Exception e)
{
  DatadogSdk.Instance.Rum.AddError(e, RumErrorSource.Source);
}
```

For the attributes collected, see [Data Collected][1].

## Upload debug symbols to get deobfuscated stack traces

Native crash reports mostly contain memory addresses. To map these addresses to legible symbol information, upload the iOS `.dSYM` files, NDK `.so` files, Android Proguard mapping files, and IL2CPP mapping file generated by your build.

1. In the Datadog section of your {% ui %}Project Settings{% /ui %}, select {% ui %}Output Symbol Files{% /ui %}. When using the IL2CPP backend (the default for iOS), also select {% ui %}Perform Native Stack Mapping{% /ui %} to get file and line information for C# stack traces.
2. Install the [`@datadog/datadog-ci`][2] command line tool, and set the `DATADOG_API_KEY` and `DATADOG_SITE` environment variables (or create a `datadog-ci.json` file that isn't checked into version control).
3. Upload the symbol files after each build:

   ```sh
   # iOS: from your build output directory
   datadog-ci unity-symbols upload --ios

   # Android: from your exported Android project directory
   datadog-ci unity-symbols upload --android
   ```

   For Android, export an Android project instead of building the APK directly, and build from the exported project.

Re-uploading files doesn't override existing ones if the build ID hasn't changed. Mapping files are limited to 500 MB each, and dSYM files to 2 GB each. To view uploaded symbols, see the [{% ui %}RUM Debug Symbols{% /ui %}][3] page. For all options, see [Unity Crash Reporting and Error Tracking][4].
