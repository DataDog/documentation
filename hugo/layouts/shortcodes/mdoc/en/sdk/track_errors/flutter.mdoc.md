## Automated error reporting

Uncaught Dart errors are reported automatically after RUM is enabled, if you initialize the SDK with `DatadogSdk.runApp` or set up the Flutter error handlers as shown in [Initialize the SDK][2]. To also report crashes that originate from native iOS or Android code, set `nativeCrashReportEnabled` to `true` in your `DatadogConfiguration`:

```dart
final configuration = DatadogConfiguration(
    // ...
    nativeCrashReportEnabled: true,
);
```

## Track custom errors

To track specific errors, notify RUM when an error occurs with the message, source, exception, and additional attributes:

```dart
DatadogSdk.instance.rum?.addError("This is an error message.");
```

To report an error with a source and stack trace, use `addErrorInfo`:

```dart
DatadogSdk.instance.rum?.addErrorInfo(
    e.toString(),
    RumErrorSource.source,
    stackTrace: st,
);
```

For the attributes collected for errors, see [Data Collected][3].

## Upload debug symbols to get deobfuscated stack traces

Native iOS crash reports are collected in a raw format and mostly contain memory addresses. Crash reports and errors from Flutter iOS and Android applications built with the `--split-debug-info` or `--obfuscate` options are also raw or obfuscated, and errors from Flutter Web applications reference JavaScript file and line numbers. To map them to legible symbols, upload the following files generated by your build:

- dSYM files for iOS
- The Proguard mapping file for Android
- Dart symbol files (when you build with `--split-debug-info`)
- The JavaScript source map for Flutter Web

Datadog matches stack traces with symbol files using their `service`, `version`, `variant`, and `architecture` fields.

1. Install the [`@datadog/datadog-ci`][4] command line tool.
2. Create a `datadog-ci.json` file at the root of your project with your API key and, optionally, your Datadog site. Because this file contains your API key, don't check it in to version control. Alternatively, set the `DATADOG_API_KEY` and `DATADOG_SITE` environment variables.

   ```json
   {
     "apiKey": "<YOUR_DATADOG_API_KEY>",
     "datadogSite": "datadoghq.com"
   }
   ```

3. Upload all the files needed for symbolication and deobfuscation in one command:

   ```sh
   datadog-ci flutter-symbols upload --service-name <your_service_name> --dart-symbols-location <location_of_dart_symbols> --android-mapping --ios-dsyms
   ```

Re-uploading a file doesn't override the existing one if the version hasn't changed. Mapping files are limited to 500 MB each, and dSYM files to 2 GB each.

For all options, including build flavors and build numbers, see the `datadog-ci` [Flutter Symbols documentation][5] and [Flutter Crash Reporting and Error Tracking][1]. To view uploaded symbols, see the [RUM Debug Symbols][6] page.
